### Находки

1. **Блокер: cmd_match засчитывает переспрос как выполненную команду.** cmd_match не смотрит на `got["clarify"]`. Запасной ответ разборщика — `report` с clarify «что им делать?» и адресатом из фразы — совпадает с ожидаемым `report` с тем же адресатом и пустыми params. Фраза считается верной, хотя по docs/COMMANDS.md команда с непустым clarify в игру не уходит.
   - Проба на моей фразе (не из набора): «дима ну как ты», ожидание report [4] → ok=True, exact=True.
   - В наборе A этому открыта ровно одна команда: report без params, во фразе simple с одной командой и clarify=false.
   - Остальные запасные переспросы безопасны: у всех ожидаемых buy/save/follow/tp/move в A есть параметр.
   - Одна фраза решает P4 (нужно ≥ 58/80 при 57/80 в PARSE-01) и P2 (нужно ≥ 17/20). Полнота и точность тоже получают лишнее попадание.
   - **Как исправить:** в начале cmd_match добавить `if got.get("clarify") and exp.get("agents"): return False`. Проверил: исходный прогон PARSE-01 остаётся 57/80 (полнота 84/113 = 0,743), регрессия 80/80, заглушка 4/5. Сравнимость с PARSE-01 сохраняется. secondary.py правка не ломает.

2. **Важно: правило для clarify-фраз слишком мягкое.** Сейчас `ok = exact or (clarify and asked)`.
   - Любой переспрос делает фразу верной, даже если другие команды пропущены или лишние. В A таких фраз 4 — это до 0,05 доли, больше запаса P1 и P4. В одной из них (hard) есть вторая команда всем пятерым, её код не проверяет вовсе.
   - Clarify-фраза с пустым expected засчитывается при полном молчании разборщика (проба подтвердила). В A таких фраз нет, но это ударит по S3 (правда B).
   - **Как исправить:** для clarify-фраз требовать три условия:
     - есть хотя бы один переспрос;
     - все ожидаемые команды с непустыми agents найдены среди команд без переспроса;
     - лишних команд без переспроса нет.
   - Проверил на доступных наборах: PARSE-01 исходный 57/80, регрессия 80/80, заглушка 4/5 — без изменений. Мои 4 пробы с ложным зачётом: было 4/4, стало 0/4. Если оставить правило как в PARSE-01 — строгий вариант давать отдельной строкой.

3. **Важно (для P6 — блокер по правилу «сухой прогон всей цепочки до регистрации»): secondary.py не заморожен и не прогнан всухую.** Файл появился во время рецензии. Его нет в таблице хешей, команд s1/s23 нет в «Методе», сухого прогона на заглушках A/B не было. Пути в нём зашиты в код — для сухого прогона нужны аргументы.
   - Текст PREREG про S1 расходится с кодом. Код требует равных флагов clarify, и это правильно: иначе «[] без clarify» и «[] с clarify» считались бы согласием. В PREREG написано «либо обе ставят clarify».
   - Нужно дописать в PREREG, что «в обе стороны» означает равенство params: пропуск параметра и `"auto"` различаются, то есть S1 — точное совпадение разметок.
