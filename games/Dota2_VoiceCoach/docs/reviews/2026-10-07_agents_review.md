**Рецензия: агенты Claude за каждого героя (Д11, уже с голосовым чатом Д12)**

Главное: два вероятных блокера. Мотор `api` на текущих средней и старшей моделях, скорее всего, будет обрезать ответы. А любая ошибка мотора при живом HTTP молча отключает приказы тренера (п. 1–2).

Файлы правились, пока я их смотрел. Номера строк даны по состоянию на 17:20 UTC.

Тесты зелёные:
- в начале весь набор — 114 (игра) + 53 (тренер);
- на последней версии — 32 (`test_custom_game` + `test_api_names`, lupa) + 61 (тренер, 2 пропущено).

Сигнатуры всех вызванных функций Доты сверил по `api.json` из @moddota/dota-data 0.47.2 (не только имена, но и аргументы) — расхождений нет. Находки п. 2–7 подтвердил скриптами на имитации из тестов: `/tmp/claude-0/-home-user-Neu/c2746a83-5006-51b9-9f59-346f06e713bc/scratchpad/probe/*.py` (в репозиторий не клал).

Пока я проверял, автор уже исправил приём решений после перезапуска сервера (номер `run`, coach_game.lua:358–365).

**Находки по серьёзности**

1. **Блокер (вероятный): мотор `api` на текущих средней и старшей моделях.**
   - Где: agents.py:485, 498–502 — `max_tokens=500`, параметров `thinking` и `effort` нет.
   - Справочник Claude API (навык claude-api в Claude Code 2.1.292): у средней модели (текущей), старшей модели (текущей) и прошлой старшей модели думание включено, если параметр не задан, а `max_tokens` ограничивает думание вместе с ответом. У старшей модели (текущей) думание не выключить; у прошлой быстрой модели оно по умолчанию выключено.
   - Сценарий: модель думает, упирается в `max_tokens`, JSON обрезан → «нет JSON-объекта». Плюс лишние секунды и выходные токены.
   - `stop_reason` возвращается (522), но в журнал не пишется (791–794), поэтому причину не увидеть.
   - Лечение: `output_config.effort: "low"`; для средней модели (текущей) — `thinking: {type: "between_tools"}` или запас по `max_tokens`; писать `stop_reason` в журнал.
   - Живой вызов не делал: ключа нет.

2. **Важно, на деле блокер при любой ошибке мотора: «связь есть, решений нет».**
   - Где: coach_game.lua:284–289 и coach_link.lua:41–43. Связь считается живой по HTTP 200, и запасной исполнитель выключается.
   - При этом мгновенные приказы тренера выбрасываются (286), а долгие никто не применяет.
   - Проверено: мотор отвечает 401 → «все назад !» не выполняется, герои идут на линии. HUD пишет «агенты на связи» и «→ 12345: все назад» без пометки.
   - Ошибку агента HUD не показывает: coach_hud.js:70 смотрит только «думает».
   - То же при исчерпанном `--max-calls` и паузе по 429: герой навсегда остаётся на последнем плане.
   - Лечение: считать связь живой, только если у героя есть свежее решение; иначе запасной исполнитель. Показывать поле `agent` в HUD.

3. **Важно: одно сломанное наблюдение роняет связь всех десяти героев.**
   - Где: coach_link.lua:60 кодирует весь пакет в одном pcall; coach_game.lua:338 строит наблюдения без pcall.
   - Проверено: ошибка в вызове API у одного героя → за 10 с ни одного запроса, все герои на запасном, строка в логе каждую секунду.
   - У `G:Think` (252–273) нет общего pcall. Ошибка в `World.update_seen` или `SendAgents` остановит цикл (предположение: Дота не перезапускает упавший `SetContextThink`).

4. **Важно: телепорт агентам недоступен.**
   - Где: coach_world.lua:307 и 316 смотрят только слоты 0–8.
   - Слот 15 — это `DOTA_ITEM_TP_SCROLL` (enums dota-data). Что стартовый ТП лежит именно там — знание игры.
   - Проверено: `item_tpscroll` не попадает в `items`, и сервер выбрасывает применение (agents.py:178, «у героя нет»), хотя промпт учит ТП (312).
   - Нейтральные слоты 16–17 тоже не видны.

5. **Важно: варды и точечные применения «по месту» не доходят.**
   - Где: coach_exec.lua:173–175 ставит `global = true` любому месту; из-за этого в 239 `walk = 0`, и герой занят применением всего около 0,6 с.
   - Проверено: вард «top», герой на боте → приказ применения, через 0,25 с его отменяет приказ фарма. Применение уже удалено из очереди — вард молча потерян.
   - Промпт (agents.py:312) обещает варды у внешней вышки. Признак `global` нужен только ТП.

6. **Важно: смысл `cast` расходится с промптом.**
   - (а) coach_exec.lua:196: способность без цели с целью "" применяется сразу, если цель плана не видна. Проверено: применение без цели при невидимой Луне в 7000. Так сгорают Eclipse и Freezing Field, а промпт обещает «цель плана или ближайший видимый враг».
   - (б) coach_exec.lua:72: каждое новое решение стирает ждущие применения (проверено: 1 → 0). Промпт об этом молчит, хотя для `buy`/`level` пустой список очередь сохраняет. Решения идут раз в ~4 с, и ульта, ждущая цель, теряется.

7. **Важно: прокачка без обратной связи.**
   - Где: coach_exec.lua:104–112 (ульта первой, повтор раз в 1 с) и coach_world.lua:324–326.
   - По dota-data `CanAbilityBeUpgraded` возвращает bool, рядом есть перечисление `AbilityLearnResult_t`. Что вернёт игра, не проверено.
   - Если приказ TRAIN не пройдёт, руки жмут ульту бесконечно (на имитации: 5 приказов за 5 с), а очки копятся.
   - В API есть `GetHeroLevelRequiredToUpgrade()`. После приказа стоит проверять, вырос ли уровень, и иначе исключать способность.

8. **Важно: мотор `cli` на Windows и «чистота» агента.**
   - Где: agents.py:535–541 — системный промпт идёт аргументом: командная строка около 7,9 тыс. знаков, 39 переводов строк.
   - Если Claude Code поставлен через npm (`claude.cmd`), `subprocess.run(["claude",…])` его не найдёт: CreateProcess дописывает только `.exe`. С `--claude claude.cmd` cmd.exe обрежет промпт на первом переводе строки, и строка почти упирается в предел 8191 знак. Это предположение по WinAPI, на Windows не проверял.
   - Лечение: `--system-prompt-file` — флаг есть в 2.1.292, но скрыт из `--help`.
   - Без `--bare` Claude Code подмешивает пользовательский `~/.claude/CLAUDE.md`, хуки, плагины, MCP и автопамять. Комментарий в строке 532 («чужой CLAUDE.md не подмешается») верен лишь наполовину. Есть `--safe-mode` (вход по подписке сохраняет) или `--setting-sources` + `--strict-mcp-config`.
   - Нет `--effort low`.
   - `encoding="utf-8"` без `errors=`: мусор в stderr (cp866) роняет решение.

9. **Важно: замер задержки и цены неполон.**
   - agents.py:762: задержка и число вызовов общие для всех моторов. При «Claude против правил» p50/p95 смешаны с мгновенными правилами.
   - agents.py:703 и 713 вместе с server.py:426–428: `--max-calls` считается на комнату и тратится и на правила, а справка обещает «за запуск сервера».
   - В журнале (791–794) не хватает:
     - `stop_reason`;
     - сырого ответа при ошибке;
     - модели, которой ответил Claude Code (в его JSON есть `modelUsage`);
     - момента, когда игра применила решение (Lua не возвращает `dec_seq`). Без него задержку «наблюдение → приказ» не измерить.
   - `cost_cli` при подписке — расчётная цена Claude Code, а не списание. `cost_usd_est` добавит те же токены ещё раз по ценам API.
   - Формула цены в коде верна: `input_tokens` — это некэшированный остаток.
   - Расчёт до замера в docs/CLAUDE_AGENTS.md занижен:
     - у прошлой быстрой модели минимум кэша 4096 токенов (так же записано в research/03 этого проекта), промпт около 3 тыс. токенов не закэшируется — примерно в 2,5 раза дороже таблицы;
     - думание средней модели (текущей) в формулу не входит.
   - `coach/logs/` стоит в .gitignore:9, поэтому журнал замера сам в репозиторий не попадёт.

10. **Важно: покупка в обход правил магазина.**
    - Где: coach_game.lua:226–233 — `AddItemByName` + `SpendGold`.
    - Описание API: «Add an item to this unit's inventory» — про запас, тайную лавку и непокупаемые предметы ничего. Сервер пропускает любое `item_*` (agents.py:43, 193), у которого цена больше нуля.
    - Предположение: так можно «купить» сыр, предметы тайной лавки у фонтана, варды сверх запаса.
    - При шести занятых слотах предмет уходит в рюкзак (coach_world.lua:314–320 считает слоты 0–8) и не работает; менять или продавать руки не умеют.
    - В API есть `DOTA_UNIT_ORDER_PURCHASE_ITEM = 16`.

11. **Мелочь, предположение по механике Доты: фарм.**
    - coach_exec.lua:271 и 292: на «hold» герой бьёт крипов в радиусе атаки и толкает линию (это уже записано в CLAUDE_AGENTS.md как непроверенное).
    - Обхода вражеской вышки нет.
    - Когда меняется «лучший» крип, атака перевыдаётся и сбивает замах.
    - Спама приказов каждые 0,25 с нет: повторы сдерживает `should_issue` (350).

12. **Мелочь: подпись «агенты Claude» без условия.**
    - coach_game.lua:83 и coach_hud.js:99 пишут «героев ведут агенты Claude» и при `--agents rules` (это значение по умолчанию), и без сервера.
    - Реплики правил («Понял…», «Вижу…») уходят в чат Доты как речь героя.
    - Строка режима в HUD честная: «правила (не Claude)».
