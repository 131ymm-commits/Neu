# Агенты Claude: каждого героя ведёт свой агент (решение Д11)

Слова автора (07.10.2026): «Нет играют не боты доты а агенты Клауд. За каждого Героя свой».

## Как устроено

```
 Dota 2: кастомка на ПК хоста (vscripts)                      Сервер тренера на том же ПК (Python)
 ┌──────────────────────────────────────────┐   раз в 1 с   ┌──────────────────────────────────────────┐
 │ coach_obs.lua  — наблюдение 10 героев    │ ─ POST /tick ►│ agents.py — 10 агентов, по одному на героя│
 │ coach_link.lua — один запрос в полёте    │ ◄─ решения ── │   свой промпт (характер, герой, позиция), │
 │ coach_exec.lua — исполнитель, 4 раза в с │               │   своя память, своя очередь; модель      │
 │ coach_game.lua — приказы тренера, HUD    │               │   вызывается в фоне, игра не ждёт        │
 │ встроенный ИИ ботов Доты выключен        │               │ мотор: api — Claude по ключу;            │
 └──────────────────────────────────────────┘               │   cli — Claude Code по подписке;         │
                                                            │   rules — правила, НЕ Claude (тесты)     │
                                                            │ журнал JSONL: задержка, токены, решения  │
                                                            └──────────────────────────────────────────┘
```

Модель отвечает за секунды, а Доте нужны десятые доли секунды, поэтому уровней два:

| Кто | Как часто | Что решает |
|---|---|---|
| Агент Claude (свой у каждого героя) | раз в `--period` с игры (по умолчанию 4) и сразу по событию | план и место, цель, какие способности и предметы по кому, что купить, что качать, порог отхода, выкуп, реплика тренеру |
| Исполнитель на Lua (руки) | 4 раза в секунду | ничего не выбирает, только выполняет решение: добивает крипов при фарме, бьёт цель, применяет способность, когда цель видна, отходит по порогу здоровья, покупает у фонтана, вкладывает очки |
| Тренер (человек) | когда пишет | приказы агентам в коротком формате; агент сам решает, как выполнить, и отвечает своими словами |

**События, по которым агент думает сразу:** первое решение, новый приказ тренера, смерть, возрождение, новый враг
ближе 1500, потеря 20 и больше пунктов здоровья с прошлого решения. Без события — раз в `--period` с игры, мёртвым —
раз в 12 с. Не чаще раза в секунду, после ошибки — раз в 3 с. Пока агент думает, руки продолжают прошлое решение.

**Без сервера агентов** (не запущен, упал, нет связи 6 с) героев ведёт запасной исполнитель: приказ тренера
превращается в решение напрямую, без агента и характера; без приказа — фарм своей линии. То же для одного героя, если
его агент 20 с игры не дал нового решения (ошибка мотора, предел вызовов, пауза по лимиту API): связь жива, но приказы
тренера не теряются. HUD пишет, кто ведёт героев, а у героя — «агент: ошибка …» и «без агента».

## Голосовой чат команды (Д12)

Агенты своей команды переговариваются, как пятёрка в голосе Доты, а тренер их слышит. Реплика агента (`say`) уходит
в чат команды, `to` — кому из союзников (пусто — всем). Каждый агент видит в сообщении последние реплики команды за
минуту: кто, кому, сколько секунд назад; новое помечено. Обращение к союзнику будит его сразу (повод «к тебе обратился
союзник»), ответ на обращение никого не будит — так переговоры не превращаются в бесконечный пинг-понг и лишние
вызовы. Чат команды слышит только она сама.

Вслух — голосами браузера (Web Speech API, голоса синтетические, Д6): страница `http://localhost:8787/voice.html`
(или главная страница тренера) на ПК, во втором окне, или на телефоне (сервер с `--host 0.0.0.0`, адрес ПК в сети).
У каждой позиции свой голос: один из русских голосов системы, своя высота и темп; очередь короткая — реплики старше
12 с не зачитываются. В игре та же страница открыта в скрытой веб-панели HUD — звучит ли речь внутри Доты, не
проверено. В HUD и в командном чате игры реплики видны текстом: «1 sniper → 2: Луна идёт к тебе».

Проверено здесь: разговор «обратился — ответил — не будит» на сервере, реплики только своей команде, путь
«приказ тренера → агент → реплика → страница» и голоса по позициям — в настоящем Chromium с подменённой речью
(`coach/tests/test_voice_page.py`). Не проверено: настоящие голоса на ПК автора, речь в веб-панели Доты, как часто
агенты Claude будут говорить и сколько это добавит к цене.

## Наблюдение и решение

Наблюдение (`coach_obs.lua`, около 1 тыс. токенов): часы, здоровье и мана, золото, выкуп, где герой (линия и ближайшая
вышка), атака, способности (готовность, откат, мана, дальность), очки и что можно качать, предметы, что сейчас делают
руки и что не смогли, крипы и вражеская вышка рядом, союзники (где, что делают), враги — только видимые, а невидимые —
где и сколько секунд назад их видели, вышки, Рошан, последние 3 приказа тренера, последние 5 событий (убийства, вышки).

Решение — JSON по схеме `DECISION_SCHEMA` (`coach/voicecoach/agents.py`):
`plan` (farm, push, defend, fight, retreat, roshan, move, follow, save, group, hold), `where`, `target`, `ally`,
`cast` (до 4 применений), `buy`, `level`, `retreat_hp`, `buyback`, `say`, `to`. Сервер проверяет имена по наблюдению:
цель — из вражеской пятёрки, способности и предметы — у героя, прокачка — из доступного. Ошибочное поле отбрасывается
с замечанием в журнале; без допустимого плана решение не принимается, и руки продолжают прошлое.

## Цена и задержка: расчёт до замера матча

Цены — страница цен Anthropic, перечитана 08.10.2026 (https://platform.claude.com/docs/en/about-claude/pricing), за
1 млн токенов; минимум кэша — страница prompt caching (там же, 08.10.2026):

| Модель | Вход | Выход | Чтение кэша | Минимум кэша |
|---|---|---|---|---|
| самая быстрая модель Claude (текущая) | $0,10 | $0,50 | $0,01 | 512 токенов |
| средняя модель Claude (текущая) | $2 | $10 | $0,10 | 512 токенов |
| прошлая быстрая модель | $1 | $5 | $0,10 | 4096 токенов — наш промпт короче, кэша нет |

Запись в кэш дороже входа: в 1,25 раза на 5 минут, в 2 раза на час. У самой быстрой модели цена выше для промптов
длиннее 100 тыс. токенов — нас не касается. Обе текущие модели думают по умолчанию (адаптивное думание), думание
оплачивается как выход и входит в `max_tokens`; по умолчанию у быстрой effort `medium`, у средней — `high`
(страницы models overview и effort, 08.10.2026). Сервер шлёт `effort: low` и `max_tokens` 4000.

Формула на матч: решений N = героев × длительность / период (плюс решения по событиям);
цена = N × (U × вход + S × кэш + O × выход) / 10⁶, где U — своя часть каждого вызова (наблюдение, память, чат),
S — системный промпт из кэша, O — ответ с думанием. Числа — из живого вызова через `claude -p` 08.10.2026
(`experiments/pilots/2026-10-08_cli_live/`, 2 ситуации × 2 модели): S ≈ 3,5 тыс., U ≈ 2 тыс. токенов; O ≈ 0,3 тыс.
у средней (на `effort low` она не думала) и ≈ 0,6 тыс. у быстрой (думала ≈ 0,3 тыс.); у прошлой быстрой (не думает
по умолчанию) взято 0,2 тыс.

| Вариант (матч 40 мин) | N | Самая быстрая | Средняя | Прошлая быстрая |
|---|---|---|---|---|
| 10 агентов, период 4 с | 6000 | ≈ $3,2 | ≈ $44 | ≈ $39 |
| 5 агентов (соперник на правилах), период 4 с | 3000 | ≈ $1,6 | ≈ $22 | ≈ $20 |
| 10 агентов, период 8 с | 3000 | ≈ $1,6 | ≈ $22 | ≈ $20 |

Решения по событиям добавят сверху. Прошлая таблица (07.10.2026) была неверна — ошибка № 86 в `journal/ERRORS.md`:
быстрая модель в ней — прошлая, с кэшем, которого у неё для нашего промпта нет, а U и O занижены. И новая таблица —
расчёт по двум вызовам на модель, не замер: настоящая цена — сводка журнала после матча (`GET /api/local/agents`, поле
`summary`; с `--price-in/--price-out/--price-cache-read/--price-cache-write` — оценка в долларах по сторонам на API;
у сторон на Claude Code цену считает он сам — поле `cost_cli`, и при входе по подписке это не списание).

**Думание.** Выключить — быстрее и дешевле, но, возможно, хуже решения (не мерили): `--thinking disabled` у самой
быстрой модели, `--thinking between_tools` у средней (думать только между вызовами инструментов, а инструментов у
агента нет). Модель, которая параметр не примет, получит запрос без него, и сервер запишет это в сводку (`dropped`).

**Лимиты API** (https://platform.claude.com/docs/en/api/rate-limits, 07.10.2026): начальный уровень Start —
1000 запросов, 2 млн входных и 400 тыс. выходных токенов в минуту на модель; прочитанное из кэша в лимит входа
не идёт; месячный потолок трат — $500. Нам при периоде 4 с нужно ≈ 150 запросов в минуту. Новые организации могут
начинать с уровня Evaluation с меньшими лимитами — какими, страница не пишет.

**Задержка.** Через `claude -p` (с запуском процесса) — 3,9–5,8 с на решение (живой вызов выше, 4 вызова). Через API
не мерили. Наша схема переносит секунды (руки работают между решениями), но не десятки секунд. Замер — в журнале:
`latency_s` (думание модели) и событие `applied` с `decision_age_s` — сколько секунд игры прошло от наблюдения, по
которому агент решал, до начала выполнения (обмен с игрой, думание, ожидание следующего обмена); медианы и 95-е
процентили — в сводке, по сторонам.

## Ключ или подписка

- **Ключ API — рекомендую.** `--agents api --model <имя модели>`, ключ в `ANTHROPIC_API_KEY`. Оплата за токены,
  ответ по схеме гарантирован (structured outputs), системный промпт кэшируется, есть `--max-calls` против перерасхода
  (считает только платные вызовы; правила не в счёт). Параметры модели: `--effort` (по умолчанию low), `--thinking`,
  `--max-tokens` (по умолчанию 4000 — запас на думание). Что модель не примет (ответ 400 с именем параметра), сервер
  отключит и повторит запрос.
- **Подписка через Claude Code** (`--agents cli`): каждое решение — новый процесс `claude -p` (3,9–5,8 с в живом вызове
  08.10.2026); лимиты подписки Anthropic не публикует. Для своей пробы на своём ПК — можно. В продукте для других вход
  по подписке использовать нельзя: «Unless previously approved, Anthropic does not allow third party developers to
  offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK»
  (https://code.claude.com/docs/en/agent-sdk/overview, 07.10.2026).
  Как сервер зовёт Claude Code: `--safe-mode` (не грузит CLAUDE.md, навыки, плагины, хуки и MCP пользователя; вход и
  модель — как обычно; `--bare` не годится — он подписку не использует), системный промпт — файлом
  (`--system-prompt-file`), наблюдение — через stdin, без инструментов (`--tools ""`), ответ по схеме (`--json-schema`),
  без сохранения сессий, в пустой временной папке. Проверено на Claude Code 2.1.294 (Linux, 08.10.2026). На Windows
  ставьте Claude Code нативным установщиком (`claude.exe`): с обёрткой `claude.cmd` из npm аргумент со схемой
  (кавычки, фигурные скобки) проходит через cmd.exe и может испортиться — предположение, на Windows не проверено.
  Старой версии без `--safe-mode` сервер покажет её ошибку в состоянии агента.

Имя модели в репозитории не записано: его задаёт тот, кто запускает (`--model`).

## Что проверено и что нет

Проверено здесь (тесты): путь «наблюдение из Lua → сервер → агент → решение → приказы героям» на имитации Доты под
LuaJIT с мотором «правила» (тот же путь, что с Claude); рефлексы рук (добивание, добивание своих, ожидание, отход и
возврат к плану, применение с подходом, вард у дальней вышки, способность без цели — только когда враг рядом, телепорт
из своей ячейки, прокачка по очереди, по умолчанию и с проверкой, что уровень вырос, покупка только у фонтана,
неизвестные имена); запасной исполнитель — и для всех героев без связи, и для одного героя, чей агент молчит 20 с
(ошибка мотора, предел вызовов, пауза 429); сбой наблюдения одного героя не мешает остальным; события убийств в
наблюдении; что уходит в Messages API и в `claude -p` и как разбирается ответ, включая обрезанный по `max_tokens`
(без настоящих вызовов API); расписание решений, ошибки, лимиты, журнал, возраст решений; имена всех функций,
констант и полей событий Доты сверены с @moddota/dota-data. Промпт агента проверен на головах Claude (пилот ниже).
Живой `claude -p` с настоящими промптами — 4 вызова, все решения приняты разбором (`experiments/pilots/2026-10-08_cli_live/`).

Независимая рецензия кода (подагент, 07.10.2026) — `docs/reviews/2026-10-07_agents_review.md`: 12 находок; что
исправлено и что нет — там же, в конце.

Не проверено (узнаем только из запуска у автора):
- живые вызовы Claude API из сервера (ключа здесь нет): задержка, цена, доля решений по схеме, отключение
  параметров по ответу 400;
- HTTP из кастомки на `127.0.0.1:8787` в Tools (`CreateHTTPRequestScriptVM`) — по описаниям и чужому коду;
- что герои-боты с выключенным встроенным ИИ слушают `ExecuteOrderFromTable` и не стоят; что прокачка приказом
  `DOTA_UNIT_ORDER_TRAIN_ABILITY` срабатывает (если нет — руки вкачивают напрямую `UpgradeAbility`);
- что стартовый телепорт лежит в ячейке `DOTA_ITEM_TP_SCROLL` (15) — знание игры, не описание API;
- `CanAbilityBeUpgraded`: описание API говорит bool, константы — перечисление; код принимает оба ответа;
- добивание по `GetAverageTrueAttackDamage × 0,9` без учёта полёта снаряда — грубо;
- «стоять» при фарме: герой сам бьёт крипов в радиусе атаки и толкает линию.

**Отступление от механик Доты — покупка.** Руки покупают так: `AddItemByName` + `SpendGold` по цене предмета, у
фонтана или мёртвыми. Запас магазина (варды, смок), тайная лавка, непокупаемые предметы при этом не проверяются;
при полном инвентаре предмет ложится в рюкзак, где не действует, а менять и продавать предметы руки не умеют. Честная
покупка — приказом `DOTA_UNIT_ORDER_PURCHASE_ITEM` (нужны номера предметов) — в плане.

## Пилот промпта на головах Claude (07.10.2026)

`experiments/pilots/2026-10-07_agent_prompt/` — пять типовых ситуаций (линия, приказ «пуш», драка, смерть с выкупом,
приказ, который руки не умеют), наблюдения собраны настоящим кодом кастомки, ответы — головы Claude через Agent (не API).
Все 14 ответов приняты разбором без потерь. Средняя модель — 5 из 5 по ожиданиям, записанным до ответов; быстрая —
3 из 5 в первом раунде: забыла покупки мёртвой с золотом, ставила «не отходить никогда», сказала тренеру неправду про
вард. По пилоту уточнён промпт и добавлено напоминание о покупках; после этого быстрая модель прошла обе ситуации,
но по одному ответу — это гипотеза для первого матча, а не проверенное улучшение.
