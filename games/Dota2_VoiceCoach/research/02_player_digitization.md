# 02. Оцифровка игроков Dota 2: реплеи, данные матчей, видео

Дата: 2026-10-06. Исполнитель: Claude, агент-исследователь темы 02 проекта Dota2_VoiceCoach.

Вопрос: как из реплеев (.dem), данных матчей и видео получить «цифрового двойника» конкретного игрока, от про-игрока до игрока с 2 MMR, чтобы потом его играл ИИ-агент в кастомке.

**Статусы фактов** (стоят у каждого факта в скобках):

- «полный текст»: я открыл страницу, файл или исходный код (для кода указаны коммит и дата);
- «сниппет»: видел только выдачу поиска (пересказ поисковика), первоисточник не открывал;
- «по памяти»: мои знания, в этой сессии не проверены;
- «свой прогон»: измерено мной на двух реальных реплеях программой на Manta (Приложение А). Повторить можно командами из приложения.

**Ограничения исследования.** Политика сети закрыла из контейнера docs/api/www.opendota.com, stratz.com, api.stratz.com, arxiv.org, Википедию, Liquipedia, Fandom, Steam, Reddit и серверы реплеев Valve. Открывались github.com (код и README), PyPI, индекс crates.io, proxy.golang.org, S3 Dotabuff с тестовыми реплеями Manta и storage.googleapis.com (PDF AlphaStar). Поэтому лимиты OpenDota взяты из исходного кода (значения по умолчанию), а не из рабочей конфигурации сервиса. Статьи, кроме AlphaStar, известны по сниппетам. К концу работы закончился общий лимит веб-поиска (200 запросов на ход), поэтому несколько вопросов остались на сниппетах и памяти (см. «Что не удалось выяснить»).

## Краткий итог

1. Больше всего данных даёт сам реплей .dem. В нём 30 тиков в секунду и снимок всех сущностей 15 раз в секунду. Записаны все приказы каждого игрока: тип, точка, цель, способность, выделенные юниты. Есть курсор в экранных координатах и боевой журнал. Проверено своим прогоном на двух реальных реплеях (2023 и 2025).
2. Реплей обычного матча Valve хранит недолго. Вторичные источники называют около 8–14 дней, комментарий в коде OpenDota — «не дольше нескольких недель». Поэтому данные обычного игрока надо собирать сразу после каждого матча: запрос разбора в OpenDota, подписка OpenDota за $5 в месяц с автоматическим разбором или .dem из клиента и свой парсер.
3. С 19.03.2025 матчи Immortal Draft (рейтинг от 8500) не попадают в публичную историю и Web API, а реплеи доступны только участникам (сниппеты). Пабы топ-про почти недоступны. Про-игроков оцифровывать по турнирным матчам: OpenDota разбирает лиги автоматически и хранит разобранные данные.
4. Живые парсеры 2026 года: Clarity 5.0.1 (Java, 05.10.2026), Manta (Go, 22.06.2026), odota/parser (Java на Clarity), source2-demo (Rust, 0.5.9) и gem-dota (чистый Python, 0.12.0 от 03.10.2026). На моём замере gem разбирал реплей 90 с, Manta — около 3 с.
5. Готовых полей OpenDota хватает для статистического профиля: purchase_log, lane_pos за первые 10 минут, actions по типам приказов, APM, тимфайты, варды, position_est. Для модели решений и микро-стиля нужен свой разбор .dem: позиций после 10-й минуты и времени приказов OpenDota не отдаёт.
6. Ближайшие прецеденты двойника — Maia в шахматах (индивидуальные модели; по сниппету стилометрия узнаёт игрока с точностью 98% по 100 партиям) и AlphaStar (обучение с учителем на 971 тыс. реплеев людей плюс статистика стратегии z; полный текст). Для MOBA есть Tencent JueWu-SL и MCC (сниппеты). OpenAI Five обучен с подкреплением и людей не имитирует.
7. За два месяца одному человеку реально сделать профиль, параметризованного бота в кастомке, небольшие модели решений на процессоре и стилометрию как меру сходства. Нереально повторить RL уровня OpenAI Five или AlphaStar и обучение по видео в масштабе VPT.
8. Перенос в кастомку прямой. Приказы в реплее и приказы кастомки (ExecuteOrderFromTable) используют одно перечисление DOTA_UNIT_ORDER_*: значения 0–35 совпадают (сверено по двум файлам).
9. Видео нужно только там, где нет реплея: скрытые Immortal-матчи на стримах и пабы с истёкшим реплеем. Детектор значков миникарты на YOLO достигает F = 0,94 (Dota2-Vis, 2026), но видео даёт в разы меньше данных, чем реплей.
10. Этика. В реплее записаны Steam ID всех 10 игроков (свой прогон), а индивидуальная модель позволяет опознать человека: авторы Maia из-за этого не публикуют индивидуальные модели. Двойников делать только с согласия. Известных про-игроков без разрешения давать как безымянные «архетипы».
11. Сколько матчей даёт устойчивый профиль, надо измерить пилотом (ICC и формула Спирмена–Брауна). Оценки в разделе 7 не проверялись.

## 1. Реплеи: срок хранения, скачивание, OpenDota, STRATZ, поиск матчей

### 1.1. Сколько дней Valve хранит .dem

- Официальной цифры Valve я не нашёл.
- По вторичным источникам реплеи на серверах Valve живут «около восьми дней» (сниппет, выдача oneesports.gg и steamcommunity.com, 2024).
- Другой вторичный источник называет «около 14 дней» для обычных и рейтинговых матчей (сниппет, hotspawn.com «How To Download Dota 2 Replays»).
- В старых обсуждениях Steam встречаются «неделя» и «2 недели» (сниппет).
- В коде OpenDota есть комментарий «Valve doesn't keep non-league replays for more than a few weeks» и закомментированный порог в 30 дней (полный текст: odota/core `svc/parser.ts`, коммит e0847d8, 05.10.2026).
- Турнирные и про-матчи хранятся «намного дольше» (сниппет, hotspawn.com). Подробнее в п. 1.7.
- Даже часть данных API устаревает: в интерфейсе OpenDota есть строка «Ability upgrade data has expired for this match» (полный текст: odota/web `src/lang/en-US.json`, коммит 7ccb42b, 03.10.2026).
- **Практический вывод:** разбор надо запрашивать в течение недели после матча.

### 1.2. Как скачать .dem (cluster, replay_salt)

- Адрес реплея: `http://replay{cluster}.valve.net/570/{match_id}_{replay_salt}.dem.bz2`. Для кластеров 413, 415 и 417 домен `dota2.com.cn`. Рядом лежит метафайл `.meta.bz2` (полный текст: odota/core `svc/util/utility.ts`, функция `buildReplayUrl`).
- `cluster` и `replay_salt` выдаёт Game Coordinator Dota 2. Нужен вошедший Steam-аккаунт: в OpenDota этим занимается сервис retriever с логином `STEAM_USER/STEAM_PASS` «for getting replay salt/profile data» (полный текст: `config.ts`, README odota/core).
- Ответ `GET /matches/{match_id}` в OpenDota содержит готовое поле `replay_url`, если соль известна (полный текст: `svc/util/buildMatch.ts`).
- В коде замерены этапы одного разбора: скачивание 2967 мс, распаковка bunzip2 6716 мс, разбор 9407 мс, обработка 3278 мс (полный текст: комментарий в `svc/fetcher/ParsedFetcher.ts`).
- Вызов GC возвращает настоящие account_id: «account ids are not anonymous in this call» (полный текст: комментарий в `svc/fetcher/GcdataFetcher.ts`).
- Свой реплей можно скачать в клиенте (вкладка «Просмотр», затем «Повторы»). Файлы лежат в `…\steamapps\common\dota 2 beta\game\dota\replays\` (по памяти).

### 1.3. OpenDota: запрос разбора, лимиты, ключи, цены

**Запрос разбора.**

- `POST /api/request/{match_id}` ставит задачу разбора, `GET /api/request/{jobId}` показывает её состояние. Описание в спецификации: «This call counts as 10 calls for rate limit (but not billing) purposes» (полный текст: `svc/api/spec.ts`, `svc/web.ts`).
- Запросы с ключом получают более высокий приоритет (полный текст: `spec.ts`, константа `PRIORITY.REQUEST_API_KEY`).

**Лимиты в коде по умолчанию** (полный текст: `config.ts`). Действующие значения сервиса задаются переменными окружения, и проверить их я не смог: API закрыт из контейнера.

| Параметр | Значение по умолчанию | Комментарий в коде |
|---|---|---|
| `API_FREE_LIMIT` | 3000 в день | после этого 429; с ключом сверх лимита платно |
| `NO_API_KEY_PER_MIN_LIMIT` | 60 в минуту | без ключа |
| `API_KEY_PER_MIN_LIMIT` | 300 в минуту | с ключом |
| `API_BILLING_UNIT` | 100 вызовов за $0,01 | — |

**Страница ключей.**

- Цена «$0,01 за 100 вызовов» зашита в интерфейс (`premPrice = 0.01`, `premUnit = 100`). Для ключа нужен способ оплаты («requires payment method»), лимит вызовов с ключом — «Unlimited».
- «Responses with status codes 404, 429 or 500 aren't billed» (полный текст: odota/web `src/components/Api/Api.tsx`, `en-US.json`).

**Что видят сторонние проекты 2026 года.**

- Без ключа наблюдали около 60 запросов в минуту и 3000 в день; авторы прямо называют это наблюдением, а не договором (фрагменты поиска по коду GitHub: atlonis/dota2-coach-skill `RESEARCH.md`, WumbleCat/dota-oracle `SOURCES.md`).
- В другом README написано «~60k calls/month unauth» (полный текст: DommyMM/dota-stats, «as of 2026-04»). Цифры расходятся. Я опираюсь на код: 3000 в день.

**Автоматический разбор** (полный текст: `svc/util/insert.ts`, `svc/util/queries.ts`).

- OpenDota сама разбирает матчи лиг и матчи, где есть «отслеживаемый» игрок.
- Сейчас отслеживаются активные подписчики и контрибьюторы. Раньше отслеживали по посещениям сайта: «At one point we tracked players based on visits».
- Подписка стоит **$5 в месяц**: «all your matches will be automatically parsed» (полный текст: `en-US.json`, ключи `subscriptions_*`).

### 1.4. STRATZ: токены, лимиты, ограничения

- API работает на GraphQL по адресу `https://api.stratz.com/graphql`. Нужен bearer-токен, привязанный к аккаунту; его выдают после входа через Steam (полный текст: STRATZ knowledge-base issue #37 от 22.11.2021; сторонний README WumbleCat — фрагмент).
- Типы токенов (полный текст: issue #37, автор STRATZ-Fantome):
  - Default — самые низкие лимиты, выдаётся без заявки;
  - Individual — «far higher rate limits» для веб-приложений;
  - Multi — отдельные токены для пользователей настольных приложений.
- Лимиты по типам токенов (полный текст: STRATZ knowledge-base issue #15 от 22.10.2020):

  | Токен | в секунду | в минуту | в час | в день |
  |---|---|---|---|---|
  | Default | 20 | 250 | 2000 | 10 000 |
  | Individual | 20 | 250 | 4000 | 20 000 |
  | Multi (на пользователя) | 20 | 20 | 50 | 100 |

- Ту же таблицу в 2026 году повторяют два независимых README (полный текст: DommyMM/dota-stats «as of 2026-04»; whothefusckisdaniil/Dota-Draft-Assistant `docs/stratz-research.md` от 25.09.2026).
- **Риск для автоматизации.** Простые `curl` и Node `fetch` к api.stratz.com блокирует защита Cloudflare. Автор обходил её запросами из страницы Playwright (полный текст: Dota-Draft-Assistant, 25.09.2026).
- Цен на API я не нашёл. Сайт STRATZ бесплатный (сниппет).
- Есть ли у STRATZ запрос разбора через API и разбирает ли сервис все матчи автоматически, не выяснил.
- Полезные поля: у каждого игрока `players[].playbackData` с событиями `playerUpdatePositionEvents`, `deathEvents`, `killEvents`, `playerUpdateHealthEvents`, `playerUpdateGoldEvents`, `abilityUsedEvents`, `abilityLearnEvents`, `buyBackEvents`; у матча `match.playbackData` с `roshanEvents`, `buildingEvents`, `towerDeathEvents`, `wardEvents` (фрагменты кода: mdiller/MangoByte, strbje/dota-coach-mvp).
- Позиции игроков STRATZ отдаёт с частотой около 1 Гц, «подтверждено живым запросом» (фрагмент: stovburtm-web/d2helper `docs/ml-roadmap.md`, 15.05.2026, патч 7.41c).
- Собственная метрика STRATZ — IMP (Individual Match Performance). Формула закрыта; есть отдельный Turbo IMP (сниппеты: medium.com/@STRATZ, esports.ru 15.10.2025).

### 1.5. Steam Web API напрямую

Всё в этом пункте — полный текст комментариев в `svc/fullhistory.ts` и `svc/fetcher/ApiFetcher.ts`, если не указано иное.

- `IDOTA2Match_570/GetMatchHistory` по account_id отдаёт до 500 последних матчей страницами по 100.
- Если игрок закрыл историю матчей, приходит `status 15`.
- «As of March 2025 high level matches are removed from results but still counted in results_remaining».
- «As of December 2021 filtering by hero ID doesn't work».
- «We currently can't fetch because the Steam GetMatchDetails API is broken». Сейчас OpenDota получает сводку матчей через `GetMatchHistoryBySequenceNum`.
- Сводка матча без реплея содержит по каждому игроку (полный текст: пример ответа `json/details_api.json` в odota/core): герой, K/D/A, LH/DN, GPM/XPM, урон по героям и башням, лечение, итоговые 6 предметов, уровень и `ability_upgrades` (порядок прокачки).
- Условия Steam Web API ограничивают 100 000 вызовов в день (сниппет: steamcommunity.com/dev/apiterms).

### 1.6. Как найти матчи игрока по Steam ID / account_id

- `account_id` = SteamID64 − 76561197960265728 (полный текст: odota/core `svc/util/utility.ts`).
- `GET /players/{account_id}/matches` отдаёт полную историю с фильтрами (полный текст: `spec.ts`):
  - по герою, линии, режиму, дате, победе и патчу;
  - с героем в своей или чужой команде;
  - с выбором полей `project`.
- `POST /players/{account_id}/refresh` обновляет историю (до 500 матчей), медаль и имя (полный текст: `spec.ts`).
- Если профиль закрыт, OpenDota показывает его только самому игроку и про-игрокам из `notable_players`. Подсказка в интерфейсе: «enable Expose Public Match Data in the Dota client to make your profile public» (полный текст: `svc/api/api.ts`, `en-US.json`).
- Анонимные игроки в матче получают заглушку `account_id = 4294967295` (полный текст: `utility.ts`).
- В STRATZ используется запрос `player(steamAccountId){ matches(request:{…}) }` (фрагмент кода: renzivan/reactjs-dota2-profile-tracker, план от 15.09.2026).

### 1.7. Про-игроки, лиги, старые турниры

Эндпоинты OpenDota (полный текст: `spec.ts`):

- `GET /proPlayers` — «Get list of pro players»;
- `GET /proMatches` — список про-матчей;
- `GET /leagues`, `/leagues/{id}`, `/leagues/{id}/matches` («excluding amateur leagues»), `/leagues/{id}/matchIds`, `/teams/{id}/matches`;
- `GET /explorer?sql=…` — «Submit arbitrary SQL queries to the database».

**Explorer.**

- В базе Postgres, к которой обращается Explorer, лежат только матчи лиг уровня `premium` и `professional` (полный текст: `insert.ts`, функция `upsertMatchPostgres`).
- Вместе с ними хранятся разобранные поля `lane_pos`, `purchase_log`, `actions`, `times`, `gold_t`, `obs_log`, `kills_log`, `ability_uses`, `life_state`, `lane_role`, `teamfights` и другие (полный текст: `sql/create_tables.sql`).
- **Это самый дешёвый источник «стиля» известных про-игроков:** SQL по тысячам турнирных матчей без своего разбора.

**Разобранные данные остаются после истечения реплея.** OpenDota хранит разбор в S3-совместимом архиве (`${matchId}_parsed`) и отдаёт его оттуда (полный текст: `svc/fetcher/ParsedFetcher.ts`, `config.ts`).

**Старые турниры.**

- Реплеи про-матчей хранятся дольше обычных (сниппет, hotspawn).
- Noxville (datdota) разбирал все 18 772 про-матча эпохи Source 1 (сниппет, noxville.substack.com «Source 1: any% complete»):
  - разобрано 86,62%;
  - у 9,58% реплея не оказалось;
  - у 2,96% данные испорчены;
  - 16 330 реплеев заняли около 64 часов на AMD Ryzen 9 3900.
- Авторы Dota2-Vis записали все 144 матча The International 2025 с обеих сторон, всего 288 видео Full HD (полный текст: README RicardoRCarvalho/dota2-vis от 13.08.2026). Отсюда следует, что эти реплеи были доступны через год, но это мой вывод, а не факт из источника.
- Хранит ли Valve реплеи лиг бессрочно — **не выяснено**.

### 1.8. Valve закрыла пабы топ-игроков (Immortal Draft)

- **19.03.2025** порог Immortal Draft подняли с 6500 до 8500 MMR, это примерно верхние 0,5% игроков. Такие матчи не показываются в публичной истории, реплеи доступны только участникам, в Web API матчи не попадают. Игрокам выше 8500 запретили рейтинговую игру в группе и обязали зарегистрировать официальное имя (сниппеты: esports.net, rdy.gg, escorenews.com 67185 и 67189, ggscore.com, hawk.live, объявление Steam «Dota 2 Update - 3/19/2025»).
- Пострадали функции STRATZ, Dotabuff и Dota2ProTracker (сниппеты).
- То же видно в коде OpenDota: «As of March 2025 high level matches are removed from results» (полный текст: `svc/fullhistory.ts`).
- **31.07.2026**, патч 7.41e: MMR игроков Immortal пересчитали в диапазон 1–9500 с сохранением порядка, порог Immortal Draft остался 8500 (сниппеты: fragster.com, players.com.ua, escorenews 79932).
- **09–10.09.2026** из-за ошибки Immortal Draft появился на всех рангах. Valve исправила её примерно через 30 минут (сниппеты: dsn.pe, cybersport.ru, esports.ru).
- **Вывод для проекта:** пабы топ-про (8500+) по реплеям оцифровать нельзя. Остаются турнирные матчи (лиги), матчи до марта 2025 (если реплей сохранился или в OpenDota остался разбор) и видео стримов (раздел 5).

**Что следует для оцифровки:**

- Уровень приказов есть в публичных реплеях: тип, точка, цель, очередь и выделенные юниты. Это основа микро-профиля.

- Мировое состояние приходит 15 раз в секунду, по нему можно восстановить, что видел игрок. Туман войны размечает gem-dota (`HeroVisibilityEvent`).
- Курсор есть только в экранных координатах. Камеру можно восстановить, если подтвердится гипотеза о pawn. Тогда видна и «привычка камеры» игрока.

### 2.3. Что берёт из реплея OpenDota (odota/parser)

Полный текст: `Parse.java` и `CreateParsedDataBlob.java`, коммит 0ab08be, 05.10.2026.

- Состояние каждого игрока снимается **раз в секунду** (`INTERVAL = 1`): x, y, уровень, K/D/A, LH/DN, золото, опыт, net worth, стаки, руны, варды, станы, состояние жизни, уровни способностей.
- В итоговый результат идут только поминутные массивы (`times`, `gold_t`, `xp_t`, `lh_t`, `dn_t`, `networth_t`, `camps_stacked_t`, `hero_damage_t`, `hero_healing_t`) и тепловая карта `lane_pos` **только за первые 600 секунд**.
- Приказы `SpectatorPlayerUnitOrders` попадают только **в счётчики по типам** (`actions`). Точки, цели и времена приказов OpenDota не сохраняет.

## 3. Готовые поля OpenDota и STRATZ: хватит ли для профиля стиля без своего парсинга

Поля разобранного матча OpenDota (полный текст: `CreateParsedDataBlob.java`, `svc/util/compute.ts`):

- **Экономика и темп:** `times/gold_t/xp_t/lh_t/dn_t/networth_t` по минутам. `lane_efficiency` — золото на 10-й минуте, делённое на теоретический максимум.
- **Линия:** `lane_pos` — тепловая карта за 10 минут. `lane`, `lane_role` (1 — лёгкая, 2 — мид, 3 — сложная, 4 — лес). `is_roaming`, если в основной линии игрок провёл меньше 45% времени.
- **Роль:** `position_est` (позиция 1–5). Считается по фарму на 10–12-й минуте, `lane_role` и ранней покупке вардов. В комментарии к коду: «98.9% exact vs reference labels on 100 pro matches» (полный текст: `compute.ts`, коммит e0847d8 от 05.10.2026; issue odota/core #1590 не открывал). Есть ли поле в рабочем API, не проверено: API закрыт.
- **Предметы:** `purchase_log` (время и предмет), `first_purchase_time`, `purchase` (количество), `item_uses`, `neutral_item_history`.
- **Способности:** `ability_uses`, `ability_targets`, `damage_targets`, `hero_hits`, `ability_upgrades_arr`.
- **Бои:** `kills_log`, `deaths_log`, `killed`, `killed_by`, `multi_kills`, `kill_streaks`, `damage`, `damage_taken`, `damage_inflictor(_received)`, `healing`, `stuns`, `life_state`, `buyback_log`, `teamfight_participation`. `teamfights` содержит начало, конец, позиции смертей, урон, способности и предметы в каждом бою.
- **Обзор:** `obs_log`/`sen_log` (время и координаты), `obs_left_log`/`sen_left_log`, `obs`/`sen` (карты точек).
- **Карта:** `runes_log`, `camps_stacked`, `creeps_stacked`, `rune_pickups`, `towers_killed`, `roshans_killed`.
- **Действия:** `actions` — число приказов по типам `DOTA_UNIT_ORDER_*`. `actions_per_min` = сумма приказов / длительность × 60. `pings`.
- **Матч:** `chat` (включая чат-колесо), `objectives`, `radiant_gold_adv`/`radiant_xp_adv`, `draft_timings`, `pauses`, а также `throw`/`comeback`/`stomp`/`loss` (размах преимущества по золоту в проигранных и выигранных матчах, по `radiant_gold_adv`).
- **Бенчмарки:** `GET /benchmarks` — перцентили по герою (полный текст: `spec.ts`).

**STRATZ** отдаёт позиции примерно раз в секунду по всему матчу через `playbackData.playerUpdatePositionEvents`, а также события здоровья, золота, способностей и вардов (фрагменты стороннего кода, см. п. 1.4).

**Вывод (мой анализ):**

| Уровень двойника | Хватит ли готовых данных | Чего не хватает |
|---|---|---|
| (а) статистический профиль: герои, сборки, тайминги, фарм, линия, варды, агрессия по K/D/A и урону, участие в боях | **Да**, OpenDota хватает | — |
| (б) модель решений: куда идти, когда пушить, фармить, ганкать | **Частично**: у STRATZ есть позиции раз в секунду, у OpenDota позиции только за первые 10 минут, смерти в боях и варды | Видимость (кто кого видел), кулдауны, точное время. Нужен свой разбор .dem или STRATZ |
| (в) микро: реакция, частота кликов, кайт, точность скиллов | **Нет**: у OpenDota только счётчики приказов по типам | Время, точки и цели приказов, снимки 15 Гц. Нужен свой разбор .dem |
| (г) «голос» и характер | Частично: `chat` и чат-колесо | Голоса игроков в реплее нет: Clarity упоминает голос только комментаторов про-матчей (полный текст: README Clarity) |

## 5. Видео: можно ли оцифровать игрока по YouTube или Twitch

**Когда видео вообще нужно.** Если есть match_id и реплей ещё на серверах (или уже разобран), реплей лучше во всём, кроме экрана игрока (см. ниже). Видео нужно, когда реплея нет:

- **пабы топ-игроков после 19.03.2025:** Immortal Draft скрыт, и стрим остаётся единственным источником (вывод из п. 1.8);
- пабы с истёкшим реплеем;
- матчи, в которых игрок играл анонимно.

**Что извлекается из видео.**

- *Миникарта.* Dota2-Vis (SBGames 2026, arXiv 2606.26970) разметили 2477 изображений миникарты 240×240 по 21 классу. Деление 1670 / 407 / 400. Лучший детектор YOLO11l: precision 0,974, recall 0,906, F 0,939, mAP50:95 0,729. Код и доступ к данным обещаны «soon» (полный текст: README, 13.08.2026). В репозитории есть папка `digit_templates_flat`: вероятно, это шаблоны цифр для чтения чисел HUD (догадка по названию, не проверял).
- *HUD.* Золото, K/D/A, предметы и часы читаются OCR или шаблонами (по памяти; готового инструмента для Доты не нашёл).
- *Экран игрока.* Положение камеры и курсора видно напрямую, с частотой кадров видео. В реплее курсор есть только в экранных координатах, а камеру приходится восстанавливать (п. 2.2).
- *Действия.* По видео видны только следы приказов: анимация клика, касты. Нужна обратная модель динамики, как в VPT. Обучить её можно на **своих** матчах, где есть и запись экрана, и реплей с точными приказами. Это гипотеза, в Доте не проверялось.

**Чем видео хуже реплея.**

- Видно только то, что на экране и на миникарте.
- Нет точного состояния мира, нет точных приказов, есть ошибки детекции.
- Нужна обработка часов видео на GPU или медленно на процессоре.
- Миникарта в 240 пикселях грубее позиций в реплее.

**Как найти match_id по видео.**

1. По 10 героям: `GET /findMatches?teamA=…&teamB=…` отдаёт до 10 последних публичных матчей с такими героями. Поиск идёт по таблице `public_matches`, которая может быть выборкой (полный текст: `spec.ts`, параметр `PUBLIC_SAMPLE_PERCENT` в `config.ts`).
2. Если известен account_id стримера: `/players/{id}/matches?hero_id=…&date=…` (полный текст: параметры `spec.ts`).
3. Match ID показан на экране после игры (по памяти).
4. Матчи Immortal Draft не попадают в Web API (сниппет), поэтому их match_id и реплей, скорее всего, получить нельзя.

Пример из LoL: Pandascore в 2018 году писала о координатах чемпионов по миникарте с помощью глубокого обучения (сниппет, только заголовок).

## 7. Уровни оцифровки и сколько нужно матчей

### 7.1. Уровни

Все числа матчей ниже — **мои оценки, не проверялись**. Как проверить, сказано в п. 7.2.

| Уровень | Признаки | Источник | Оценка числа матчей | Есть ли у игрока низкого MMR |
|---|---|---|---|---|
| **(а) Статистический профиль** | Пул героев и позиции (`position_est`, `lane_role`); сборки и порядок прокачки; тайминги ключевых предметов; GPM/XPM, LH на 10-й минуте (`lane_efficiency`); агрессия (убийства и помощь в минуту, смерти, урон по героям в минуту, участие в боях); варды (число, места, время); руны, стаки, байбеки; тепловая карта линии | OpenDota после разбора; часть есть без разбора (герои, K/D/A, LH/DN, GPM/XPM, предметы, порядок прокачки) | 20–50 на роль; для сборки конкретного героя 10 и больше | **Да**, если матчи публичны и разобраны вовремя |
| **(б) Модель решений** | Состояние каждую секунду: позиции 10 героев, **видимость** (что знал игрок), время, золото и опыт, вышки, Рошан, руны, ключевые кулдауны. Цель — «намерение» на 10–30 с: линия, лес, ганк, пуш, Рошан, отход | Свой разбор .dem (Manta или Clarity, или gem для видимости) либо STRATZ playbackData | Популяционная модель — сотни и тысячи матчей (лиги из OpenDota); персональный сдвиг — 20–100 матчей игрока (аналог Maia4All) | Да. Шум выше, решения менее устойчивы, поэтому матчей нужно больше |
| **(в) Микро-стиль** | Приказы в минуту; доля «спама» (интервал меньше 200 мс); доли move, attack и cast; attack-move или attack-target; hold и stop; shift-очереди; реакция от появления врага в видимости до первого приказа (шаг 67 мс); ластхит относительно HP крипа (боевой журнал); кайт (чередование атаки и движения); попадания скиллшотов; привычки курсора и камеры | Только свой разбор .dem | Тысячи приказов за матч, поэтому средние могут устояться за 3–5 матчей; редкие события (скиллшоты конкретного героя) — десятки матчей на героя | **Да**: реплей Herald технически такой же, как реплей про |

| 2 | 351 | 77 | 17,4 | 3,4 | 13 | 67 | 81% |
| 3 | 115 | 84 | 2,8 | 7,8 | 0 | 200 | 32% |
| 4 | 67 | 77 | 11,5 | 7,5 | 0 | 200 | 32% |
| 8 | 226 | 74 | 19,3 | 3,1 | 141 | 67 | 82% |

Это один матч в режиме Turbo. Устойчивы ли такие различия от матча к матчу, **не проверялось**.

### 7.2. Как измерить, сколько матчей нужно (план пилота)

1. Взять 5–10 согласившихся игроков разных уровней, по 30 и больше матчей у каждого. Разбирать .dem сразу после матча.
2. Для каждого признака посчитать ICC — долю межигроковой дисперсии в общей.
3. Число матчей для надёжности профиля R считать по формуле Спирмена–Брауна: k = R·(1 − ρ) / (ρ·(1 − R)), где ρ — ICC одного матча (формула по памяти). Например, при R = 0,9 и ρ = 0,5 получается k = 9; при ρ = 0,2 — k = 36; при ρ = 0,1 — k = 81.
4. Разбить признаки по типам задач и ролям заранее, а не сливать их в одну проверку (правило CLAUDE.md).

### 7.3. Как проверять двойника: правда от кода

- **Мера сходства — стилометрия.** Обучить классификатор «тот же игрок или нет» на реальных матчах. В Доте такая постановка уже давала 95% (Yuen и др., сниппет). Затем подать ему матчи двойника из кастомки. Хороший двойник опознаётся как оригинал так же часто, как реальные матчи. Отдельно сравнивать распределения микро-признаков (расстояние Вассерштейна или критерий Колмогорова–Смирнова).
- **Подвох со слабыми игроками.** Модель имитации выбирает «средний ход» и поэтому сильнее оригинала (полный текст: README Maia). Двойника игрока с 2 MMR нужно сэмплировать из распределения действий и явно моделировать ошибки (невнимание, запоздалую реакцию), а не брать самое вероятное действие.
- **Учёт тумана войны.** Решение оценивается по тому, что игрок мог видеть, а не по исходу: это есть в gem-dota (`HeroVisibilityEvent`) и в подходе dota-foresight (сниппет).

### 7.4. Перенос двойника в кастомку

- В кастомке приказы юнитам отдаёт `ExecuteOrderFromTable` — «Issue an order from a script table» (полный текст: ModDota/API `dump/script_help2.lua`, коммит 570fff4 от 15.05.2023).
- Перечисление `DOTA_UNIT_ORDER_*` в описании API кастомок (`examples/vscript/declarations/dota-enums.d.ts`) и в протоколе реплеев (`dota_commonmessages.proto` в Manta) совпадает для значений **0–35** (полный текст: сверил оба файла).
- Значения 36–42 есть в протоколе и встречаются в реплеях: 37 и 38 в реплее 2023 года, 42 в реплее 2025 года (свой прогон). В описании ModDota 2023 года их нет — в текущем движке надо проверить.
- **Вывод:** двойник может выдавать приказы в том же пространстве действий, в котором записан оригинал.

## 8. Этика и права

**Сделано выводов по фактам:**

- **В реплее записаны Steam ID и имена всех 10 игроков** (свой прогон на реплее 2025 года). Вызов GC тоже отдаёт неанонимные account_id (полный текст: комментарий в OpenDota). Был ли у этих игроков выключен «Expose Public Match Data», неизвестно. Скрывает ли настройка ID в самом .dem, **не проверено**.
- Настройка «Expose Public Match Data» в клиенте закрывает игрока от сторонних сайтов: в OpenDota он виден как Anonymous, ID 4294967295, профиль закрыт (полный текст: код и интерфейс OpenDota). По сниппетам настройка по умолчанию выключена, а уже собранные данные при выключении не удаляются (blog.opendota.com FAQ, dotabuff.com, hotspawn). Это не проверено.
- Индивидуальная модель поведения — это инструмент опознания. Поэтому авторы Maia не публикуют модели конкретных игроков: «because of the stylometry results … we cannot release anonymous models» (полный текст: README maia-individual).
- Valve сознательно закрыла данные топ-игроков (март 2025): цель — бороться с договорными играми и закрыть доступ к пабам про (сниппеты). Обходить это закрытие, например перехватом реплеев или сбором чужих Immortal-матчей, нельзя.
- Условия Steam Web API ограничивают объём вызовов и запрещают использовать данные для нежелательной рекламы (сниппет: steamcommunity.com/dev/apiterms). Условия OpenDota и STRATZ на использование данных я не открыл (сайты закрыты).

**Рекомендации (мой анализ, не юридическая консультация; правовые нормы по памяти):**

1. **Обычные игроки, включая игроков с 2 MMR:** только с явного согласия. Человек сам включает публичность матчей или присылает свои .dem. Двойник хранится у автора. Публиковать модель или «играть за человека» на публике — только с отдельного разрешения. В ЕС поведенческий профиль опознаваемого человека — это персональные данные (GDPR, по памяти).
2. **Известные про-игроки:** имя, ник, образ и голос — предмет прав на публичный образ, а ники команд ещё и торговые марки (по памяти). В публичной кастомке Steam Workshop без письменного разрешения использовать **безымянные архетипы** («агрессивный мидер стиля 2010-х», «саппорт-роамер»), обученные на турнирных данных. Голос реального человека не клонировать.
3. **Двойник себя и друзей** — самый чистый вариант для первой версии: согласие есть, реплеи свои.
4. Правила Steam Workshop и кастомок Dota 2 об именах реальных людей я **не нашёл** (см. ниже). Перед публикацией их нужно проверить.

## Приложение А. Как повторить замеры реплея

Реплеи брались в отдельную папку. Программа лежала в другой папке и подключала Manta на коммите 0efe7e1 через `replace` в `go.mod` (Go 1.24.7, Linux).

```bash
mkdir -p replays && curl -o replays/8552595443.dem https://s3-us-west-2.amazonaws.com/manta.dotabuff/8552595443.dem
git clone https://github.com/dotabuff/manta && (cd manta && git checkout 0efe7e1)
mkdir replaycheck && cd replaycheck
# go.mod: module replaycheck / require github.com/dotabuff/manta v0.0.0 / replace github.com/dotabuff/manta => ../manta
GOFLAGS=-mod=mod go build -o replaycheck . && ./replaycheck ../replays/8552595443.dem
```

```go
// replaycheck: что лежит в реплее Dota 2 (.dem). Использование: ./replaycheck <файл.dem>
package main

import (
	"fmt"
	"os"

	"github.com/dotabuff/manta"
	"github.com/dotabuff/manta/dota"
)

func main() {
	f, err := os.Open(os.Args[1])
	if err != nil {
		panic(err)
	}
	defer f.Close()
	p, err := manta.NewStreamParser(f)
	if err != nil {
		panic(err)
	}
	p.Callbacks.OnCDemoFileInfo(func(m *dota.CDemoFileInfo) error {
		fmt.Printf("время %.1f с, тиков %d, тиков/с %.2f, game_mode %d\n", m.GetPlaybackTime(), m.GetPlaybackTicks(),
			float64(m.GetPlaybackTicks())/float64(m.GetPlaybackTime()), m.GetGameInfo().GetDota().GetGameMode())
		return nil
	})
	orders, withPos, withTarget := 0, 0, 0
	byType := map[int32]int{}
	gaps := map[uint32]int{}
	last := map[int32]uint32{}
	p.Callbacks.OnCDOTAUserMsg_SpectatorPlayerUnitOrders(func(m *dota.CDOTAUserMsg_SpectatorPlayerUnitOrders) error {
		orders++
		byType[m.GetOrderType()]++
		if m.Position != nil {
			withPos++
		}
		if m.GetTargetIndex() != 0 {
			withTarget++
		}
		if t, ok := last[m.GetEntindex()]; ok && p.Tick-t <= 4 {
			gaps[p.Tick-t]++
		}
		last[m.GetEntindex()] = p.Tick
		return nil
	})
	combat := 0
	p.Callbacks.OnCMsgDOTACombatLogEntry(func(*dota.CMsgDOTACombatLogEntry) error { combat++; return nil })
	updTicks := map[uint32]bool{}
	minX, maxX, minY, maxY := int32(1<<30), int32(-1), int32(1<<30), int32(-1)
	p.OnEntity(func(e *manta.Entity, op manta.EntityOp) error {
		updTicks[p.Tick] = true
		if e.GetClassName() == "CDOTAPlayerController" {
			if x, ok := e.GetInt32("m_iCursor.0000"); ok {
				minX, maxX = min(minX, x), max(maxX, x)
			}
			if y, ok := e.GetInt32("m_iCursor.0001"); ok {
				minY, maxY = min(minY, y), max(maxY, y)
			}
		}
		return nil
	})
	if err := p.Start(); err != nil {
		fmt.Println("ошибка разбора:", err)
	}
	fmt.Printf("тиков с обновлением сущностей: %d из %d (%.2f в секунду)\n", len(updTicks), p.Tick, float64(len(updTicks))/(float64(p.Tick)/30))
	fmt.Printf("приказов %d, с точкой %d, с целью %d; по типам %v\n", orders, withPos, withTarget, byType)
	fmt.Printf("интервалы между приказами одного игрока (в тиках, 0..4): %v\n", gaps)
	fmt.Printf("записей боевого журнала %d; курсор X [%d..%d], Y [%d..%d]\n", combat, minX, maxX, minY, maxY)
}
```
