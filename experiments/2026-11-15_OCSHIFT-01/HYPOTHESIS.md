Толкование — `journal/DECISIONS.md`: все прогоны на сторонних площадках (Kaggle, GitHub Actions); «продолжи» — ответ на мою рекомендацию в итоге OCREP-01: правило «уверенность головы против LR-AGREE» заранее, на свежем сдвиге, с AGREE того же сдвига как контролем.

**Что изменил разбор трёх готовых сдвигов** (`EXPLORE-three-shifts.md`; пост-хок, опорой не считается).
- В линии «оценщик» не было базы «одна лучшая голова» (ONE-BEST): голова с лучшей точностью на ID и её собственная откалиброванная уверенность, без выбора между головами (ERRORS № 163).
- На трёх готовых сдвигах, в тесте и в пилоте, её ИОИ ниже, чем у лучшего из восьми оценщиков толпы: 0,312 против 0,472; 0,420 против 0,479; 0,429 против 0,486 (тест).
- Отбор между головами сам даёт самообман, без сдвига: у CONF на ID с кросс-подгонкой заявка выше точности на 0,055–0,090 (тест).
- Поэтому главный контроль нового опыта — ONE-BEST. Правило автора (CONF против LR-AGREE) остаётся.

**Главный вопрос Neu — оценщик, который не обманывается под давлением отбора.** OCSHIFT-01 спрашивает на десяти свежих средах:
1. лучше ли одна лучшая голова, чем лучший из восьми оценщиков толпы;
2. даёт ли сам отбор между головами самообман — на ID, без сдвига;
3. что лучше — CONF или LR-AGREE (слово автора), и различается ли ответ между средами (C-089).

## Среды (свежие; ни одна задача и ни одна подсказка раньше не использовались)
- Задача — «трёхзначное + двузначное»: a ∈ [X00, X99], b ∈ [10, 99]. ID — сумма < (X+1)00, OOD — сумма ≥ (X+1)00.
- Диапазоны X = 4, 5, 6, 7, 8. У каждого две подсказки теста (p = 0, 1; по 4 примера, зерно 7 600 000 + 1000·X + p).
- **Среда — пара (диапазон, подсказка): 10 сред теста, по 2200 задач.** Задачи сред не пересекаются (зерно разбиения 7 610 000 + X); примеры подсказок в задачи не идут.
- Зачем две подсказки: в OCCOR-01, OCMIX-01 и OCREP-01 у сдвига была одна подсказка, и «сдвиг» нельзя было отделить от «четырёх примеров».
- Пилот — третья подсказка (p = 9) и свои 300 задач на диапазон; с задачами теста не пересекается.
- Головы — те же девять Pythia.

## Определения (закреплены до пилота)
- **Восемь оценщиков толпы** — AGREE, NB-AGREE, LR-AGREE, NB-IND, FAM-AGREE, CONF (код OCCOR-01), VETO, MIX-LR (код OCMIX-01), без изменений. Калибровка — изотоническая по ID среды, по головам; выбор — наибольшая откалиброванная заявка, ничья «поровну»; ИОИ = (1 − T) + max(0, C − T).
- **ONE-BEST** — голова с наибольшей точностью на ID среды (при равенстве — первая по порядку списка голов). T — её точность на OOD; C — средняя её заявка на OOD; заявка — изотоника по её logp на ID (та же, что у CONF для этой головы). Между головами ничего не выбирается.
- **Самообман от отбора без сдвига** — на ID среды, кросс-подгонка в 5 частей (зерно 7 620 000 + 10·X + p): калибровка — без части, выбор головы и счёт T и C — на части. Мера — T − C по всем задачам ID.
- **Проверка метода в среде:** голова проходит, если на ID и на OOD у неё не меньше 20 верных и 20 неверных ответов и ответов без числа не больше 5 %. Толпа и кандидаты ONE-BEST — прошедшие головы. Среда годна, если прошло не меньше 6 голов.
- **Сверка цепочки:** в каждом прогоне извлечения — первые 96 задач пилота OCREP-01 с его подсказкой. Ответы всех голов должны совпасть с закоммиченным выводом OCREP-01; допуск по logp задаётся по пилоту.

## Правила (уровень 0,0025 на сторону; вердикт — по ДИ BC и процентильному вместе, совет 58)
Среднее — по годным средам, с равными весами. Бутстреп вложенный (ID с переподгонкой, затем OOD), 10000 повторов, независимо по средам; в каждом повторе ONE-BEST выбирается заново.
- **R1 (одна голова против толпы):** D1 = среднее по средам [ИОИ(ONE-BEST) − наименьший ИОИ среди восьми оценщиков толпы]. Лучший из восьми берётся в каждой среде задним числом, по правде, — это фора толпе.
  - «Подтверждено» — верхняя граница < 0: одна голова лучше даже лучшего задним числом оценщика толпы.
  - «Опровергнуто» — нижняя граница > 0.
- **R2 (самообман от отбора без сдвига):** D2 = среднее по средам [T − C у CONF на ID с кросс-подгонкой]. «Подтверждено» — верхняя граница < 0 (заявка выбранного ответа выше его точности); «опровергнуто» — нижняя > 0.
- **R3 (слово автора):** D3 = среднее по средам [ИОИ(CONF) − ИОИ(LR-AGREE)]. «Подтверждено» — верхняя граница < 0 (CONF лучше); «опровергнуто» — нижняя > 0 (LR-AGREE лучше).
- **R4 (различие между средами, C-089):** неоднородность D3 по средам. Q = Σ (D3 среды − среднее)² / s², s — стандартное отклонение бутстрепа среды. «Подтверждено» — p < 0,0025 и по бутстрепу с центрированием под нулевую гипотезу, и по χ² с (число сред − 1) степенями свободы. Иначе «не решено»; «опровергнуто» у этого правила нет.
- Правило с мощностью < 0,05 при «не решено» читается как «не проверено».
- Если годных сред меньше 8 или сверка цепочки не прошла — все правила «не определено (проверка метода)».
- Ложное «подтверждено» по серии из четырёх правил — не выше 0,01.

## Описательно (вес 0, без вердикта)
- Таблица по средам: восемь оценщиков и ONE-BEST — T, C, самообман, ИОИ, Брайер выбранной заявки; верхние 10 %.
- ONE-BEST против каждого из восьми; то же по Брайеру (ИОИ не штрафует заниженную заявку).
- Контроль AGREE той же среды для R3 (совет 59): ИОИ(CONF) − ИОИ(AGREE) и ИОИ(LR-AGREE) − ИОИ(AGREE).
- Самообман от отбора на ID у всех восьми; доля самообмана OOD, которая есть уже на ID.
- Где выбор отходит от ответа ONE-BEST: доля задач и точность там.
- Вторая калибровка после отбора (POST), слияние FUSE-MIN, ONE-BEST с заявкой min(CONF, LR-AGREE), правило MIN-C.
- Толпа без лучшей головы против лучшей из оставшихся.
- Разложение различий между средами: диапазон и подсказка.
- Оракул; доли выбора по головам.

## Что опровергнет
- R1: ДИ среднего целиком выше 0 — на свежих средах оценщик толпы (лучший задним числом) лучше одной головы.
- R2: ДИ целиком выше 0 — отбор по уверенности на ID не завышает заявку.
- R3: ДИ целиком выше 0 — LR-AGREE лучше CONF в среднем по свежим средам.
