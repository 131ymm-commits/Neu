# OCSHIFT-01 — отклонения от PREREG (коммит 2721a7fa)

1. **Время.** Извлечение на Kaggle шло 3580,3 с при прогнозе 3151 с. Анализ на GitHub Actions — 5890,6 с; прогноз PREREG §10 — от полутора до двух с половиной часов. На вердикты не влияет.
2. **Вес стороны «подтверждено» у R3 посчитан после данных.** В PREREG §6 мощность и вес были только для ожидаемого знака (LR-AGREE лучше CONF). Подтвердилась другая сторона (CONF лучше).
   - Вес посчитан по той же формуле и на тех же зарегистрированных числах `power.json`: порог — дальняя граница этой стороны в единицах SE цепочки, эффект — та же половина по модулю, без предохранителя; мощность 0,134.
   - Потолок — ожидание E4 = 0,11 из PREREG §7. Вес — 5,46 бита.
   - Счёт — `facts_ocshift.py`, ключ `other_side`; совет 61 может этот вес снизить или снять.
3. **Сборка производных чисел — отдельным заданием GitHub Actions** (`gha_jobs/ocshift_facts.sh` → `gha_out/ocshift_facts/`). В порядке PREREG §10 этого шага не было. Сборщик `facts_ocshift.py` не входит в хеши регистрации.
   - До данных теста в него добавлены поля новых правил (строгая ветвь, число сред того же знака, смещение повторов).
   - После данных — вес другой стороны (п. 2).
4. **Сборщик отчёта** `report_ocshift.py` тоже не входит в хеши. Разделы «Коротко», 5, 7 и 8 написаны после данных; числа в них берутся из json.
5. Других отклонений нет.
   - Код анализа, сценарий, обёртка задания и файл workflow сверены по хешам в том же задании: «совпало».
   - Сырой вывод закоммичен до анализа (45500072). До анализа проверялась только целостность: число голов и сред, коды выхода, отсутствие ошибок и ключей.
   - Попытка на Kaggle одна; запасной путь извлечения не понадобился.
