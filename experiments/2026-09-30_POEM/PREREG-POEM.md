# PREREG «Арена стихов» — пилот (30.09.2026)

Основание: слово автора 30.09 («пусть они друг с другом соревнуются, а не просто с математикой»; «рисуй рисунки»; «выбирай из них или стихи» — Claude выбрал стихи); совет 18 (`docs/council/2026-09-30_POEM_session18.md`, 3 из 4). Твёрдое требование Левого (голосовал «против» до этого изменения) включено по правилу автора от 28.09: вместо выбора из двух гипотез — одно правило решения с тремя исходами (ниже).

## Устройство
- **Заказ нападающего:** тема; 2–6 пунктов прозой; по функции `def item(poem)` на пункт (подмножество Python по AST, только библиотека `poemlib.py` и базовые встроенные; строковые константы ≤ 40 символов; ≤ 2 млн шагов); стихотворение-свидетель; тип (буквенный / слоговой / рифменный / словесный); ставка.
- **Библиотека** `poemlib.py` (описание прозой видят все роли): строки, слова `[а-яё]+`, буквы (ё ≠ е), слоги = гласные буквы (без ударения и метра), рифменный хвост от последней гласной (≥ 2 букв), рифма = разные слова с одинаковым хвостом, первые буквы строк, словарь OpenCorpora (`pymorphy3.word_is_known`), повторы. Юнит-тесты и сверка интерпретатор = CPython: `test_poemlib.py`, 0 расхождений.
- **Базовое условие каждого заказа:** ≥ 2 строк; все слова в словаре; одно слово ≤ 3 раз.
- **Приёмка кодом:** свидетель проходит свои пункты в интерпретаторе и CPython (вердикты совпадают); свидетель проходит базовое условие; проверка отвергает ≥ 50 % из 30 механических искажений свидетеля (буква / слово / строка). Одна бесплатная попытка исправить.
- **Честность:** независимая голова пишет проверки только по прозе пунктов; проверки нападающего и независимые сравниваются по пунктам на пуле текстов (свидетель, искажения, свидетели других заказов, тексты двух искателей расхождений, все стихи защитников). Хоть одно расхождение → заказ снят (0 очков нападающему). Опора вывода — только честные заказы.
- **Руки защитников (2×2):** {одиночка, команда поэт → редактор} × {без библиотеки, с библиотекой}. На попытку у каждой руки ровно 2 вызова модели: одиночка — «написать» и «проверить и исправить своё»; команда — поэт и редактор (редактор видит заказ и стих, не рассуждение поэта). В руках с библиотекой инструмент — только команды `python3 /tmp/poemtool/poemlib.py ...` (одиночка — оба вызова, команда — только редактор); без библиотеки — никаких команд (аудит журнала). Защитники не видят кода проверок, только прозу.
- **Две попытки:** попытка 1 → обратная связь по коду (прошло/нет, номера нарушенных пунктов, слова не из словаря) → попытка 2 только у не прошедших рук. Итог руки — прохождение после попытки 2.
- **Очки:** защитнику +1 за итоговое прохождение; нападающему +1 за каждую провалившую руку на честном заказе.
- **Против бессмыслицы (вторичная мера, «не истина»):** слепая голова выбирает тему итогового стиха из 5 (верная + 4 темы других заказов; случайно 0,2), сверяет код. Калибровка на свидетеле и на свидетеле с перемешанными строками.

## Правило решения (первичное, записано до холостого прогона)
Первичная оценка — парная разность долей итогового прохождения **Δ = команда без библиотеки − одиночка без библиотеки** по честным заказам, 95 % ИД для парной разности (Ньюкомб, метод 10). Граница эквивалентности **δ = 0,15**. Исходы: ИД целиком > 0 — команда лучше; ИД целиком внутри (−δ, +δ) — эквивалентны; ИД целиком < 0 — команда хуже; иначе — не решено (набрать объём). **В пилоте правило только оценивается** (описательно); по доле несогласных пар считается объём подтверждающего прогона; данные пилота в подтверждающий анализ не входят.
Положительный контроль: одиночка с библиотекой против одиночки без (ожидается выше; если нет — арена не различает руки).
Вторичные: взаимодействие факторов; разрыв по типам заказов; доля ошибочных пунктов поэта, которые редактор без библиотеки оставил, против доли верных, которые он испортил; прохождение попытки 1 и после обратной связи; узнаваемость темы.

## Объём
Холостой прогон: 1 нападающий × 3 заказа, вся цепочка — только инфраструктура (сколько снято и на каком шаге, число вызовов, время); доли прохождения по рукам не считаются и не показываются. После него поправкой с хешем меняются только технические пороги (доля отвергаемых искажений, K, лимиты).
Пилот: 2 нападающих × 4 заказа × 2 раунда = 16 поданных, цель ≥ 12 честных; на заказ ≈ 3 вызова панели + 8 (попытка 1) + до 8 (попытка 2) + 6 (тема) ≈ 25 вызовов → ≈ 400 вызовов.

## Моя калибровка
P(одиночка без библиотеки проходит итог ≤ 50 % честных заказов) = 0,6; P(с библиотекой выше, чем без, у одиночки) = 0,85; P(|Δ| ≤ 0,15 точечно) = 0,55; P(> 25 % поданных заказов снято честностью) = 0,5.

## Холостой прогон (30.09, 1 нападающий × 3 заказа; только инфраструктура)
- Приёмка: 3 из 3 заказов приняты кодом с первой попытки; доля отвергаемых искажений свидетеля 0,67 / 0,77 / 0,73 (порог 0,5 оставлен).
- Честность: независимые проверки совпали с проверками нападающего по всем пунктам на всём пуле (свидетели, 30 искажений, тексты искателей расхождений с тире, кавычками, латинской «a», дефисами, стихи защитников): снятых 0.
- Вызовы: панель 9, попытка 1 — 24, попытка 2 — 4, слепая тема — 18; всего 55 + 1 нападающий. Отказов и пустых ответов 0.
- Аудит защитников (28 вызовов): руки без библиотеки команд не запускали; руки с библиотекой вызывали только `poemlib.py` (и создание каталога/файла) — нарушений 0.
- Замечание: при 3 заказах в слепой теме только 3 варианта (темы других заказов); в пилоте заказов ≥ 12 — будет 5.
- Доли прохождения по рукам не считались и не смотрелись. Технические пороги не меняются. Данные холостого прогона в пилот не входят.
