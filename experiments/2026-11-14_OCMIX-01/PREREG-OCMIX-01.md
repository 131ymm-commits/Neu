## 4. Оценщики и выбор головы (`analyze_ocmix.py`)
- **AGREE, LR-AGREE, CONF** — код OCCOR-01 без изменений (тест 10/10 сверяет совпадение).
- **VETO** — logp ответа, если его дала хотя бы ещё одна голова; иначе logp − 1000.
- **MIX-LR** — логистическая регрессия по ID на голову: совпадения с каждой другой головой и стандартизованный по ID logp; L2, C = 1. При одном классе в выборке ID — константа.
- **Общее:**
  - калибровка — изотоническая по ID теста, по головам и оценщикам;
  - выбор — наибольшая откалиброванная вероятность, ничья «поровну»;
  - ИОИ = (1 − T) + max(0, C − T).
  - Верхушка `top10_sel`: единица — задача OOD, ранжируется откалиброванная оценка выбранного ответа, порог ⌈0,1 · n⌉, граничный блок ничьих — дробно; самообман = заявка − точность. Поле json — `evaluators[*].top10_sel.deception`.
- **Бутстреп** вложенный: 4000 повторов (зерно 1301). Каждый повтор — выборка ID с возвращением, переподгонка LR-AGREE, MIX-LR и калибровки, затем выборка OOD. Выборки заранее, счёт в нескольких процессах.

## 5. Правила (уровень 0,0025 на сторону; интервал BC)
- **R1 (главное, верхушка):** D1 = самообман верхушки VETO − LR-AGREE.
- **R2 (в среднем):** D2 = ИОИ(VETO) − ИОИ(CONF).
- **R3 (повтор C-086 на свежем сдвиге):** D3 = ИОИ(LR-AGREE) − ИОИ(AGREE).
- **Вердикт:** «подтверждено» — верхняя граница ДИ < 0; «опровергнуто» — нижняя > 0; иначе «не решено».
- **Проверки метода** (провал → R1–R3 «не определено (проверка метода)»): загружены все девять голов; у каждой на ID и на OOD не меньше 20 верных и 20 неверных; ответов без числа не больше 5 %; голов не меньше 6.
- **Защита LR:** повторов с одним классом у какой-то головы в выборке ID больше 1 % — R1 и R3 «не решено». Порог может отменить подтверждение, но создать его не может.
- **Хвосты BC:** число повторов за каждой границей и интервалы по двум половинам повторов; если половины дают разный вердикт — пометка «граница по Монте-Карло неустойчива» (вердикт не меняет).
- **Описательно** (вес 0, без вердикта, в серию не входит; ДИ BC 99 %): MIX-LR против VETO (ИОИ и верхушка), MIX-LR против LR-AGREE (верхушка), VETO против CONF (верхушка), VETO против LR-AGREE и AGREE (ИОИ); разложение R2 на ΔT и ΔC; доля поддержанных выбранных ответов VETO; кросс-подгонка LR-AGREE и MIX-LR (только точка); AUROC; верхушка по всем парам.
- Ложное «подтверждено» по серии из трёх правил — не выше 0,0075; так же для ложного «опровергнуто».

## 6. Мощность и вес опоры (`power.json`)
Нормальное приближение, как в OCCOR-01: стандартная ошибка теста = ширина ДИ 99 % пилота / (2 · 2,576) · √(1494 / 3409). Порог z = 2,807.

| Правило | Δ пилота | SE теста | Мощность по пилоту | Мощность при эффекте вдвое | Вес, бит |
|---|---|---|---|---|---|
| R1 | −0,0278 | 0,0267 | 0,039 | 0,011 | 2,15 |
| R2 | −0,0010 | 0,0178 | 0,003 | 0,003 | 0,13 |
| R3 | −0,0955 | 0,0195 | 0,982 | 0,363 | 7,18 |

- **R1 и R2 почти без мощности.** Исход «не решено» для них ожидается. Тест ставится ради R3 (повтор главного вывода OCCOR-01 на свежем сдвиге) и ради описательного вопроса: переносится ли самообман верхушки согласия (C-088) на свежий сдвиг.
- Вес — log₂(мощность при эффекте вдвое / 0,0025). Опровержение — тот же вес со знаком минус. «Не решено» — 0 бит.

## 8. Ограничения (записаны до данных теста)
- Одна задача (сложение) и один новый сдвиг; головы — те же девять Pythia, что в OCCOR-01.
- Пилот уже показал, что явления, ради которого придумано вето, на этом сдвиге почти нет. Отрицательный или «не решено» исход по R1 и R2 о смеси скажет мало: вето нечего исправлять.
- Сухой прогон indep: на заглушке без общих ошибок H3 = +0,0235 при ожидании |H3| < 0,02 — ожидание не выполнено. Без структуры общих ошибок LR-AGREE может быть чуть хуже AGREE.
- LR-AGREE и MIX-LR подгоняются и калибруются на одних задачах ID. Для верхушки это сдвигает их в сторону «обманывается» и может помогать R1. Кросс-подгонка — описательно.
- BC при уровне 0,0025: граница со стороны сдвига опирается на немногие повторы; хвосты и половины — в json.
