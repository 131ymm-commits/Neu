## Зачем
Критерий 3 из `journal/DECISIONS.md` (27.09.2026): «честный оценщик в EVO по мере совета EVO-06: |C − T| выжившей элиты на свежих тестах вдвое меньше BASE при незнании не хуже». Здесь посчитана БАЗА (BASE) и, для сравнения, остальные руки EVO-05, до предрегистрации нового эксперимента.

## Что и как мерил (откуда взято каждое число)
- Источник: `experiments/2026-09-26_EVO-05/runs/{task}_{arm}_s{seed}.json`, ключ `hist` — список из 151 записи `{gen, claimed, true}` (поколения 0…150).
- **Выжившая элита** — особь `best = argmax(key)` поколения; в `evo05.py` она копируется в следующее поколение без изменений (`new = [pop[best]]`). Именно для неё сохранены `claimed` и `true`.
- **C (заявка)** — `hist[g].claimed`. **Заявка сохранена**, дописывать код не нужно. У BASE — доля верных на 16 свежих случайных тестах поколения (`claim = raw`, тесты из отдельного потока `r_test`, новые каждое поколение); у R80 — на 80 свежих; у HEAD/HEAD_LCB — предсказание μ головы (`claim = mu`). Важно: у BASE заявка считается по тем же 16 тестам, по которым сделан отбор (проклятие победителя), — это и есть «BASE» критерия.
- **T (истина)** — `hist[g].true`: доля верных той же особи на 1000 скрытых входах (`hid`, отбор их не видит).
- **|C − T|** — по поколениям; агрегирую двумя окнами: все 0–150 и **121–150** (окно, которое совет EVO-06 назначил для первичной меры ИОИ′ = (1−T) + |C−T|).
- **max(0, C − T)** и **1 − T** — по `truth.py`; сверено: совпадают с сохранёнными ключами `deception` и `ignorance` каждого прогона (assert в скрипте).
- Агрегат по сидам — **медиана** (в json также среднее и квартили). Столбцы T и C — медианы средних по 121–150.
- «Вырожд.» — число прогонов из 20 с итоговой T < 0,1 (порог совета EVO-06; в базу входят все прогоны, без исключений).
- Оговорка о словах критерия: «на свежих тестах» здесь означает, что заявка C делается по свежим тестам поколения, а истина T — по скрытым 1000 входам (как в ИОИ). Отдельной «истины на свежих тестах» в прогонах нет; если критерий подразумевает T на независимой свежей выборке, а не на скрытой, это надо добавить в код нового прогона (см. «Что дописать»).

## Что видно (описательно)
- **База критерия 3 по T2–T5 (EVO-05, BASE): |C − T| ≈ 0,09 в окне 121–150 (медиана 0,088; по задачам 0,028 / 0,096 / 0,084 / 0,095 для T2 / T3 / T4 / T5), незнание 1 − T ≈ 0,46 (0,037 / 0,739 / 0,466 / 0,524).** Цель «вдвое меньше» — |C − T| ≈ 0,044 (по задачам 0,014 / 0,048 / 0,042 / 0,048) при незнании не выше базы. На других сидах (EVO-03, EVO-04) база BASE та же с точностью до сотых: 0,091 и 0,096 по T2–T5.
- **У BASE |C − T| — это почти целиком шум 16 тестов, а не проклятие победителя.** Средняя знаковая C − T в окне 121–150 у BASE: T2 0,021, T3 0,059, T4 0,008, T5 0,014 (медианы 0,000 / 0,063 / 0,000 / 0,013). Только на T3 завышение заметно; на T4/T5 разброс |C − T| ≈ 0,08–0,10 при смещении ≈ 0,01. Это согласуется с оценкой Скептика в совете EVO-06 (шум заявки по 16 входам до ≈ 0,125). Следствие для нового эксперимента: разделение отбора и заявки (SPLIT) уберёт смещение, но шум 16 входов не уменьшит; «вдвое меньше» по |C − T| на T4/T5 достижимо только большей выборкой заявки или сглаживанием (голова).
- **R80 уже описательно попадает в цель:** по T2–T5 |C − T| 0,040 против 0,088 (≤ ½ BASE в 54 парах из 80; побед 59, ничьих 11), незнание не хуже (46 побед против 21 у BASE). Но это 80 ответов оракула вместо 16 — другой бюджет, а не другой оценщик; для критерия «0 вызовов голов при том же бюджете» R80 — потолок «грубой силы».
- **HEAD/HEAD_LCB** дают |C − T| 0,037 / 0,033 (тоже меньше половины базы: ≤ ½ BASE в 45 / 50 парах из 80), но проваливают условие «незнание не хуже»: BASE выигрывает по незнанию в 69 / 71 парах из 80 — тот же вывод, что в REPORT-EVO-05 («самообман мал, потому что голова ничего не вырастила»).
- **T2 особая:** BASE почти решает задачу (T ≈ 0,96), база |C − T| = 0,028, а шаг заявки по 16 тестам — 1/16 = 0,0625. Половина базы (0,014) ниже разрешения одной заявки; на T2 критерий проверять надо по среднему за окно, а не по поколению, и ожидать много ничьих (у R80 против BASE — 7 из 20).
- **T1 и T6** в критерий не входят (гладкие); BASE решает их полностью (T = 1, |C − T| = 0 в окне 121–150), сравнивать нечего.

## Что не удалось посчитать и почему
- **T «на свежих тестах» отдельно от скрытой правды** — в прогонах нет: `hist[g].true` считается только на 1000 скрытых входах. Вариант «истина на независимой свежей выборке» посчитать нельзя без нового прогона. Для нового эксперимента см. ниже.
- **Разложение |C − T| на смещение и шум по поколениям** сделано только через среднюю знаковую C − T; дисперсию заявки по одной особи (несколько независимых выборок тестов за поколение) без нового прогона не получить.
- **Доверительные интервалы** не считал: пост-хок описательный, вердикта не меняет; в json есть среднее и квартили по сидам, парные победы даны без порогов.
- Пилоты `pilot_v1/`, `pilot_v2/` (сиды 998, 999) в базу не включены — по PREREG они в тест не входят.

## Что дописать в код для нового прогона (критерий 3)
Заявка C уже сохраняется (`hist[g].claimed`), дописывать её не нужно. Для честного зачёта критерия предлагаю в `evo06.py` (или новом файле) добавить в запись поколения:
1. `claimed_fresh` — доля верных элиты на **отдельной** свежей выборке из независимого потока (`default_rng(3*10**6 + seed)`, как записал совет), не участвующей в отборе; тогда |C − T| можно разложить: (C_sel − T) — проклятие победителя, (C_fresh − T) — чистый шум выборки.
2. `true_fresh` — доля верных на другой независимой свежей выборке того же размера, если критерий читать буквально («истина на свежих тестах»); скрытые 1000 (`true`) оставить как в ИОИ.
3. `n_labels` — число размеченных входов за поколение (единица бюджета совета), чтобы R80-подобные ветви не выглядели «честнее» задаром.
4. Сохранять `abs_ct_late`, `signed_ct_late`, `ign_late` (окно 121–150) в итоговом json рядом с `ioi`, чтобы анализ не пересчитывал `hist`.
5. Сверка при подмене выборки заявки: траектория популяции должна совпасть побитово (требование совета EVO-06).
