# OCPOST-01 «ОЦЕНЩИК-ПОСЛЕ-ОТБОРА» — гипотеза (15.11.2026, 21:20 UTC; до кода опыта и до любых его данных)

## Откуда вопрос
- **Слово автора:** «делай» (15.11.2026) — ответ на рекомендацию после OCINT-01.
- **Главный вопрос Neu** — оценщик, который не обманывается под давлением отбора.
- **Что уже есть:**
  - C-090 (OCSHIFT-01, R2): отбор головы по наибольшей откалиброванной заявке (CONF) завышает заявку уже на ID, без сдвига.
  - C-097 (OCINT-01, описательно): по закону a + b·(n/m) около 0,9 этого завышения остаётся при бесконечной калибровке — его не убрать большей выборкой; нужен оценщик, который учитывает сам отбор.
  - OCSHIFT-01, описательно (точки, 10 сред; эти данные породили гипотезу и опорой не считаются): ИОИ CONF 0,882; вторая калибровка после отбора по частям (POST-CV CONF) 0,823; одна лучшая голова (ONE-BEST) 0,838. По Брайеру POST-CV CONF хуже ONE-BEST (0,177 против 0,153).
- **Идея.** Отбор — это тоже вход оценщика. Вторая калибровка учит, насколько верна выбранная заявка именно после отбора: на ID, вне частей, по которым откалиброваны головы, она сопоставляет выбранной заявке долю верных выбранных ответов. Если отбор — главный источник самообмана, после второй калибровки самообман на ID должен исчезнуть, а толпа с честной оценкой — догнать или обогнать одну лучшую голову.

## Определения (только уверенность голов; код OCSHIFT-01 — `analyze_ocshift`: калибровка, выбор, ИОИ)
- **CONF** — изотоническая калибровка logp каждой головы по ID среды; выбор наибольшей заявки, ничья «поровну».
- **POST-CV CONF** — вторая калибровка: изотоническое отображение «выбранная заявка → верен ли выбранный ответ», обученное на парах ID вне частей (5 частей, закреплены за исходными задачами, как в OCSHIFT-01); применяется к выбранным заявкам вне диапазона.
- **ONE-BEST** — голова с наибольшей точностью на ID; её собственная откалиброванная заявка.
- **FIXED** — голова, закреплённая по имени до данных: pythia-2.8b-deduped; её собственная откалиброванная заявка; отбора нет.
- **wc X** — T − C на ID с кросс-подгонкой: wc CONF (как в OCSHIFT-01), wc POST (вложенная кросс-подгонка: вторая калибровка учится внутри обучающих частей), wc FIXED.

## Правила (уровень 0,0025 на сторону; интервал M4 — точка ± 2,807·ст. откл. повторов бутстрепа, OCINT-01; среднее по годным средам)
- **P0 (положительный контроль, повтор C-090 на свежих средах):** wc CONF < 0 — «подтверждено», если верхняя граница < 0.
- **P1:** ИОИ(POST-CV CONF) − ИОИ(CONF) < 0 — «подтверждено», если верхняя граница < 0; «опровергнуто», если нижняя > 0.
- **P2:** ИОИ(POST-CV CONF) − ИОИ(ONE-BEST): «подтверждено», если верхняя граница < 0 (толпа с честной оценкой лучше одной головы); «опровергнуто», если нижняя > 0.
- **P3 (самообман от отбора на ID снят):** wc POST равен нулю с точностью ±0,02 — «подтверждено», если интервал целиком внутри [−0,02; +0,02]; «опровергнуто», если интервал целиком вне этой полосы (верхняя < −0,02 или нижняя > +0,02).
- **N (отрицательный контроль, совет 63):** wc FIXED равен нулю с точностью ±0,02 — то же правило. Если N опровергнуто, способ счёта T − C сам смещён, и вердикт P3 читается как «не определено».
- **Т (хвост M4, совет 63):** свежие миры модели OCINT-01 (зерно, которого не было), не меньше 30 миров по 100 опытов, те же пять статистик (P0–P3, N). Доля односторонних промахов M4 при 0,0025 по каждой стороне, по мирам: «подтверждено», если у всех статистик и сторон верхняя граница ниже 0,0075 (втрое больше номинала); «опровергнуто», если у какой-то нижняя граница выше 0,0075.
- Правило чтения P2: если P2 «подтверждено», а по Брайеру POST-CV CONF хуже ONE-BEST, запись реестра — «по ИОИ лучше за счёт заниженных заявок, по Брайеру хуже».
