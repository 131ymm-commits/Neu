# OCDIV-01 «ОЦЕНЩИК-РАЗНЫЕ-ГОЛОВЫ» — гипотеза (16.11.2026, 12:14 UTC; до кода опыта и до любых его данных)

## Откуда вопрос
- **Слова автора, 16.11.2026:**
  - «Ты думаешь. Внешние ресурсы считают. Кстати ты можешь лбопщатся к другим ИИ? Попробуй их так то интегрировать в проект.»
  - «Да делай» — ответ на рекомендацию начать ОЦЕНЩИК-РАЗНЫЕ-ГОЛОВЫ на открытых моделях разных производителей (`docs/2026-11-16_other_AIs.md`).
- **Главный вопрос Neu** — оценщик, который не обманывается под давлением отбора.
- **Что уже есть** (все головы до сих пор — одно семейство, девять Pythia):
  - C-090 «установлено» узко: отбор по наибольшей откалиброванной заявке (CONF) завышает заявку на ID. Совет 65: на другие головы не переносится.
  - C-100: вторая калибровка после отбора сводит самообман на ID в полосу ±0,02.
  - C-102, описательно: вне диапазона самообман у всех оценщиков, даже у одной головы, названной до данных.
  - OCGEO-01, разведка: когда два варианта pythia-2.8b оба ошибаются, их неверный ответ совпадает в 0,77–0,78 случаев. Эти данные породили гипотезу и опорой не считаются.
- **Идея.** Оценщику по согласию нужны разные ошибки голов. Головы других производителей учились на других данных и другой архитектурой. Если их ошибки совпадают реже, чем у Pythia, согласие разнородной толпы — более честный свидетель. Заодно — первая проверка вне семейства Pythia для C-090 и C-100 и предсказание совета 65 «калибровка на ID не переносится вне диапазона».

## Данные
- **Тест — пять сред OCPOST-01:** X = 4…8, подсказка p = 2, по 2200 задач.
  - Задачи и подсказки берутся из сырого вывода OCPOST-01 (`experiments/2026-11-15_OCPOST-01/run/out/answers.json`, коммит f4dc1ba9): поле `prompt_head`, задачи `problems`. Правда — по коду (ответ == a + b).
  - **Однородная толпа** — девять голов Pythia. Их ответы и logp на этих средах уже есть в том же файле; заново они не считаются.
  - Совпадение ошибок у пар Pythia на средах теста не считалось и не считается до регистрации; его считает только задание анализа теста.
- **Разнородная толпа** — открытые модели других производителей. Тот же запрос, что у Pythia: `prompt_head + "a+b="`, без чат-шаблона. Жадный вывод, не больше 6 новых токенов. Ответ и logp — функцией `answer_logp` из `ocpost_extract.py`: сверка по коду, а не по памяти.
- **Счёт** — процессор GitHub Actions (`gha_par/`): одно задание — одна голова на одной среде. Без ключей; веса с Hugging Face без лицензионного замка; ревизия каждой модели записывается.
- **Пилот** — десять сред OCSHIFT-01 (X = 4…8, p = 0, 1). В тест они не входят; ответы Pythia на них есть (`experiments/2026-11-15_OCSHIFT-01/run/out/answers.json`). Новые головы считают первые 300 задач каждой среды.

- **Отбор голов — только по ID пилотных сред:**
  - проверка метода, как в OCPOST-01: не меньше 20 верных и 20 неверных ответов на ID и не больше 5 % ответов без числа;
  - время — не больше 1,5 с на задачу на раннере;
  - не больше двух голов на производителя и не меньше четырёх производителей;
  - если годных больше девяти — девять с наибольшей точностью на ID пилота при тех же ограничениях;
  - если производителей меньше четырёх — опыт перепроектируется, запись в журнал.
- **FIXED-нов** — годная голова с наибольшей точностью на ID пилота. Она называется в PREREG до данных теста.

## Определения (код OCPOST-01 — `ocpost.post_stats` — и OCSHIFT-01 — `analyze_ocshift`; «как в X» — сверка по коду)
- Оценщики на разнородной толпе: CONF, POST-CV, ONE-BEST, FIXED-нов, SHIFT (контроль «постоянное снижение заявки», совет 65), AGREE, оракул выбора (верно, если верна хоть одна голова; описательно).
- **q(i, j)** — совпадение ошибок пары голов в среде: доля задач, где у обеих голов ответ — число, обе ошиблись и их ответы равны, среди задач, где обе ошиблись и у обеих ответ — число. Считается по всем задачам среды (ID и OOD).
- **Q-нов** — среднее q по парам разнородной толпы от разных производителей.
- **Q-py** — среднее q по парам шести разных моделей Pythia: 1.4b, 1.4b-deduped, 2.8b, 2.8b-deduped, 6.9b, 6.9b-deduped; чекпойнты одной модели не берутся.

## Правила (уровень 0,0025 на сторону; M4 — точка ± 2,807·ст. откл. повторов бутстрепа; среднее по годным средам; бутстреп по задачам внутри среды, одинаковый для всех голов)
- **D1 (главное новое: разные производители — разные ошибки):** Q-нов − Q-py < 0. «Подтверждено», если верхняя граница < 0; «опровергнуто», если нижняя > 0.
- **D2 (C-090 вне семейства Pythia):** wc CONF разнородной толпы < 0, с теми же сторонами. Предохранитель «без одного диапазона» — как в OCPOST-01.
- **D3 (предсказание совета 65: калибровка на ID вне диапазона не переносится):** C − T вне диапазона у FIXED-нов, со знаком.
  - «Подтверждено (не переносится)» — интервал целиком вне полосы [−0,02; +0,02].
  - «Опровергнуто (переносится)» — интервал целиком внутри полосы.
- **D4 (C-100 вне семейства Pythia):** wc POST разнородной толпы в полосе ±0,02 — правило P3 OCPOST-01.
- **D5 (согласие разнородной толпы):** ИОИ(AGREE) − ИОИ(CONF) вне диапазона < 0, с теми же сторонами. Если мощность по пилоту меньше 0,2, правило переходит в описательное; решение записывается в PREREG до данных.
- **N (отрицательный контроль):** wc FIXED-нов в полосе ±0,02. N «опровергнуто» — D4 «не определено».
- **Опыт определён**, если годны не меньше 4 сред из 5 по проверке метода OCPOST-01, применённой к разнородной толпе.
- **Описательно** (вес 0):
  - Q-нов и Q-py по средам и типам ошибок (например, потерянный перенос разряда);
  - q у пар «новая голова — Pythia»;
  - ИОИ, незнание и самообман всех оценщиков в обеих толпах и в смешанной толпе;
  - POST-CV − SHIFT; оракул.
- **Множественность:** шесть правил на уровне 0,0025 на сторону. Ложное «подтверждено» в серии — не больше 0,015.

## Ожидания
Записываются в PREREG по пилоту и мощности, до данных теста.

## Что может пойти не так (проверить пилотом и тестами до PREREG)
- Чат-модели на запросе без шаблона дописывают текст. Ответ — ведущее целое, как у Pythia; доля ответов без числа — в проверке метода.
- Слабые модели почти всё решают неверно — тогда q считается на малом числе общих ошибок. В пилоте смотреть число общих ошибок на пару.
- Время на процессоре: оценку по пилоту умножить на 2, сравнить с лимитом шага 340 мин (ERRORS № 171).
