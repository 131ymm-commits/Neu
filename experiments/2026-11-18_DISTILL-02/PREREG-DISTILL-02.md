## 1. Программа головы (HYPOTHESIS, 394b7be2) и что уточнено до регистрации
- **Ответ программы:** a + b − Σ_j 10^j · D_j по разрядам j, куда есть перенос. P(D_j = 1) = σ(w · x_j), не больше 3 признаков, жадно по BIC.
  - Кандидаты в признаки: pos (разряд), top (старший перенос), newplace (перенос в новый разряд), prop (перенос протянут, а не порождён), chain (длина цепочки), c1, nines, ood, phi = Φ_j − 1 (запас переноса по Wen и др.).
  - Коэффициенты — две значащие цифры, проверка — по округлённым.
- **«Прочие» ошибки** (не потеря переноса) — доля ε головы. Их смещения взяты по частотам головы на построении, как у B1; остаток — равномерно по справочному множеству V (числа с n − 2 … n + 1 цифрами, n — цифр в сумме). Это уточнено после ERRORS № 209: при равномерной «прочей» части база частот выигрывала у верной программы.
- **Соперники:**
  - B1 — частоты смещений головы без учёта входа, 30 самых частых;
  - Φ-база — та же программа с одним признаком phi;
  - ящик — бустинг деревьев глубины 3 на признаках задачи, предсказывает класс исхода (верно / набор потерянных переносов / прочее);
  - B0 — «верно с частотой головы, иначе любое число из V» (только описательно).
- **Строится** по семейству («тысячи», «длина») на всех собранных ответах (§2), для каждой из семи голов.

## 4. Меры (код — `distill02.py`, часть 2)
- **m1** — среднее по головам разности лог-вероятностей ответа головы «программа − B1» на числовой ответ.
- **m1_phi** — то же, «программа − Φ-база».
- **m2** — доля объяснимого: Σ(программа − B1) / Σ(max(ящик, программа) − B1) по головам; не больше 1.
- **m3** — ln(K наблюдённое / K из программ):
  - K — среднее по парам голов доли одинаковых смещений среди задач, где обе дали неверное числовое смещение;
  - K из программ — среднее по R = 20 выборкам, где каждая голова отвечает по своей программе независимо при данном входе. «Без числа» — на тех же местах, что у голов.
- **Бутстреп** — строки задач с возвращением, B = 4000; одни строки для всех мер среды.
- **M4** — точка среднего сред ± z · ст. откл. повторов среднего (`ocdiv4.mean_entry`), z = 2,807 (0,0025).
- **t по средам** — `ocdiv4.t_envs`.
- **Знак по средам** — `ocdiv4.env_signs` при 0,0025 / n.

- **Часть А** — нижняя граница M4 среднего сред (за вычетом сдвига) больше 0. У двустороннего — нижняя больше 0 или верхняя меньше 0.

- **Вердикты:**
  - «подтверждено» / «больше» — часть А и (где есть) часть Б;
  - только часть А — «в среднем этих сред (на новые среды не переносится)»;
  - иначе — «не решено»; противоположная сторона — «опровергнуто» / «меньше».
- **Описательно** (мощность ниже 0,2): Р2-Л.
- **Чтение (заранее):**
  - **Р1 подтверждено** — на свежих задачах программа отдаёт настоящим ответам головы больше вероятности, чем частоты смещений без учёта входа: какие переносы есть и какие теряются, задаёт вход через простую формулу.
  - **Р1Ф подтверждено** — признаки программы добавляют к одному потенциалу переноса Φ.
  - **Р2-Т подтверждено** — программа из ≤ 3 признаков берёт больше половины того, что ящик на тех же признаках.
  - **Р3 «больше»** — головы совпадают в неверных числах чаще, чем дают их программы, независимые при данном входе: совпадение не сводится к простой математике входа и частотам «прочих» ошибок. «Меньше» — реже. «Не решено» — программы совпадение объясняют в пределах точности.
  - **Р4-Т подтверждено** — программы, построенные на четырёхзначных a, переносятся на пятизначные с тем же узором переносов.
  - Причину не пишу без проверки. «Установлено» — только после повтора с контролем на неспецифичность.
- **Описательно, без вердикта:**
  - доля неверных ответов, названных в трёх самых вероятных (программа против B1);
  - оценщик: AUC P(верно) программы против уверенности головы (logp);
  - F наблюдённое / из программ; формулы голов; L_X9999 (одна среда); m2 на «длине»; детерминизм; прибор (`trunc_check.py`).

## 7. Множественность
- Правил с вердиктом восемь (Р1-Т, Р1-Л, Р1Ф-Т, Р1Ф-Л, Р2-Т, Р3-Т, Р3-Л, Р4-Т), каждое при 0,0025 на сторону.

- Уровень номинальный: перенос M4 на 0,0025 для среднего сред не проверен.

## 11. Порядок прогона и запреты
1. **Регистрация** — коммит этого файла и констант. Шаблоны лежат в `jobs/`, вне `gha_par/`: пуш регистрации ничего не запускает.
2. **Запуск** — отдельным коммитом, в ходе, начатом уведомлением: копии 108 шаблонов в `gha_par/`.
3. **Анализ** — после вывода всех 108 заданий: копия `jobs/distill02_sum_test.sh`. Сверка хешей, тесты, анализ под `timeout 180m`.
4. Каждое задание — один прогон в полёте. Повтор — только после коммита вывода сбоя и с записью в DEVIATIONS.
5. Код после регистрации не меняется: задание анализа сверяет хеши и останавливается при расхождении.
