  - На своей подсказке формула не хуже уверенности головы; на другой подсказке не переносится.

## Вопрос
Можно ли заменить голову на сложении короткой программой, которую человек прочтёт вслух: «сумма a + b, но перенос в разряд j теряется с вероятностью σ(…) от двух-трёх признаков входа»?
- Программа должна воспроизводить не только частоту ошибок головы, но и сами неверные числа.
- И на свежих задачах, а не только там, где её строили.

## Программа головы (устройство закрепляется здесь)
- Для входа (a, b) код считает переносы c_j (перенос в разряд j).
- **Ответ программы:** a + b − Σ_j 10^j · D_j по разрядам j, куда есть перенос. D_j = 1 — перенос в разряд j потерян.
- P(D_j = 1) = σ(w · x_j): логистическая формула от не больше 3 признаков. Признаки — только из входа, их считает код:
  - сам разряд j;
  - старший ли это перенос;
  - перенос в новый разряд;
  - c1 и цифра десятков суммы u;
  - девятки в a;
  - длина цепочки переносов.
- **Прочие ошибки** (не «потеря переноса») — одна доля ε головы на семейство. Конкретное число программа не предсказывает: такой ответ получает вероятность ε, делённую на число «прочих» ответов в справочном множестве. Множество задаётся в PREREG.
- **Мерило «осознаваемости»** — как в DISTILL-01: не больше 3 признаков, коэффициенты с двумя значащими цифрами, одну задачу можно проверить на бумаге.

## Предсказания (направления; пороги, мощность и правила — в PREREG после пилота)
- **П1 — программа воспроизводит неверные числа.** На свежих задачах средняя лог-вероятность ответа головы по программе выше, чем по базе «верно с частотой головы, иначе — любое неверное число из справочного множества». То же для доли неверных ответов, названных программой точно (среди её трёх самых вероятных неверных ответов).
- **П2 — простота почти ничего не теряет.** Программа берёт большую часть того, что вообще объясняют те же признаки. Мера — доля объяснимого против «чёрного ящика» на тех же признаках. Порог — по пилоту.
- **П3 — совпадение ошибок голов задаётся входом через их программы.**
  - Если программы голов, независимые при данном входе, дают совпадение неверных чисел (K) и ложное большинство (F), близкие к наблюдённым, — совпадение объясняет простая математика входа.
  - Если наблюдённое заметно больше — есть совпадение сверх неё.
  - Направление не предсказываю: правило двустороннее.
- **П4 — перенос за диапазон построения.** Выигрыш П1 сохраняется на средах с новыми X, не входившими в построение.

## Данные (решено до кода)
- **Построение и пилот** — уже собранные ответы семи голов с подсказкой только из ID (p = 3): тест OCDIV-03 («тысячи» X = 19…59) и пилот и тест OCDIV-04 («тысячи» X = 19…89, «длина» X = 9, 99, 999).
  - Эти данные разобраны другими мерами (Т4, Δ3c, K). Поэтому все числа на них — описательно, проверки на них нет.
- **Проверка** — свежие задачи, отдельное извлечение на GitHub Actions. Места задач не пересекаются ни с одной прежней фазой, это проверяет код.
  - Среды построения, новые задачи.
  - Новые среды: X вне построения (для П4); выбор X — в PREREG до извлечения.
- **Пилот** — на данных построения: строить на одной части (OCDIV-04, пилот), проверять на другой (OCDIV-03, тест). Решается выбор признаков, справочное множество и мощность. Тест не трогается.

## Связь с главным вопросом (оценщик)
- **Программа как оценщик ответа головы:** вероятность «голова права» по программе — оценщик с правдой от кода, прозрачный. Обманывается ли он под отбором — описательно, мера ИОИ.
- **Программа как нуль для совпадения.** П3 даёт нуль, который сохраняет устройство задачи через явную модель, а не через перестановку. Это ответ на вопрос OCDIV-04 о годном нуле.

## Чего гипотеза не утверждает
- Что голова «внутри» считает так же: программа описывает поведение, а не механизм (механизм — следующая ступень).
- Что программа переносится на другую подсказку: DISTILL-01 показал, что нет; здесь подсказка одна (p = 3, только ID).
