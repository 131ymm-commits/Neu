## Линза 2. Ошибки кода, масштабы, статистика

**2.1 (важно) Ничьи на T1/T6/T2 и мощность.** На гладких задачах правда элиты в окне 121–150 часто ровно 1: в BASE EVO-05 `|C−T|` и `1−T` по окну равны точно 0 у 13/20 прогонов T1, 18/20 T6, 10/20 T2 (посчитано по `2026-09-26_EVO-05/runs`). В паре SPLIT16+16/SAME32 обе величины будут тождественно равны → ничьи. Ожидаю 10–20 ничьих из 60, т.е. n_eff ≈ 40–50. Код пересчитывает порог по n без ничьих (`evo06_analyze.py:58`, верно), но PREREG §5 приводит мощность только при n=60 (0,76 при доле 0,70); при n=45 порог 31, мощность 0,63; при n=40 порог 28, мощность 0,58. Для A/A (§7.6) код берёт n от одной меры `abs_ct_late` и применяет интервал ко всем трём (`evo06_analyze.py:164–165`), хотя n_eff у `ign_late`/`ioi2_late` иной. **Fix:** в PREREG §5 записать ожидаемое число ничьих и мощность при n≈45; в анализе — интервал нуля отдельно по n_eff каждой меры.

**2.2 (важно) Ставка Правого (§7.5): порог и вердикт.** PREREG: «> 0 не менее чем в 40/60»; код: `thresh(n, ALPHA)` при α=0,05 → 39/60 (`evo06_analyze.py:152`). Вердикт только «подтверждено/разницы нет» (`:155`), обратный эффект не выдаётся, хотя ожидание PREREG — «опровергнуто». Общая причина: `p_two_sided = min(1, 2·P(X ≥ wins))` (`evo06_analyze.py:61,154`) равен 1 при wins < n/2 (проверено: wins=9, n=56 → p=1 вместо 2,6·10⁻⁷), так что Холм никогда не отмечает обратный эффект, а в `cmp` «обратный эффект» ставится только по порогу без Холма (`:62`). **Fix:** `alpha=ALPHA/2` для ставки (порог 40), p = 2·min(P(X≤wins), P(X≥wins)), в ставку добавить ветку `rev ≥ k → «обратный эффект (опровергнуто)»`.

**2.3 (важно) Ворота не блокируют первичные.** PREREG §4: «если интервал SPLIT не содержит 0 — H2/H3 не вскрываются». Код печатает и сохраняет H2/H3 безусловно (`evo06_analyze.py:111–118`). **Fix:** `if has(...) and out.get('gate', {}).get('passed'):`, иначе писать в json `primary = 'не вскрыто: ворота не пройдены'`.

**2.4 (замечание) «Холм на две» = Бонферрони.** Обе первичные считаются при α/2 (`evo06_analyze.py:112–113`): это первый шаг Холма, второй шаг (α для второй гипотезы) не делается — консервативнее и совпадает с «порог 40/60» в PREREG. Записать словами «порог 40/60 для обеих (Бонферрони)».

**2.5 (замечание) Критерий «вдвое», лишний кандидат.** В `evo06_analyze.py:123` есть кандидат `SAME16/abs_pool_late`, которого нет в §6; для него тест незнания «SAME16 против SAME16» даёт n_eff=0, `threshold=None`, `passed=False` всегда (`:133`). Либо убрать, либо для базы считать условие незнания тождественно выполненным и добавить в §6.

**2.6 (замечание) «число пар с |C−T| ≤ ½ базы».** Код считает попарно — против половины `|C−T|` SAME16 в той же паре (`evo06_analyze.py:131`), как в POSTHOC EVO-05. Текст §6 допускает чтение «½ медианы базы». Уточнить формулировку.

**2.7 (замечание) Хеш кода не сверяется.** `code` пишется в json (`evo06.py:132`), но анализ его не читает; при повторном запуске с изменённым кодом смесь не обнаружится. **Fix:** в загрузчике `assert len({d['code'] ...}) == 1`, печатать хеш и сравнивать с хешем в PREREG.

**2.8 (замечание) Очередь.** Разбор `jobs.txt` проверен всухую: 480 строк → 480 команд по одной на строку, у пилотных строк с турниром 4 поля; хвостовой перевод строки есть; имя `_tour{n}` совпадает с `evo06.py:135`.
