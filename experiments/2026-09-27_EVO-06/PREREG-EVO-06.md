## 1. Вопрос
При одинаковом бюджете размеченных входов на поколение: что лучше — отбирать программы и заявлять их точность C по одной выборке тестов (проклятие победителя: C завышено) или по двум независимым (заявка честна по построению, но отбор идёт по меньшей выборке)? Цена разделения — падение правды T. Первичная мера совета — ИОИ′ = (1 − T) + |C − T| выжившей элиты в окне поколений 121–150; критерий 3 — |C − T| и незнание 1 − T (по пост-хоку EVO-05).

## 2. Постановка
Мир EVO-01/03 без изменений (`evo01.py`, `evo03.py`, копии из EVO-05): 300 программ-деревьев, 150 поколений, турнир 5, элитизм, задачи T1–T6, истина T — доля верных элиты на 1000 скрытых входах (`default_rng(10^6+seed)`; отбор их не видит — проверено подменой скрытого набора, `pilot/checks.log` п. 6: заявка, элита и её возраст не меняются ни в одной ветви, кроме ORACLE). Код: `evo06.py`; хеш кода пишется в каждый json (`code`), версии — в `runs/run.log`.

**Ветви** (имя = правило оценщика; в единицах совета «размеченных входов на поколение», поле `n_labels`):

| Ветвь | У совета | Отбор по | Заявка C по | labels/поколение | вызовов программ/поколение (`n_calls`) |
|---|---|---|---|---|---|

| SPLIT8+8 | **первичная пара** синтеза | 8 свежих | **другие** 8 свежих (поток `default_rng(3·10^6+seed)`) | 16 | 2408 (заявка — только у элиты) |

**Потоки случайности и что из этого следует** (по рецензиям; свойства постановки, не ошибки):
- Пары (задача, сид) общие для всех ветвей без сдвига: одна начальная популяция и вариация (`default_rng(seed·1000+№задачи)`, как в EVO-01), одна скрытая правда. Свежие тесты отбора — отдельный поток `default_rng(10^7+seed·1000+№задачи)`; постоянные — `default_rng(2·10^6+seed)` (как `fixed` в EVO-01, поэтому FIXED16 побитово = FIXED16 EVO-01, проверено). Выборка заявки не влияет на отбор: при подмене её потока траектория популяции совпадает побитово во всех восьми ветвях (`pilot/checks.log` п. 4).
- **SPLIT16+16 ≡ SAME16 по траектории.** Обе берут по 16 тестов на поколение из одного потока `r_sel`, значит ключ отбора, элита, T, `true_fresh`, `elite_age` и `claimed_fresh` совпадают побитово по всем поколениям; различается только заявка: `claimed(SPLIT16+16) = claimed_fresh(SAME16)` (`pilot/checks.log` п. 5). Следствия: (а) в критерии §6 пара SPLIT16+16/SAME16 — чистая разница заявки, незнание совпадает тождественно; (б) сравнение при равных вызовах (4816 ≈ 4800), о котором говорил черновик, — это то же самое, отдельной гипотезой не является. Кроме того, тесты отбора SAME32 в поколении g равны тестам SAME16 в поколениях 2g и 2g+1 (один поток, разный размер вызова) — вложенность потока, не популяций.
- **AA32 сдвигает и поток `r`** (другая начальная популяция и вариация) при общей скрытой правде. Поэтому пара SAME32/AA32 делит меньше случайности, чем пара SAME32/SPLIT16+16, и интервал A/A шире чистого шума оценщика: для ворот §4 это в сторону «пройдено», для полосы «разницы нет» (§5) — консервативно, «разницы нет» получить труднее. Фраза «одна начальная популяция во всех ветвях» верна для всех ветвей, кроме AA32.
- Потоки заявки (`3·10^6+seed`), `true_fresh` (`4·10^6+seed`) и постоянных тестов (`2·10^6+seed`), как и скрытая правда, сидированы без номера задачи: у одного сида все шесть задач получают одни и те же входы (разные функции и популяции). Это не утечка (проверено), но пары (T1,s)…(T6,s) знакового теста делят входы: на 120 пар приходится 20 независимых наборов входов заявки/правды. Пары считаются по (задача, сид), как записано; ограничение отчитывается, не исправляется (правка потоков сломала бы побитовую регрессию к EVO-01 и пилот; решение Claude 27.09).
- Скрытые 1000 входов покрывают ~200 из 201 значений отрезка −100…100; свежие тесты берутся из того же отрезка. «Отбор их не видит» верно для мультимножества скрытых ответов, не для значений (как в PREREG-EVO-05).

**Две единицы бюджета.** Совет принял «размеченные входы на поколение» (`labels`) — первичная единица; вызовы программ (`n_calls`) пишутся и отчитываются описательно. Первичная пара SAME16/SPLIT8+8 — равный бюджет 16 labels; SAME32/SPLIT16+16 — 32 labels (вторично, §7).

**Запись поколения** (`hist[g]`): `claimed` (заявка ветви), `true` (на 1000 скрытых), `claimed_fresh` (доля верных элиты на отдельной свежей выборке потока заявки; размер 16 у ветвей без разделения, у SPLIT — сама заявка размера m), `true_fresh` (на другой независимой свежей выборке того же размера, поток `4·10^6+seed`), `n_labels`, `n_calls`, `elite_age`. В итоговом json — меры окна (`abs_ct_late`, `signed_ct_late`, `ign_late`, `ioi2_late`, …), `ioi` и части, `labels_total`, `calls_total`, `gens`, `code`, `sec`. Json пишется атомарно (временный файл + `os.replace`), усечённый файл не может остаться под итоговым именем.

**Объём.** 8 ветвей × 6 задач × **20 сидов (80–99)** = 960 прогонов, `jobs.txt` (заняты: EVO-01 0–19, EVO-03 20–39, EVO-04 40–59, EVO-05 60–79, пилоты 996–999; сдвинутые сиды AA32 580–599 свободны, рецензия 1.4). Очередь `run_evo06.sh` (продолжает с места остановки, ждёт, пока опустеют `run_queue.sh`/`run_evo05.sh`; в основной ветке `EVO06_GENS` сбрасывается — всегда 150 поколений). Совет назначил 10 сидов; 20 взяты по мощности (§5), решение Claude в `journal/DECISIONS.md` 27.09 (вечер), человек может отменить до регистрации.

## 3. Меры
Окно — последние 30 поколений (121–150), по каждому прогону среднее по окну; агрегат по сидам — медиана; сравнения — парные по (задача, сид).
- **ИОИ′ = (1 − T) + |C − T|** (`ioi2_late`) — первичная мера совета.
- **|C − T|** (`abs_ct_late`) — главная мера критерия 3; **незнание 1 − T** (`ign_late`).
- Знаковая C − T (`signed_ct_late`) — проверка манипуляции и теоремы.
- Старый ИОИ и его части (`truth.py`: `ioi`, `ignorance`, `deception` = среднее max(0, C − T)) — вторично; **считаются по всем 151 поколению, не по окну** (так устроен `truth.py`, рецензия 2.10).
- Заявка, накопленная за жизнь элиты (`abs_pool_late`): среднее `claimed` по поколениям, пока элита — та же программа (`elite_age`), против T. Разведочно (советом не обсуждалась); в §6 — кандидат, но с пометкой.
- Правило вырожденности (итоговая T < 0,1) и «давления не было» (средняя T за последние 30 поколений ≤ средней за первые 10) — только для анализа чувствительности; первичный тест — по всем парам без исключений. Число помеченных прогонов отчитывается по каждой ветви. Ретроспектива по готовым данным (`retro_evo01_random16.py` → `pilot/retro_EVO01_RANDOM16.log`, воспроизводится из json EVO-01/EVO-05): RANDOM16 EVO-01 — вырожденных 10/60 (все на T1), «без давления» 1/60; BASE EVO-05 — 8/120 и 2/120.
- Ожидаемые ничьи: в BASE EVO-05 |C − T| и 1 − T в окне равны ровно 0 у 13/20 прогонов T1, 18/20 T6, 10/20 T2 (правда элиты = 1). В парах SAME16/SPLIT8+8 на таких задачах обе меры совпадут → ничьи; ожидаю 20–40 ничьих из 120, n_eff ≈ 80–100 (расчётная точка §5 — 90). Порог всегда пересчитывается по фактическому n без ничьих, до вскрытия, по каждой мере отдельно.

## 4. Ворота до вскрытия первичных гипотез (проверка манипуляции; обе половины условия совета)
Считаются по первичной паре **SPLIT8+8 / SAME16** по всем прогонам: (1) бутстреп-интервал 95 % (Монте-Карло, 4000, сид 0) средней знаковой C − T у SPLIT8+8 содержит 0; **и** (2) нижняя граница бутстреп-интервала 95 % средней знаковой C − T у SAME16 выше 0 (проклятие победителя видно). Ворота **пройдены** только при обоих условиях; иначе H2/H3 не вскрываются, в json пишется `primary = 'не вскрыто: ворота не пройдены'` и исход: «ИД SPLIT не содержит 0 — утечка выборки заявки в отбор» (ошибка кода, отчёт только об этом) либо «ИД SAME содержит 0 — проклятия победителя не видно, H2 неинформативна». Рядом отчитываются: те же интервалы без вырожденных прогонов (описательно), бутстреп-интервал средней разности знаковой C − T между SAME32 и AA32 (интервал A/A для средней, не для одиночных разностей), и те же ворота для пары SPLIT16+16 / SAME32 (отчитываются, вскрытие не блокируют). **H1** «знаковая C − T у SPLIT8+8 меньше, чем у SAME16» — проверка теоремы (условие Скептика): печатаются побед/n без ничьих, число пар, где SPLIT ближе к нулю, медиана парной разности с ИД95 — без порога, без вердикта, без Холма; то же для SPLIT16+16 / SAME32. Ожидание по пилоту (§10): при n = 6 условие (2) не выполняется (ИД широк); при n = 120 ширина ИД ≈ 0,01–0,02 при смещении SAME16 в EVO-05 0,01–0,06 — ожидаю прохождение с вероятностью 0,85.

## 5. Первичные гипотезы (SAME16 против SPLIT8+8, 120 пар; две гипотезы при α/2 = 0,025 каждая)
Победа — строго меньшая мера в паре; ничьи не считаются, порог пересчитывается по фактическому n без ничьих (точный двусторонний биномиальный, полный перебор `scipy.stats.binom`; `power.py` → `pilot/power.log`). Поправка: обе гипотезы при двустороннем 0,025 — **Бонферрони на две, что равно первому шагу Холма на двух** (второй шаг, α для оставшейся, не делается; консервативнее). Ложный уровень **на тест** 2·P(≥k | n, ½), **на серию из двух** — сумма (FWER ≤ 0,05):

| n без ничьих | порог k (α/2 = 0,025 двусторонне) | P(≥k | ½) | ложный уровень на тест | на серию из двух | мощность при доле побед 0,60 / 0,65 / 0,70 / 0,75 |
|---|---|---|---|---|---|
| 120 (без ничьих) | **73/120** | 0,0110 | 0,022 | 0,044 | 0,47 / 0,85 / 0,99 / 1,00 |
| 90 (ожидаемое n_eff) | **57/90** | 0,0074 | 0,015 | 0,030 | 0,30 / 0,67 / 0,93 / 1,00 |
| 60 (справка: 10 сидов) | 40/60 | 0,0067 | 0,013 | 0,027 | 0,18 / 0,45 / 0,76 / 0,95 |

Сверено scipy: 73 — наименьшее k, при котором 2·P(X ≥ k | 120, ½) ≤ 0,025 (у 72 — 0,035); 57 — то же при n = 90.

**Полоса «разницы нет» (третий исход).** δ = полуширина бутстреп-ИД95 медианы парной разности A/A (AA32 против SAME32) той же меры в этом же прогоне (все 120 пар). Она вычисляется до первичных, из данных, не подбирается. A/A шире парного шума (AA32 — другая популяция, §2), поэтому исход «разницы нет» консервативен.
- **H2.** ИОИ′ в окне у SPLIT8+8 меньше, чем у SAME16. Исходы: «подтверждено» — побед SPLIT8+8 ≥ k; «обратный эффект» — побед SAME16 ≥ k; «разницы нет» — ИД95 медианы парной разности ИОИ′ целиком внутри ±δ(ИОИ′); иначе «не решено» (мощности не хватило, вывода о цене разделения нет).
- **H3 (условие Скептика).** Правда у SPLIT8+8 не хуже. Считается по незнанию 1 − T, победы SAME16. Исходы: «SPLIT хуже по незнанию» — побед SAME16 ≥ k; «SPLIT лучше (не хуже)» — побед SPLIT8+8 ≥ k; «SPLIT не хуже» — верхняя граница ИД95 медианы парной разности (незнание SPLIT8+8 − незнание SAME16) ≤ δ(незнание); иначе «не решено». Неотклонение само по себе «не хуже» не считается.
- Мои вероятности нулевого результата (условие Скептика: не выше 0,8): H2 «не подтверждено» — 0,5 (довод Левого: шум заявки по 8 входам ≈ 0,18 задавит эффект; в пилоте на T3 разделение убирает завышение 0,145 → −0,003, а |C − T| падает лишь с 0,151 до 0,110 — остаток шум 8 входов; на T4 ИОИ′ у SPLIT8+8 ниже, 0,411 против 0,600, за счёт T); из них «разницы нет» — 0,15, «не решено» — 0,35. H3 «SPLIT хуже» — 0,3 (отбор по 8 вместо 16 стоит T); «не решено» — 0,3. H1 — проверка теоремы, без порога; вероятность нуля (побед SPLIT8+8 меньше ⅔ пар без ничьих) — 0,1, как у совета.

## 6. Критерий «вдвое» (DECISIONS 27.09, критерий 3; оценка критерия, не проверка гипотезы)
База — BASE EVO-05 (SAME16, сиды 60–79, T2–T5): медиана |C − T| в окне 121–150 = 0,088, цель ≤ 0,044; незнание не хуже. В этом прогоне база пересчитывается на SAME16 (сиды 80–99), цель = min(0,044; ½ медианы SAME16 здесь). Пары T2–T5, 80 пар с SAME16. Кандидаты — ровно те, что считает код (`criterion_half`): по одиночной заявке `abs_ct_late` — **SPLIT16+16, SPLIT8+8, SAME32**; по накопленной заявке `abs_pool_late` (разведочно, §3) — SPLIT16+16, SPLIT8+8, SAME32 и **SAME16 (база сама, пуллинг без новых меток) — только описательно, вердикта не получает**. Буквально формулировке DECISIONS «на свежих тестах» отвечают SPLIT (заявка по отдельной свежей выборке); у SAME32 заявка — по свежей на поколение выборке отбора; у пуллинга — среднее прошлых заявок; это оговаривается в отчёте.
- Исход по бутстреп-ИД95 (4000, сид 0) медианы |C − T| кандидата по 80 парам: **«выполнен»** — верхняя граница ≤ цели и незнание не хуже; **«не выполнен»** — нижняя граница > цели, либо незнание хуже базы; иначе **«не решено»**. Незнание «не хуже»: побед SAME16 по 1 − T меньше порога (при n = 80 порог 50, α = 0,05 двусторонне; мощность 0,37 / 0,72 / 0,94 / 1,00 при доле побед 0,60–0,75); **для SPLIT16+16 незнание совпадает с SAME16 тождественно (§2), условие выполнено по построению, сравнение идёт только по заявке**; при n без ничьих, для которого порога нет, — «не решено».
- Отчитывается также число пар, где **попарно** |C − T| кандидата ≤ ½ |C − T| SAME16 в той же паре (без порога, описательно).
- Ожидание (записываю честно): по одиночной заявке критерий не выполнится — |C − T| базы почти целиком шум 16 входов (пост-хок EVO-05), разделение убирает только смещение; вероятность «не выполнен» 0,8 для SPLIT16+16 и SPLIT8+8, 0,7 для SAME32. По накопленной заявке — 0,5.
- Задача T2: шаг заявки 1/16 больше половины базы (0,014); ожидаются ничьи, считать по среднему за окно, как записано.

## 7. Вторичные (семья с поправкой Холма по двусторонним p знакового теста, α = 0,05; вердикты — как в §5, δ по A/A той же меры на тех же задачах)
1. **SAME32 против SPLIT16+16** (бюджет 32 labels; позиция Левого): SPLIT16+16 меньше по ИОИ′, |C − T|, старому ИОИ и самообману max(0, C − T); незнание — побед SAME32. Ожидание: |C − T| и самообман меньше у SPLIT (вероятность нуля 0,4); ИОИ′ — 0,5; незнание — «не решено» 0,5 (H3 здесь тождественно «SAME16 не хуже SAME32» по незнанию, §2).
2. Первичная пара по остальным мерам: SPLIT8+8 меньше SAME16 по |C − T|, старому ИОИ, самообману (самообман — 0,2; остальное 0,5).
3. Разбивка H2 (ИОИ′, SPLIT8+8 против SAME16) на гладкие (T1, T6) и кусочные (T2–T5) задачи; на гладких n_eff мал из-за ничьих (§3).
4. Гудхарт: SAME32 против FIXED32 по |C − T| и ИОИ′ (регрессия к EVO-01: FIXED хуже; вероятность нуля 0,3).
5. ## 11. Как читать исход
- Ворота не пройдены из-за SPLIT → ошибка кода, отчёт только об этом. Не пройдены из-за SAME16 (проклятия не видно) → H2 неинформативна, отчёт описательный, критерий §6 всё равно оценивается.
- H2 «подтверждено» и H3 «не хуже» → разделение отбора и заявки даёт честную заявку без цены при бюджете 16; критерий «вдвое» проверяется отдельно (§6).
- H2 «разницы нет» (ИД95 внутри ±δ) → при равных labels разделение не окупается: смещение убрано, шум остался (ожидаемый исход). H2 «не решено» → мощности не хватило, вывода о цене разделения нет; так и записать.
- H3 «SPLIT хуже» → цена разделения — правда; тогда честность заявки куплена незнанием, ИОИ′ показывает, что перевешивает.
- Критерий «вдвое» не выполнен ни одним кандидатом → следующий шаг критерия 3 — не разделение, а сглаживание/накопление заявки без новых меток (пуллинг) или бюджет заявки; записать в DECISIONS. «Не решено» → повтор с бо́льшим n или другой мерой, критерий не засчитан.
