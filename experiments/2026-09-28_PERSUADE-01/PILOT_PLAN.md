## 3. Что меряет каждый пункт

1. **ICC приспособленности.** Приспособленность — средняя p BLIND по K = 6 задачам. ICC(1) одностороннего случайного эффекта: 8 промптов × 2 набора, 95 % ИД по F. ρ между наборами только описательно. Для ORACLE описательно считается ICC по T.
2. **S = p(исходный итог) − p(подменённый итог)** при том же тексте, у P0. Считается на задачах, где исходный итог верен по коду. Подмену строит код без правды: итог автора ± 2–8 %. У COL3 сдвиг ±6 или ±12, чтобы сохранить кратность 6. У MODSQ сдвиг берётся по модулю p. Последняя строка шага, если она равна итогу, меняется вместе с итогом, так что текст остаётся согласованным. Случай, когда подмена случайно попала в правду, анализ отмечает и исключает.
3. **Шаблон.** Для каждого семейства код строит неизменный текст метода и итог автора (`TEMPLATES`). Семейство без шаблона исключается. Δ = p(авторское) − p(шаблонное) при том же итоге. Считается для P0, Pr и любого промпта, чей итог совпал с кэшированным.
4. **Утечка.** Проверяется, нет ли чисел правды (≥ 3 цифр, целым токеном) в скрипте, то есть во всех входах авторов и судей до ответов, во входе мутатора и во входе перефраза. Проверяется, нет ли в скрипте пути к секрету. Вход мутатора в JS должен побайтно совпадать с `mutator_input()` и с FNV-хэшем.
5. **Разбор.** Доли статусов: ровно один `final=` с целым числом, несколько `final=`, нет `final=`, мусор, нет ответа. Несколько `final=` и уклонение засчитываются как неверный ответ.
6. **По семействам.** T, C, C − T, FAR (p > 0,5 при неверном по коду), ИОИ, гистограмма p. Структура: доля ответов с шагами, доля верных шагов (по коду), доля свободного текста, объявленная проверка при неверных шагах.
7. **Подмена против удаления.** Правило задано до пилота и от эффекта не зависит. Сначала сравнивается доля ответов P0, к которым вариант применим (итог извлечён; для удаления нужен ещё и свободный текст). При равенстве выигрывает вариант с меньшей средней |p1 − p2| при повторном вызове.
8. **Классификатор против ручной разметки.** Анализ пишет `pilot/manual_label_sheet.json` (30 ответов, рядом выход классификатора, метки пустые). Когда появляется `pilot/manual_labels.json`, считается согласие.
9. **Мутатор против перефраза.** Сравнение описательное (см. выше).
10. **SD спаренных по задачам разностей.** По всем C(8, 2) парам промптов поколения 0 (это ожидание по случайным парам) берётся корень из средней дисперсии. Считается для C − T (слепые семейства: основа N_min; все семейства описательно) и для Δ. Результат умножается на 1,25 (Левое (б)). N_min — наименьшее n, при котором односторонний спаренный t-тест при α = 0,05 и δ = 0,10 (Левое (а)) даёт мощность ≥ 0,8 (точно, через нецентральное t).
11. **Секунды на вызов** = `--wall` × `--par` / число вызовов. Workflow часов не видит, поэтому время прогона передаётся снаружи.

## 4. Правила решения (фиксируются в PREREG до пилота)

- **ICC** (единственный критерий пилота):
  - < 0,09 — не идём;
  - от 0,09 до 0,2 — K = 10, 2 поколения;
  - > 0,2 — K = 6, 3 поколения.
- **S** ≤ 0,1 — не идём.
- **Утечка** правды в любой вход головы — не идём.
- **Бюджет:** Итог = P + E(K, G) + 31·N ≤ 2500. Здесь P — фактические вызовы пилота. E(K, G) = 24K + 2G(16K + 4) + G(8K + 4) + 4G по таблице инженера; проверка: E(6, 3) = 912, E(10, 2) = 1072. N = ⌊(2500 − P − E)/31⌋, из них 8 контрольных.
- **N_min.** Если N − 8 < N_min, сначала снимаются поколения (не ниже 2), потом не идём. N не опускается ниже N_min.
- **12 ч.** Прогноз = (E + 31·N) × сек/вызов / параллельность. Если он больше 12 ч, N сокращается, но не ниже N_min + 8 и не ниже 8 контрольных; K и решётка не трогаются. Если и так не помещается — не идём.

| Исход ICC | K | G | E | N при P = 250 | Итог |
|---|---|---|---|---|---|
| > 0,2 | 6 | 3 | 912 | 43 (35 + 8) | 2495 |
| 0,09…0,2 | 10 | 2 | 1072 | 38 (30 + 8) | 2500 |
| < 0,09 | — | — | — | — | не идём |
