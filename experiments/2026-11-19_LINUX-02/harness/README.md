# LINUX-02 — обвязка (ступень А)

План — `../PLAN-PILOT.md`, уточнения до оценки пилота — `../DEVIATIONS.md`. Здесь устройство и числа, которые план отсылает сюда.

## Сборка
- Семантика C, которая считается правдой, — как у ядра (Makefile v7.4-rc3): `-std=gnu11 -O2 -funsigned-char -fno-common -fno-strict-aliasing -fno-delete-null-pointer-checks -fno-strict-overflow`.
- Дополнительно — `-Werror=implicit-function-declaration -Werror=int-conversion`. Так непереведённый макрос или функция ядра не проходит молча (так нашлись пропуски поручений, ERRORS № 216).
- Заголовки ядра — заглушки в `include/` и общий `kernel_shim.h`: типы, макросы, атомарные операции на `__atomic`, errno, ctype ядра (Latin-1).
- Конфигурация: `CONFIG_64BIT`, `CONFIG_X86_64`, `CONFIG_HAVE_EFFICIENT_UNALIGNED_ACCESS`, `CONFIG_KUNIT`.
- Функции ядра вне модулей — `kernel_helpers.c`:
  - kstrtox — из LINUX-01;
  - `hex_to_bin` — дословно из lib/hexdump.c;
  - `crc32_be` — алгоритм gen_crc32table;
  - `get_options` — сам `lib/cmdline.c` (хеш сверен с тегом, `../src_hashes.json`);
  - kmalloc и родственные — с журналом вызовов (`kalloc_log.h`). Больше 4 МиБ (KMALLOC_MAX_SIZE x86_64) — NULL, как в ядре;
  - `get_random_bytes` — детерминированный xorshift64\*, общий поток для оригинала и перевода (`harness_random_reset`).
- Rust: `rustc --edition 2021 --crate-type staticlib -C opt-level=2 -C overflow-checks=on -C panic=abort` (как в LINUX-01).
- Оригинал для сравнения переименовывается: `objcopy --redefine-sym s=orig_s` для каждого определённого глобального символа (`nm -g --defined-only`).
- **UBSan** в проверке обвязки — `-fsanitize=undefined -fno-sanitize=alignment -fno-sanitize-recover=all`. Почему без выравнивания — DEVIATIONS, п. 5.

## Исполнитель KUnit (`kunit_runner.c`)
- Каждый случай и каждый параметр — в отдельном процессе. Предел — 120 с на случай.
- ASSERT прекращает случай, skip — случай пропущен.
- Случай без единого утверждения — «пустой», пройденным не считается.
- «KUnit пройден» (`run.py`): провалов 0, пустых 0, случаев больше 0. Пропущенные (бенчмарк md5) не считаются ни провалом, ни пройденным.
- kthread — на pthreads (гонка в errseq). `kunit_run_irq_test` — задача и два потока.

## Сравнение с оригиналом (`diff_<модуль>.c`, общая часть `diff_common.h`)
- Генератор — xorshift64\*. Проверки идут порциями по 500, каждая порция — в своём процессе.
- Падение перевода (паника Rust → abort, сигнал, зависание дольше 600 с) засчитывает всю порцию как расхождения. Это верхняя граница.
- `--boundary` — генератор крайних значений: 0, 1, степени двойки и соседи, наибольшие значения; длины 0, 1, max−1, max, кратные блоку ± 1.

| Модуль | Что сравнивается после каждого вызова | Входы |
|---|---|---|
| errseq | возврат, `errseq_t`, три курсора | до 40 операций set / sample / check / check_and_advance; начальное значение любое, в том числе у верхней границы счётчика |
| 842_decompress | код возврата, `*olen`, весь выходной буфер с запасом, журнал `crc32_be` | данные 0…4096 байт, сжатые оригинальным `sw842_compress`; без порчи, с перевёрнутыми битами, обрезкой, хвостом, случайные байты; ёмкость выхода точная, меньше, больше, 0 |
| md5 | state, bytecount и буфер после каждого update; весь контекст и дайджест после final; подготовленный ключ HMAC | сообщения до 1000 байт, случайное деление на части; ключи 0…200 байт |
| random32 | возврат, буфер, состояние | до 20 вызовов, любое состояние (в том числе вырожденное), буфер с любым смещением |
| min_heap | результат, nr, size, смещение data, весь массив | элементы 1…32 байт, смещение 0…4, ёмкость 0…40, свой обмен или NULL; до 40 операций |
| string_helpers | возврат, выходные буферы с запасом, журнал kmalloc / kfree / devres; указатели — как смещения | все 19 экспортируемых функций, 8 проверок; флаги — любые подмножества масок |

Входы, на которых оригинал ведёт себя неопределённо, генератор не даёт (план). Это:
- позиция `del` у min_heap — только внутри кучи (`idx < nr`): за её пределами оригинал выходит за массив;
- диапазоны `parse_int_array` — только при |предыдущее| < 100 000, иначе оригинал выделяет гигабайты (было OOM в проверке, `dmesg`).

## Режимы
- `python3 harness/run.py check OUT.json` — оригиналы: KUnit, оригинал против себя (обычные и крайние); то же под UBSan.
- `python3 harness/run.py eval OUT.json pilot` — переводы `translations/pilot/<голова>/<модуль>_r<k>.rs`.
- `python3 harness/run.py one OUT.json МОДУЛЬ ФАЙЛ.rs` — один файл.
- `python3 harness/mutants.py OUT.json МОДУЛЬ` — мутанты модуля, правила 3 и 5 (DEVIATIONS, пп. 2–4).
- `python3 harness/sealing_facts.py ПАПКА[,ПАПКА] pilot OUT.json` — факты запечатывания.

## Сухой прогон на заглушках (19.11, в сессии)
- `stubs/errseq_stub_ok.rs` — мой перевод errseq по коду оригинала. Результат: «верен» — KUnit пройден, 0 расхождений из 20 000.
- `stubs/errseq_stub_bad.rs` — та же заглушка с намеренной ошибкой: `new += ERRSEQ_CTR_INC` вместо `wrapping_add`, при переполнении паника. Результат: KUnit пройден, расхождений 20 000 из 20 000 (все порции упали). Это тот самый случай «прошёл KUnit, но неверен».
- Мутанты на этих заглушках: errseq — чистая основа одна из двух, 10 мутантов; min_heap — запасная основа, оригинал C. Там и нашлось, что KUnit min_heap не вызывает модуль (ERRORS № 217).

## Известные пределы правды
- Сравнение однопоточное. Поведение при гонках (ветви cmpxchg в errseq, когда значение поменял другой поток) оно не видит. Пример: мутант заглушки `cur == new → cur != new` в errseq эквивалентен без гонок.
- Сравнение видит только то, что даёт генератор. Независимый поиск (другое зерно, в 10 раз больше входов, крайние значения) — проверка этого предела, а не доказательство полноты.
