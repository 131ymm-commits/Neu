# LINUX-02 — обвязка (ступень А)

План — `../PLAN-PILOT.md`, уточнения до оценки пилота — `../DEVIATIONS.md` (пп. 1–10). Здесь устройство и числа, которые план отсылает сюда. Устройство пересмотрено 19.11 после независимого разбора кода, до оценки пилота (ERRORS № 219, № 220).

## Сборка
- Семантика C, которая считается правдой, — как у ядра (Makefile v7.4-rc3): `-std=gnu11 -O2 -funsigned-char -fno-common -fno-strict-aliasing -fno-delete-null-pointer-checks -fno-strict-overflow`.
  - Плюс `-U_FORTIFY_SOURCE`: gcc Ubuntu сам ставит `_FORTIFY_SOURCE=3`, а в ядре `CONFIG_FORTIFY_SOURCE` не задан.
  - `-fno-strict-overflow` в gcc ≥ 8 — это `-fwrapv`: знаковое переполнение заворачивается, и `-INT_MIN` = `INT_MIN`. Поручения версии test это говорят.
- Дополнительно — `-Werror=implicit-function-declaration -Werror=int-conversion`. Так непереведённый макрос или функция ядра не проходит молча (ERRORS № 216).
- Заголовки ядра — заглушки в `include/` и общий `kernel_shim.h`: типы, макросы, атомарные операции на `__atomic`, errno, ctype ядра (Latin-1).
- Конфигурация: `CONFIG_64BIT`, `CONFIG_X86_64`, `CONFIG_HAVE_EFFICIENT_UNALIGNED_ACCESS`, `CONFIG_KUNIT`.
- Функции ядра вне модулей — `kernel_helpers.c`:
  - kstrtox — из LINUX-01;
  - `hex_to_bin` — дословно из lib/hexdump.c;
  - `crc32_be` — алгоритм gen_crc32table;
  - `get_options` — сам `lib/cmdline.c` (хеш сверен с тегом);
  - kmalloc и родственные — с журналом вызовов (`kalloc_log.h`). Больше 4 МиБ — NULL, как в ядре. Отказ по заказу драйвера — `harness_kmalloc_fail_at`, k-й вызов выделения у обеих сторон;
  - `get_cmdline` и `file_path` отдают то, что задал драйвер: байты с NUL и любой длины; путь или ошибку;
  - `__devres_alloc_node` и `devres_add` запоминают release и ресурс — драйвер зовёт release сам;
  - `get_random_bytes` — детерминированный xorshift64\*, общий поток для обеих сторон; по заказу — малые 32-битные слова (`harness_random_small`);
  - `num_online_cpus` — по маске сродства процесса.
- Rust: `rustc 1.97.0 --edition 2021 --crate-type staticlib -C opt-level=2 -C overflow-checks=on -C panic=abort`. На GitHub Actions версия закреплена (`rustup default 1.97.0`).
- Оригинал для сравнения переименовывается: `objcopy --redefine-sym s=orig_s` для каждого определённого глобального символа.
- **UBSan** в проверке обвязки — `-fsanitize=undefined -fno-sanitize=alignment -fno-sanitize-recover=all`. Почему без выравнивания — DEVIATIONS, п. 5.

## Исполнитель KUnit (`kunit_runner.c`)
- Каждый случай и каждый параметр — в отдельном процессе. Предел — 120 с на случай.
- ASSERT прекращает случай, skip — случай пропущен.
- Случай без единого утверждения — «пустой», пройденным не считается.
- «KUnit пройден»: провалов 0, пустых 0, случаев больше 0. Пропущенные (бенчмарк md5) не считаются ни провалом, ни пройденным.
- kthread — на pthreads (гонка в errseq). `kunit_run_irq_test` — задача и два потока (DEVIATIONS, п. 7).
- KUnit min_heap не вызывает функции модуля (ERRORS № 217) — условие отбора 5.

## Вердикт «верен» (`run.py: verdict_runs`, тот же у мутантов)
Перевод «верен», если выполнено всё:
- собрался и слинковался;
- KUnit пройден;
- 0 расхождений в основном сравнении — n обычных проверок на функцию драйвера, зерно драйвера по умолчанию (0xC0FFEE00);
- 0 расхождений на крайних значениях — n проверок с `--boundary`, зерно 777 (DEVIATIONS, п. 10а).

Пределы времени — от времени оригинала на том же раннере: KUnit — max(30 с, 10×), сравнение — max(60 с, 10×). При пределе убивается вся группа процессов.

## Сравнение с оригиналом (`diff_<модуль>.c`, общая часть `diff_common.h`)
- Генератор — xorshift64\*. Проверки идут порциями по 500, каждая порция — в своём процессе.
- Падение перевода (паника Rust → abort, сигнал, зависание дольше 600 с) засчитывает всю порцию как расхождения. Это верхняя граница: прибавляется размер порции, а настоящих расхождений в ней не больше.
- `--boundary` — генератор крайних значений: 0, 1, степени двойки и соседи, наибольшие значения; длины 0, 1, max−1, max, кратные блоку ± 1.
- **Охранные страницы** (`gbuf`). Каждый вход у каждой стороны — своя копия вплотную к недоступной странице. Чтение за концом входа роняет порцию, как oops в ядре на границе страницы. Вход, который функция не должна менять, сверяется после вызова.
  - Выходные буферы — с запасом и заливкой: запись за ёмкость видна, чтение за ёмкость — нет.
- Пример расхождения в JSON: верный UTF-8 идёт как есть, сырые байты — как `\u00XX`.

| Модуль | Что сравнивается после каждого вызова | Входы |
|---|---|---|
| errseq | возврат, `errseq_t`, три курсора | до 40 операций set / sample / check / check_and_advance; начальное значение любое, в том числе у верхней границы счётчика; в крайних — err = INT_MIN и др. |
| 842_decompress | код возврата, `*olen`, весь выходной буфер с запасом, журнал `crc32_be`; вход не изменён | данные 0…4096 байт, сжатые оригинальным `sw842_compress`; без порчи, с перевёрнутыми битами, обрезкой, хвостом, случайные байты; ёмкость выхода точная, меньше, больше, 0 |
| md5 | state, bytecount и буфер после каждого update; весь контекст и дайджест после final; подготовленный ключ HMAC | сообщения до 1000 байт, случайное деление на части; в крайних — длины 55, 56, 57, 63, 64, 65 … по модулю 64; ключи 0…200 байт |
| random32 | возврат, буфер, состояние, журнал get_random_bytes | до 20 вызовов, любое состояние (в том числе вырожденное), буфер с любым смещением; в половине засевов — малые слова в потоке |
| min_heap | результат, nr, size, где лежат данные (свой массив или запасной), весь массив и запасная область; журнал обратных вызовов less и swp — вид и адреса аргументов как смещения от начала данных | элементы 1…32 байт, смещение 0…4, ёмкость 0…40, `data == NULL` в четверти случаев; swp — NULL, свой, SWAP_WORDS_32 (размер кратен 4), SWAP_BYTES; до 40 операций, в том числе pop_push и sift_up над пустой кучей и sift_down за концом кучи |
| string_helpers | возврат, выходные буферы с запасом, журнал kmalloc / kfree / devres; указатели — как смещения; release ресурса devres | все 19 экспортируемых функций, 8 проверок; флаги — любые подмножества масок; cmdline пустой, с NUL внутри и в хвосте, у границы 4095 и длиннее; путь у границы PATH_MAX + 11 и ошибки file_path; отказ kmalloc по заказу; `kfree_strarray(NULL)` и массивы с NULL |

Входы, на которых оригинал ведёт себя неопределённо, генератор не даёт (план):
- позиция `del` у min_heap — только внутри кучи;
- диапазоны `parse_int_array` — только при |предыдущее| < 100 000, иначе оригинал выделяет гигабайты.

## Режимы
- `python3 harness/run.py check OUT.json` — оригиналы: KUnit, оригинал против себя на всех потоках правды, в обычной сборке и под UBSan.
- `python3 harness/run.py eval OUT.json pilot2` — переводы `translations/<фаза>/<голова>/<модуль>_r<k>.rs`. Пишет `done`, а у модуля — `complete`.
- `python3 harness/run.py one OUT.json МОДУЛЬ ФАЙЛ.rs [--no-kunit] [--seed S] [--boundary]` — один файл: вердикт; плюс свой прогон для разбора.
- `python3 harness/mutants.py OUT.json МОДУЛЬ --phase pilot2` — мутанты модуля, правила 3 и 5.
- `python3 harness/select_modules.py CHECK.json MUT_DIR OUT.json --eval pilot2=E.json --default-phase pilot2` — отбор. Неполная оценка — отбора нет.
- `python3 harness/sealing_facts.py ПАПКА[,ПАПКА] pilot2 OUT.json` — факты запечатывания.
- `python3 harness/prompt_coverage.py [OUT.json] [--dir prompts/test]` — полнота поручений.

## Пределы правды (что она не видит и сейчас)
- Сравнение однопоточное, поведение при гонках не видно. Пример: ветка «cmpxchg не удался» в errseq (DEVIATIONS, п. 10е).
- Независимый поиск идёт тем же генератором, что и вердикт: другое зерно, в 10 раз больше входов, крайние. Структурные слепые зоны у них общие. Поэтому первая часть правила 3 («сравнение убивает ≥ 0,95 меняющих поведение») слабая — она во многом выполняется по построению. Решает вторая часть: «KUnit поймал, сравнение пропустило».
- Чтение за ёмкость выходного буфера не видно (видна только запись).
- Содержимое ресурса devres сравнивается только через его release: внутреннее устройство ресурса — дело модуля.
