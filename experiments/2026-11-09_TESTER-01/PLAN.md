**Продукт.** Плагин Claude Code «тестировщик поделок ИИ». В нём навык (как тестировать игру), среда — API игры без снимков экрана — и команда запуска.

**Вопрос опыта.** Это главный вопрос Neu: оценщик, которого не обмануть, и оценка у самой оценки. Сколько внесённых багов находит тестировщик и насколько верны его заявки о найденном, в зависимости от того, что он видит:
- экран;
- API состояния;
- API и исходный код.

**Игры.** Reifenwerk и Bäckerei — `131ymm-commits/agent-games`, коммит dccf348, лицензия MIT. Две стартап-симуляции в духе RimWorld, одной файл-страницей каждая. Принципиально похожи; это моё прочтение слов автора.

## Шаги (ворота CLAUDE.md)
0. **Импорт игр** в `games/` с провенансом: репозиторий, коммит, sha256.
1. **Поиск (ворота 2).** Агент-исследователь; строка «кто раньше» в `docs/PRIORITY.md`. Темы:
   - текст и API против снимков у игровых агентов;
   - оценка тестировщиков внесёнными багами (мутационное тестирование);
   - оракулы без спецификации (повтор, разностное и метаморфное тестирование);
   - «белый ящик» против «чёрного» у ИИ-тестировщиков.
2. **Среда без снимков** (`harness/`, Playwright и Chromium — уже стоят).
   - В страницу встраивается зонд. Зерно случайности, виртуальное время (`advance`), ошибки консоли, текст интерфейса со списком кнопок и состояние игры из её объектов (адаптер по коду игры).
   - Запись следа действий и его повтор. Детерминизм — «одно зерно и один след дают одно состояние» — проверяет код.
3. **Банк багов** — правда по построению.
   - На каждую игру — N мутантов, по одному багу шести типов: падение, мёртвое положение, число или правило, интерфейс, сохранение, экономика. Плюс чистые копии.
   - Мутанты и список багов лежат вне git до правды, как соли. В PREREG — только sha256.
   - Каждый баг до регистрации подтверждается эталонным следом: правда вторым способом.
4. **Руки** — «различными агентами».
   - S — только снимки и клики по координатам (как продукты «чёрного ящика»);
   - A — API без кода;
   - W — API и исходник;
   - возможно, C — только код, без игры.

   Головы работают в чистом контексте вне git, без доступа к банку багов.
5. **Мера — код.**
   - Отчёт засчитан, если повтор его следа на мутанте задевает место мутации и даёт расхождение с чистой копией.
   - Ложный — отчёт, который повтор не воспроизводит.
   - Заявленная уверенность тестировщика против воспроизводимости — его самообман.
6. **Пилот (ворота 1)** — на отдельных мутантах, не входящих в тест. Проверяется, работает ли среда, сколько стоит сессия, нет ли потолка или пола.
7. **Три линзы** (совет), PREREG, коммит и пуш до первого вызова теста.
8. **Тест — на выходных, на остатках лимита** (слово автора 09.11). Бюджет утверждает автор вместе с PREREG.
9. Отчёт, совет, реестр, калибровка.
10. **Плагин.** `SKILL.md`, MCP-сервер среды и команда `/test-game`. Потом — игры с GitHub.

**Оценка цены** — до пилота, не замер:
- подготовка (шаги 0–3) — почти без вызовов голов;
- пилот — около 0,2 млн токенов выхода;
- тест — 1–2 млн, уточнится по пилоту.
