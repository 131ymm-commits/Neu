## 4. Анализ (`analyze_precond.py`)
**Регрет голоса** — нормированный, как в SELECT-01.
- Отказ (choice = −1) → регрет выбора по заявке A0, на всех этапах: medium, high и проверка.
- Сбой, пропуск и недопустимый номер → 1; пропуски и сбои по рукам выводятся отдельно (`vote_status_*`).
- Задача исключается, если лучший − средний ≤ EPS (150), как в THINK-01.
- После правды повторы запрещены.

**Число задач (Т1).** n — задачи с пулом и разбросом > EPS; df = n − 1, во всех t-ДИ и в §4.6.
- Задачи без пула публикуются до правды, исключённые по EPS — в отчёте, по правилу.
- Если выпало больше 20 % задач этапа (на открытии меньше 8 из 9, на проверке меньше 40 из 50), этап «не определён». Порог — соглашение, пилотом он не обоснован.

**4.1. Вопрос 1 (первичный, один тест).** Статистика — сумма квадратов средних 64 клеток по центрированным внутри задачи регретам. Метки клеток переставляются внутри задачи (точный нуль «ничто не действует»), B = 20 000, зерно 27102026. «Разница есть» — p < 0,05.

**4.2. Вопрос 2 (первичное семейство, Холм по восьми, α = 0,05).**
- Действие ингредиента — «включён − выключен» на центрированных регретах (= 2β, столбцы ортогональны внутри задачи).
- p — Freedman–Lane внутри задач: переставляются остатки модели без этого ингредиента, двусторонний тест.
- ДИ — t по контрастам задач, df = n − 1. Бутстреп — только описание.
- Потоки случайных чисел — `SeedSequence(27102026).spawn(10)`: поток 0 — вопрос 1, 1–8 — Freedman–Lane по ингредиентам в порядке `prompts_precond.F`, 9 — §4.3 (К4).
- Действие CONF — это ингредиент плюс схема ответа с p_best (Т8).

**4.3. REFUSE × CLAIMS (один тест, α = 0,05).** Взаимодействие — 2β столбца x_REFUSE·x_CLAIMS. Freedman–Lane с восемью главными действиями в сокращённой модели. Остальные 27 пар — описательно.

**4.4. Потолок (первичный критерий, голос «против» совета 37).**
- D = регрет «всё выключено» − регрет «всё включено» на своём уровне: D_m = M0 − C63 на medium, D_h = H0 − H1 на high; d = D_h − 0,5·D_m по задачам.
- «Гипотеза потолка опровергнута», если среднее d ≥ 0, рядом t-ДИ с df = n − 1.
- Это описательное решение по точечной оценке, высокий шум (Т3). Коэффициент 0,5 — соглашение.
- Если среднее D_m ≤ 0, то §4.4 и E7 «не определены» (Т2).
- Дополнительный критерий: средний регрет H1 ≥ 0,1. Это та же величина, что в E7.

**4.5. Победители — только на открытии, правило фиксировано:**
- **OBS** — клетка с наименьшим средним регретом на 9 задачах; при равенстве — меньший номер C;
- **MODEL** — включить ингредиент, если его действие из §4.2 < 0;
- **ANCHOR** — C44.

Если наборы совпали, рука одна, а псевдоним записан в `winners.json`. Скрипт выбора — `analyze_precond.py open`. Его хеш — в регистрационном коммите. Победители коммитятся и пушатся до заданий этапа проверки.

**4.6. Проверка победителя (первичный тест, α = 0,05).**
- Мера руки на задаче — средний регрет 5 голосов.
- Разность «OBS − MODEL» по задачам, парный t, df = n − 1, односторонний. **OBS − MODEL > 0 ⇔ MODEL лучше** (Т5). «Модель лучше», если p < 0,05.
- Если OBS и MODEL совпали — «не проверено: победители совпали».

**4.7. Описательно:**
- сжатие = 1 − выигрыш на проверке / выигрыш на открытии; выигрыш — над ANCHOR, по неокруглённым значениям (К2). При выигрыше на открытии ≤ 0 — «не определено». Если MODEL вне плана, его выигрыш открытия — по прогнозу модели главных действий, и сжатие MODEL только описательно (Т6);
- опорная рука A0 без вызовов — её регрет на открытии и проверке; разложение действия отказа: доля отказов × (регрет A0 − регрет ответивших) в клетках с REFUSE; флаг «вырожден в A0», если победитель отказывается в ≥ 50 % голосов. Это аварийное соглашение, а не тест (Т7);
- перестановочный нуль инфляции отбора: выигрыш лучшего из 64 над ANCHOR при перемешанных метках внутри задач;
- ln(выход) как посредник (совет 35), не ковариата первичной проверки;
- насыщение: регрет ~ k + k² внутри задач. Коэффициент при k² > 0 означает убывающую пользу, только если линейный член отрицателен (Т8). Тогда выводы §4.2 получают пометку «возможно смещены насыщением»;
- выход и доля отказов по ингредиентам;
- самооценка в клетках с CONF: средняя p_best против доли ровно лучших;
- 27 пар.

**Ложный уровень серии (Т4).**
- Семейство §4.2 — Холм на 0,05.
- Решения §4.1, §4.3, §4.6 и семейство §4.2 — четыре отдельных решения на одних данных, без поправки между ними. Ложный уровень серии ≤ 0,20 (Бонферрони).
- Критерий §4.4 — описательный, по точечной оценке.

## 7. Порядок работ (`run_precond.sh`)
1. Регистрация: коммит этого файла с кодом, сидами, `prereg_hashes.json`; до этого созданы обе соли, их sha256 — здесь.
2. `run_precond.sh exec` — задачи и пулы обоих этапов; коммит задач и пулов проверки до правды открытия.
3. `run_precond.sh open`. Дальше — выборы → пуш → событие → `truth open` → `analyze_precond.py open` → коммит и пуш `open_an.json` и `winners.json` → публикация соли открытия.
4. `run_precond.sh val`. Дальше — выборы → пуш → событие → `truth val` → `analyze_precond.py val` → публикация соли проверки.
5. Отчёт, совет, реестр, калибровка.
