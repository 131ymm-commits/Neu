# LEVEL-05 — искусственный новый уровень для LLM: организации из 5, 10 и 20 голов на задаче новой сложности (замысел, 28.09.2026)

**Слова человека:** «Возьми проект Neu. Создай искусственно новый уровень в агентской среде для LLM. Возьми 5, 10, 20 и создай новую сложность». Модель голов — claude-opus-5-5 (как в LEVEL-04).

## Что значит «новый уровень» здесь
По системе появления уровней Neu (архив, «Грамматика переходов», SYNTH-06) уровень — пара (оператор, описание): у целого есть свойство, которого нет у частей, и целое описывается своими макропеременными короче, чем через части; признаки — сертификаты (повторяемость ≈ 10 оборотов, зазор t1/t2, стационарность). LEVEL-04 дал ландшафт на **последовательной** задаче (цепочка x → x² + c mod p, L = 200): одиночка отказывается, звенья по 40 без проверки ошибаются, проверка соседом и дублирование поднимают до 2/3–3/3.

## Новая сложность
Задача, которую одна голова в принципе не проходит (горизонт ≈ 10 шагов арифметики по модулю без ошибки), а организация из N голов — может, и где **структура** задачи требует не только цепочки, но и сборки:
- **Семейство M(N): произведение M = 10·N матриц 2×2 по модулю простого p** (p ≈ 10⁹, матрицы из зерна; правда — код). Ассоциативность позволяет дерево: N листьев по 10 матриц (на пределе одной головы), затем сборка ⌈log₂ N⌉ ярусов. При N = 5, 10, 20 — M = 50, 100, 200 матриц; ярусов 3, 4, 5.
- Сложность растёт по двум осям сразу: объём (M) и глубина сборки (ярусы), а ошибка на любом листе или стыке портит итог — нужна проверка.
- Контроли: одиночка на всей задаче M; одиночка на одном листе (калибровка ε); цепочка вместо дерева (та же работа, глубина N вместо log N).

## Организации (генотипы, как в LEVEL-04)
Размер N ∈ {5, 10, 20}; проверка v ∈ {0, 1} (сосед пересчитывает выход листа/узла, при расхождении — третий); дублирование r ∈ {1, 2}; топология — дерево или цепочка. Отбор in silico по ландшафту, как в фазе 3 LEVEL-04.

## Что мерим и что будет «новым уровнем»
- Точность на задаче M(N) по коду; вызовы; ε на операцию.
- **Сертификат уровня (предзаявлено):** (1) организация проходит M(N), где одиночка — нет (разрыв ≥ 0,5 по точности); (2) точность организации описывается макромоделью «ε листа × структура проверки» без знания отдельных голов (предсказание из фазы калибровки попадает в ИД наблюдаемого); (3) повторяемость на новых зёрнах.
- Предсказание «масштаба»: при фиксированной ε точность дерева без проверки падает как (1 − ε)^(10N + ярусы·…), с проверкой — почти не падает; переход «уровень есть / нет» — между 10 и 20 без проверки.

## Цена (прикидка)
Лист — 1 вызов (10 умножений 2×2), узел сборки — 1 вызов; дерево без проверки ≈ 2N вызовов, с проверкой ≈ 4N, с дублированием ≈ 8N. Ландшафт 3 размера × 8 генотипов × 3 зерна ≈ 1500 вызовов; калибровка ≈ 100.

## Порядок
Литература (ворота 2) и совет → калибровка ε на листе (пилот, зёрна вне теста) → рецензия → PREREG → прогон → совет оценивает.

## Поправка по слову человека (28.09.2026): «Нет, смотри: ты создаёшь ансамбль из нескольких агентов. Возьми и создай из них новый уровень сложности»
Уровень — не задача для организации, а **сам ансамбль, ставший агентом**. Матрёшка с одним интерфейсом на каждом уровне: вход — задача, выход — {ответ, уверенность, довод}.
- **Уровень 1** — одна голова-решатель.
- **Уровень 2 (5 голов)** — 4 решателя разными методами (напрямую; другим способом; границы и порядок величины; сначала подводные камни) + 1 интегратор, который видит их ответы, уверенности и доводы и выдаёт один ответ с уверенностью.
- **Уровень 3 (10 голов)** — два агента уровня 2 + мета-интегратор (голова), видящий только их выходы (ответ, уверенность, довод) — ровно как агент уровня 2 видит решателей.
- **Уровень 4 (20 голов)** — два агента уровня 3 + мета-интегратор.
Вложенность: уровень 1 ⊂ 2 ⊂ 3 ⊂ 4 на одной задаче — все уровни измеряются в одном прогоне (23 вызова на задачу: 16 решателей + 4 + 2 + 1 интеграторов).
- **Задачи:** счётные с правдой от кода (TWIN, COL3, SUB5, PART, COLLATZ; генератор HIVE-01), критерий — в пределах 1 % от правды.
- **Что мерим на каждом уровне:** T, C, ИОИ = (1 − T) + max(0, C − T), Брайер; по семействам.
- **Что будет «новым уровнем»:** (1) у уровня k+1 есть свойство, которого нет у уровня k (точность выше, самообман ниже, честное «не знаю» — уверенность ≈ 0,5 там, где уровень k уверенно ошибался); (2) **ренормировка**: закон перехода F, предсказывающий (T, C) уровня k+1 по выходам уровня k при независимости частей; расхождение с наблюдаемым — мера корреляции голов (урок PRED-01: копии — одна голова); если F имеет неподвижную точку — рост уровней останавливается, и мы знаем, где.
- **Разведка (пилот):** 12 задач на зёрнах вне любого будущего теста, ≈ 276 вызовов; без PREREG, результат — описательный; совет оценивает после (правило автора 28.09).

## После литературы (отчёт K, до прогона)
- Коррелированные ошибки копий: мерить долю одинаковых **неверных** ответов у независимых вызовов (в матрёшке — у 16 решателей на задаче); ренормировка при независимости против наблюдаемого — прямая мера ρ (Liu, Kong, Pei 2026).
- Определение уровня записывается явно: по Neu — «описание макропеременными короче, чем через части» и свойство целого, которого нет у частей. По Rosas 2020 / Riedl 2025 точная предсказуемость из независимых частей означает агрегат без синергии; поэтому **синергия = отклонение наблюдаемого от ренормировки при независимости в лучшую сторону**, а отклонение в худшую — корреляция копий.

## Решение совета по первой редакции (заседание 13, `docs/council/2026-09-28_LEVEL-05_session13.md`): принято 3 из 4
Ветвь «организации на произведении матриц» ставится по решению совета: вложенное дерево (N = 20 из двух N = 10, те — из двух N = 5), первичный генотип «дерево, r = 2, большинство из 3 при расхождении», проверка соседом — только если d ≥ 0,9 и ложные тревоги ≤ 0,1 на калибровке; калибровка ≈ 130 вызовов на отдельных зёрнах (ε листа и сборки, d, ρ, det-проверка, одиночка на M = 50/100/200); макромодель заморожена до прогона; 10 зёрен оценки; контроли — одиночка одним вызовом и **одиночка с равным бюджетом** (одна беседа, самоперепроверка разрешена).
Матрёшка (ансамбль как агент следующего уровня, по уточнению человека) идёт отдельной ветвью LEVEL-05 — сейчас разведка.

**Твёрдые требования Скептика (голос «против», включены по правилу автора 28.09):**
1. Вложенная генерация в `tasks.py`: на зерно 200 матриц и одно p; N = 20 берёт все, N = 10 — половины, N = 5 — четверти; assert, что правда N = 20 равна произведению правд двух N = 10.
2. Зёрна оценки — из секретной соли (HMAC(salt, i)); соль вне репозитория, в PREREG — только её хеш.
3. Сбои формата публикуются отдельной строкой рядом с отказами по каждой ячейке и входят в тот же порог 0,3 для одиночки.
4. Критерий Скептика — нижняя граница разрыва против одиночки с равным бюджетом > 0,2 — печатается в сертификате рядом с основным.

## Калибровка горизонта (28.09.2026, `wf_874fbd9d-6da`, 20 вызовов, все claude-opus-5-5; `run/calib_analysis.json`)
| M матриц | n | T (все 4 числа точны) | C (уверенность) |
|---|---|---|---|
| 5 | 4 | 1,00 | 0,83 |
| 10 | 8 (4 задачи × 2 вызова) | 0,75 | 0,62 |
| 20 | 4 | 0,75 | 0,48 |
| 40 | 4 | 0,50 | 0,31 |
- Горизонт Opus 5.5 на этой задаче длиннее ожидавшегося: 50 % при M = 40. Значит, для N = 5/10/20 при листе 10 одиночка на всей задаче (M = 50/100/200) будет близко к 0,5 / ниже / около нуля — шкала сложности совета годится, но точку N = 5 может исключить правило «одиночка ≤ 0,1».
- **Корреляция ошибок копий:** на M = 10 два независимых вызова на одной задаче дали побитово одинаковые ответы во всех 4 задачах — в том числе **одинаково неверный** на C10-701. Дублирование r = 2 с точным сравнением такую ошибку не поймает (ρ ≈ 1 на этой выборке; n мало).
- Уверенность падает с M вместе с точностью — голова знает, где её горизонт.
- Следствие для матрёшки: работа должна делиться (разные куски — разные участники), а проверка — идти другим путём (другой порядок умножения, det-проверка), а не повтором.

## Код ветви организаций (28.09.2026, до PREREG; прогонов голов не было)
Файлы: `tasks.py` (вложенная генерация, соль), `org_step.js` (один сценарий, генотип — в задании), `org.py` (смета, сборка, заморозка макромодели, анализ, сухой прогон), `run/mock_org.mjs` (мок-голова), `salt_sha256.txt`.
- **Скептик 1:** `tasks.py nested` — на зерно одно p и 200 матриц; N = 20 — все, N = 10 — первая половина, N = 5 — первая четверть (вторичные поддеревья тоже анализируются); assert N20 = N10·N10, N10 = N5·N5, каждый узел = произведение детей, оба проверочных пути дают лист.
- **Скептик 2:** зёрна = HMAC-SHA256(соль, `<ns>:<i>`), ns = eval / hold / mock; соль `/root/level5_secret/salt` (0600), в репозитории только `salt_sha256.txt`. Публичный файл задач — без зерна и правды.
- **Скептик 3:** строгий разбор (только цифры, < p; ответ не чинится); сбои формата и отказы (`completed = false`) — отдельные столбцы каждой ячейки; для одиночки порог 0,3 считается по (формат + отказы).
- **Скептик 4:** сертификат печатает рядом «b − равный бюджет > 0» (совет) и «> 0,2» (Скептик); нижняя граница = min(бутстреп по зёрнам 2,5 %, Ньюкомб 95 %).
- **Проверка «другим путём» (генотип b):** вторая голова считает M10ᵀ·M9ᵀ·…·M1ᵀ = (M1…M10)ᵀ — законная обратная ассоциация (промежуточные — суффиксы, а не префиксы; промпт — просто другие 10 матриц, голова не знает о транспонировании); код переставляет элементы и сравнивает по точному равенству. Расхождение → третий путь «половины» (M1…M5), (M6…M10) двумя вызовами + сборка; большинство 2 из 3, если все разные — берётся «половины» (флаг unresolved). Сборки не проверяются. Det-проверка не выбрана: голова считает 10 определителей и цепочку из 10 умножений чисел mod p — сопоставимо по трудности с листом, при этом только обнаруживает ошибку и требует ещё одного пересчёта.
- **«Без защиты» (a)** = первичные вызовы листьев b (тот же промпт — по калибровке копии побитово одинаковы, «копия A» совета) + свои 19 сборок.
- **Равный бюджет (e):** одна беседа в workflow невозможна; приближение — цепочка K вызовов одного промпта, каждый получает только свои прошлые записи (контрольные точки P_k, заметки, последний ответ), K = фактические вызовы b на поддереве N = 10 того же зерна; голова может закончить раньше (`done`). Контекст растёт только записями, не рассуждением.
- **Макромодель** замораживается `org.py freeze` (sha256 проверяется при анализе, перезапись запрещена). Параметры берутся **только из калибровки 2** (`run/calib2.js`, 56 вызовов, новые зёрна пространства `L5cal2` — вне оценки (HMAC соли), вне прежней калибровки C*-70x и вне моков; правда — `/root/level5_secret/calib2tasks.json`): ε сборки — 20 задач A·B (элементы < p); ε листа и ε_TR — 12 задач M = 10, каждая путём P и путём TR; ρ — доля задач, где P неверен и TR после обратной перестановки дал тот же неверный ответ; ε₅ — 12 задач M = 5 (путь «половины»). Сбой формата = ошибка. Первая калибровка (20 вызовов) остаётся справочной.
- **Закреплено (решение координатора, 28.09.2026):** нижняя граница 95 % ДИ парной разности = **min(бутстреп по зёрнам 2,5 %, Ньюкомб 1998, метод 10)** — один метод для всех порогов сертификата; ячейка e (равный бюджет) — **8 зёрен** (E0–E7).
- **Смета** (`python3 org.py plan`, ε листа 0,25, пути независимы): калибровка 2 — 56; b — 852,5 (макс 1190); a — 190; c — 100; одиночки — 30; e — 337 (макс 472). Итого ожидаемо **1565,5**, 95-й перцентиль 1618, макс 2038.
