## Твёрдая позиция Скептика (голос «против») — включена по правилу 28.09
Дыра: «C — один дешёвый вызов против большинства N своих копий» предрешает ответ. Включены оба варианта:
- (а) C и D отличаются от сэмпла B **только** ролевым промптом оценщика по правилам (D — с правом отказа). Тексты заморожены по SHA-256 до пилота (`prompts.py`, ниже). Модель у всех рук одна.
- (б) первичное семейство — руки на равном бюджете: **C_N и D_N = N вызовов ролевого промпта, большинство** (у D_N — среди неотказавшихся; все отказались → A0). B_blind — N вызовов базового промпта «выбери лучший план» с той же информацией (правила + планы, без заявки). Одиночные C и D — вторичные.
- В «самообман» добавлено: менять промпты, роли или модель рук после пилота.

Первичное семейство: {C_N − B_blind, D_N − B_blind}, Холм, α = 0,05, односторонний парный перестановочный тест по задачам, статистика — **среднее** разностей нормированного регрета (без обрезки, без перехода на медиану; Левое). Δ — в тех же единицах. Рука засчитывается, только если обходит B_blind по Холму **и** её регрет ниже A0 (односторонний, α = 0,05).

## Правила, записанные до пилота
- A0 — argmax заявки; ничьи везде — по sha256(задача|рука|кандидат), не по индексу. E — случайный выбор, регрет ≡ 1.
- Недопустимый номер или сбой головы после одного перезапуска → регрет 1 (как случайный). Отказ D → выбор A0; регрет на всех задачах; доля отказов — в отчёт.
- Допуск по трудности (по типу задач): медианный регрет A0 в пилоте ∈ [0,2; 0,8]; стоп по потолку — медианный регрет A < 0,1. Не прошёл — трудность меняется только параметрами генератора (не экземплярами) и пилот повторяется на новых сидах 7201+; два провала подряд — тип снимается.
- Пилот: N = 5 для рук из N вызовов. N основного прогона — по токенам пилота: фактические токены B_blind ≥ токенов самой дорогой руки семейства.
- Вторичные: кривая «заявка − правда» у argmax заявки по k ∈ {1, 2, 4, 8}; Спирмен заявки с правдой; AUROC сомнений исполнителя; доля отказов D; A против B_zayavka; A против A0 (TOST, граница — в PREREG).
- Изоляция: головы без инструментов (проверка по транскриптам — `harness.wf_tokens` считает вызовы инструментов, `tools/audit_heads.py`).

## Три линзы (07.10) и исправления
Отчёты: линза 1 (утечка), линза 2 (код, независимые WH и SC), линза 3 (проверяемость) — сводка здесь.
- **Л1-1, блокировало:** у голов workflow были Bash/Read/MCP, правда открыта на чтение; вызовов не было (0), но изоляция не физическая (ERRORS №70). → `run_sealed.py`: каждая голова — `claude -p --tools ""` (только StructuredOutput), без настроек, CLAUDE.md и MCP, из пустой папки; проверено тестовой головой. Пилот 1 оценщиков остаётся как есть (сделан на старой обвязке), PREREG опирается на пилот 2.
- **Л1-2:** правда считалась при сборе пулов. → `harness.py truth` — только после сбора всех выборов; хеши пулов пишутся при сборе (`run/<stage>_pools.sha256`); список задач — из файла сидов, не вручную; перезапуск сбоя — один, автоматический (run_sealed).
- **Л1-3:** порядок кандидатов нёс ранжирование исполнителя (позиции 0–1 лучше по правде; головы их чаще выбирали). → одна перестановка на задачу по sha256(сид|perm) для всех рук; выбор переводится обратно в номер пула.
- **Л1-4 / Л3-6:** ε был флагом с умолчанием 0. → зашит: EPS = {WH: 150, SC: 15}.
- **Л1-6 / Л2-Н1, Н5:** текст правил неполон: какой товар принимается первым при переполнении (сдвиг правды до 2612, регрета до 1,45), округление спроса, среднее множителя 1,046, K при обнулённом заказе, хранение после списания; SC — переналадка после rel. → дописано в `rules_wh` / `rules_sc`. Шаблоны промптов (хеши EXEC/BASE/ROLE/ROLE_REFUSE) не менялись; меняется текст правил задачи → новый пилот 2 на сидах 7301–7312 (`seeds_pilot2.json`).
- **Л2-Н2:** урезание заказа в float (539,9999… вместо 540). → деньги в целых десятых. Правда пилота 1 сдвигается ≤ 0,1. Независимая реализация линзы 2 после исправления: 96 000 из 96 000 совпадений.
- **Л2-Н3 / Л3-4:** сбой головы (None) голосовал. → недействительные голоса исключаются; все недействительны → регрет 1 (D/D_N → A0).
- **Л2-Н4:** ключ ничьей включал руку (лишний независимый шум в парных разностях). → ключ sha256(задача|кандидат), общий для рук.
- **Л3-2, 3:** «засчитывается» = Холм против B_blind **и** неокруглённый односторонний перестановочный p против A0 ≤ 0,05 **и** равенство бюджета (ниже). Иначе вывод «не доказано».
- **Л3-1:** Δ = 0,2 нормированного регрета — только для расчёта n; тест против 0; величину ≥ Δ не утверждаем.
- **Л3-5:** дубли (задача, рука, i) — берётся последняя запись; одиночные A, C, D — вызов i = 0; их токены — этого вызова.
- **Л3-8:** TOST A против A0: граница ±0,1, оба односторонних перестановочных p ≤ 0,05 и совпадение выбора ≥ 0,7.
- **Л3 токены:** бюджет равен, если B_blind ≥ каждой руки семейства и по «вход + выход», и по выходу (средние на задачу) — проверка в `analyze.py` (`budget.equal`); нарушение → «бюджет не равен», рука не засчитывается.
- Вторичные меры — только описательно, без p.
