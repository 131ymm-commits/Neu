# Правила для Claude в репозитории Neu

**Цель максимум (слова автора, 26.09.2026):** «Создать сильный ИИ как систему взаимодействия предобученных голов Клауда».
Проверяемая часть: система взаимодействующих голов (специалисты + мозолистое тело + заземлённый проверяльщик + реестр и калибровка) сильнее одной головы при том же бюджете; измерить, что даёт диалог, голосование и заземление. Мера — ИОИ. Первый шаг — CLAUDE-01 (задачи мира EVO, скрытая правда), проект утверждает совет голов.

Автор просит записывать в репозиторий всё: результаты, отрицательные результаты, ошибки Claude, предположения и сам разговор.

1. **Журнал.** В конце каждой сессии выгрузить чат: `python3 journal/export_chat.py <transcript.jsonl> journal/CHAT_<даты>.md`. Транскрипт сессии лежит в `~/.claude/projects/<проект>/<session-id>.jsonl`. Закоммитить и запушить.
2. **Ошибки и предположения.** Всё, в чём Claude ошибся или что предположил без проверки, — в `journal/ERRORS.md`, новой записью. Старые записи не удалять и не переписывать; исправление дописывается к записи.
3. **Эксперименты.** Каждый — в `experiments/<дата>_<ID>/`. Предрегистрация (`PREREG-<ID>.md`) коммитится и пушится до первого прогона; отчёт ссылается на хеш этого коммита. Отрицательный результат хранится так же, как положительный. Пост-хок анализ записывается и вердикт не меняет. Протокол проекта — пять ворот из `archive/neu_archive_2026-09-16/docs/PREPROMPT.md`.
4. **Git.** Коммиты — от `Claude <noreply@anthropic.com>`. Запушенную историю не переписывать (хеши предрегистраций — доказательство). Один репозиторий на программу; версии — тегами, а не новыми репозиториями.
5. **Большие файлы.** Чекпойнты моделей (`*.pkl`) в git не класть; в репозитории — логи и json с результатами.

6. **Алгоритм целиком** — `PROTOCOL.md`; исполняемая версия — навык `.claude/skills/research-journal/SKILL.md`. Предложение для Anthropic по итогам опыта — `proposals/`.

## Мои правила (Claude для себя, 26.09.2026; выведены из journal/ERRORS.md № 13–25)

**Главный вопрос программы.** Как построить оценщика, который не обманывается под давлением отбора. Мера — ИОИ (`experiments/truth.py`): незнание + самообман, дальше + цена и обобщение. Лестница: игрушка → символьная модель → Pythia. Новый эксперимент должен отвечать на этот вопрос или прямо сказать, зачем он нужен.

**Ворота перед каждой предрегистрацией (обязательно, без исключений):**
1. Пилот на сиде, который не войдёт в тест. Смотреть динамику по шагам: численность, лосс, ранжирование. Итоговое число недостаточно.
2. Независимая проверка кода и плана агентами по трём линзам:
   - утечка истины в отбор;
   - ошибки в коде (масштабы, точки подключения, потоки случайных чисел);
   - проверяемость каждого предсказания в том виде, как оно записано.
3. Каждое «так же, как в X» сверить по коду X, а не по памяти (урок № 25).
4. Пилоты и всё, что изменилось после них, записать в PREREG. Только потом коммит.

**Статистика:**
- Разные задачи в один тест не сливать. Разбивку по типам задач задавать заранее.
- Кроме счёта побед давать величину эффекта с интервалом.
- Помнить о множественных проверках: указывать общий ложный уровень серии.
- «Точное» p — только полный перебор. Иначе писать «оценка Монте-Карло».
- Мощность считать до прогона.

**Миры и меры:**
- Проверять обобщение на входах вне обучающего диапазона, а не только на скрытых входах того же малого множества.
- Отчёт даёт незнание и самообман отдельно.

**Выводы:**
- Вывод получает статус «установлено» только после повтора с контролем на неспецифичность (урок AUTO-03 → AUTO-04/05).
- Причину эффекта писать только проверенную. Иначе «объяснение не проверялось».
- Каждое число в отчёте берётся из json и сверяется `ledger.py audit`. Из округлённого лога числа не брать.

**Литература.**
- Без полного текста ставить статус «сниппет» или «по памяти», и никак иначе.
- Числа и годы не додумывать.

**Постановки с головами Claude (уроки HUMOR/SMUGGLE/CALIB/PEER/PRED/HIVE, 26.09.2026):**
- Правда — только от кода. Без неё головы Claude меряют «нравится Claude» и сходятся друг с другом (HUMOR-01).
- Сложность задач выбирать пилотом, начиная с заведомо трудного уровня: головы без инструментов точно считают комбинаторику в уме.
- Одинаковые головы на одинаковом промпте дают один ответ: толпа без разнообразия ничего не добавляет (PRED-01).
- Отказ головы — сигнал о постановке, а не технический сбой. Постановки с намеренным внесением ошибок в код не делать.
- Правду проверять вторым способом до прогона; правду не класть туда, где её могут прочитать головы.
- Сухой прогон всей цепочки на заглушках — до регистрации.

**Работа и очереди:**
- Долгие прогоны ставить в очередь, которая умеет продолжать с места остановки (`experiments/run_queue.sh`).
- Логи коммитить вместе с отчётом.

**Общение с человеком:**
- Писать по-русски, всегда, независимо от языка кода и подсказок агентам.
- Коротко: итог, одна таблица, что дальше.
- Решения предлагать с рекомендацией, а не списком вопросов.
- Свою ошибку называть первой, без смягчений, и записывать в `journal/ERRORS.md`.

**Работа с собой (наши же инструменты):**
- `tools/ledger.py` — реестр утверждений Neu (`claims.jsonl` → `CLAIMS.md`). Выводы меняются только через него, с опорой.
- `tools/self_calibration.py` — моя калибровка: ожидания до прогона против исходов. Каждое новое ожидание из PREREG дописывать в таблицу, исход — после отчёта.
- В начале сессии хук показывает сводку реестра, мои последние ошибки и калибровку (`.claude/settings.json`).

**Совет голов (`.claude/workflows/council.js`).**
- Решения о новых экспериментах, изменениях протокола и спорных выводах принимает совет: формалист, интуит, скептик и инженер, координатор — мозолистое тело.
- Изменения вношу только по принятому решению: единогласно или большинством, не меньше 3 из 4 голосов «за».
- Если большинства нет, решение переписывается по возражениям, и совет голосует снова, до двух раз. Не принято — не вношу, а докладываю человеку.
- Стенограмма и голоса сохраняются в `docs/council/`.
