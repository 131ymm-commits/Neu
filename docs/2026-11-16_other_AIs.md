# Другие ИИ в Neu: каналы, правила, первый опыт (16.11.2026)

**Слова автора, 16.11.2026 (дословно):** «Дальше. Ты думаешь. Внешние ресурсы считают. Кстати ты можешь лбопщатся к другим ИИ? Попробуй их так то интегрировать в проект.» «лбопщатся» я читаю как «обращаться», «так то» — как «как-то».

## Зачем это Neu
- **Главный вопрос — оценщик под давлением отбора, и у него есть слабое место: общие ошибки голов.**
  - Согласие помогает, пока ошибки голов разные. Когда два варианта pythia-2.8b оба ошибаются, их неверный ответ совпадает в 0,77–0,78 случаев (OCGEO-01, разведка). Для согласия это почти одна голова.
  - Ложное согласие при общих ошибках — PLATON-01. Одинаковые головы на одинаковом промпте дают один ответ — PRED-01.
  - Головы разных производителей — самый дешёвый источник разных ошибок.
- **Цель автора** — «набор препромптов для сильного „мотора“ из сторонних моделей». Несколько моторов вместо одного — прямое её продолжение.
- **Совет голов** — сейчас четыре головы одного мотора. Голова другого производителя дала бы внешнюю проверку, которой не хватало (критика 12.10.2026).

## Правила (CLAUDE.md и уроки)
1. **Правда — только от кода.** Ответы моделей — текст для записи; ничего из них не исполняется.
2. **Ключи — только в секретах репозитория** и только в заданиях `gha_par/`. В сессию они не кладутся, не печатаются и вычищаются из вывода.
3. **В запросах к чужим моделям нет личных данных автора.** Задачи — синтетические, из кода.
4. **Модель фиксируется до данных.** Открытые веса — по имени и ревизии. У API — имя модели и дата; модель API может смениться молча, поэтому смена модели — стоп прогона (PREREG EVAL-01 §3).
5. **У каждого опыта с API — счётчик трат с остановкой.** У бесплатного яруса — счётчик запросов под суточный предел.
6. **Отказ головы — сигнал о постановке**, а не технический сбой.
7. **В каждой постановке с несколькими головами** — база «одна лучшая голова» и оракул. Мощность считается до PREREG.
8. **Контроль «постоянное снижение заявки».** Совет 65: P1 показал, что одно снижение уверенности уже даёт выигрыш.

## Первый опыт (набросок; пойдёт через ворота)
- **Рабочее имя — ОЦЕНЩИК-РАЗНЫЕ-ГОЛОВЫ.** Тот же мир, что в линии оценщика: сложение, ID и OOD по диапазону, правда от кода. Головы — 6–9 моделей разных производителей. Уверенность головы — по логарифмам вероятностей ответа (у открытых весов); у API — по повторным ответам или словесная.
- **Вопросы:**
  1. Переносится ли калибровка с ID на OOD у голов другого рода? Предсказание совета 65: не переносится.
  2. Повторяется ли самообман от отбора (C-090) у голов разных производителей?
  3. Помогает ли согласие голов разных производителей больше, чем согласие голов одного рода? Общих ошибок должно быть меньше; это проверка мысли из разведки OCGEO-01.
- **Порядок:**
  1. проба каналов;
  2. гипотеза;
  3. литература;
  4. пилот на сиде вне теста;
  5. мощность;
  6. PREREG;
  7. совет — три линзы;
  8. прогон на внешних площадках.
- **Моя рекомендация — начать с открытых весов.** Они бесплатны, модель не меняется без нашего ведома, и считать можно на Kaggle, Modal или процессоре GitHub Actions. Claude через API — когда в секретах появится ключ. Бесплатные API других производителей — только по слову автора: на каждый нужен свой ключ в секретах.
