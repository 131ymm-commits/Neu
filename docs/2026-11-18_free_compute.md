Это список разрешённых хостов окружения, а не недоступность сайтов. `oracle.com/cloud/free/` ответил 403. Прокси статус: эти домены в политике сессии не разрешены; в обход не ходил.
2. **Поэтому почти все статусы в таблице — «сниппет» (выдача поиска) или «по памяти».** Статус «официальная страница (прочитана)» не присвоен ни одной площадке. Цифры из выдачи противоречат друг другу в нескольких местах (отмечено ниже).
3. Чтобы закрыть проверку по первоисточникам, нужно разрешить в сетевых настройках сессии хосты документации (см. «Что нужно от автора»).

## Рекомендация

Две-три площадки к GitHub Actions и Kaggle:

1. **Colab CLI как второй путь к T4 (приоритет 1).** Это GPU, уже выбранный в `COMPUTE.md`, и CLI умеет запускать скрипт и забирать файлы. Блокер — вход через аккаунт Google; нужно проверить, можно ли держать токен в секрете репозитория и обновлять его без клика. Если нельзя — Colab остаётся по клику.
2. **GitLab CI по программе для открытых проектов (приоритет 2, только при одобрении заявки).** Даёт процессорный пул, независимый от GitHub. Без программы 400 минут в месяц — почти бесполезно. Цифра 50 000 минут — только по выдаче, не подтверждена.
3. **Codeberg Woodpecker (приоритет 3).** Бесплатный и открытый, но лимиты не опубликованы, доступ по заявке, код хранится у третьей стороны.

Не рекомендую: Cirrus CI (возможное закрытие), Bitbucket (50 минут), Hugging Face Spaces (не пакетный режим, противоречивые правила), Oracle (мощности и карта, в процессоре GitHub Actions уже сильнее).

Главный вывод по процессору: GitHub Actions даёт 20 параллельных заданий, и это, вероятно, достаточно для текущих опытов. Узкое место — видеокарта (Kaggle ~6 ч в неделю), поэтому дополнительный поиск имеет смысл прежде всего для GPU.
