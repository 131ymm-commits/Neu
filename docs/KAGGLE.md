# Прогоны Neu на Kaggle

Решение автора, 14.11.2026: «может запускать прогоны не в тебе а на кагле с колабом?» → Kaggle через официальный API.

## Как устроено
- **Ключ API Kaggle** хранится в секретах среды «Neu» (сетевые секреты, хост api.kaggle.com, заголовок Authorization). Сетевой прокси подставляет ключ в запросы. В коде, в репозитории и в чате ключа нет: клиенту передаётся заглушка `proxy-injected`.
- **Файлы результатов** Kaggle отдаёт с адреса www.kaggleusercontent.com, он добавлен в разрешённые хосты среды.
- **Инструмент** — `tools/kaggle_run.py` (kagglesdk):
  - `push` — отправить скрипт закрытым ноутбуком;
  - `wait` — ждать завершения;
  - `output` — скачать файлы и журнал;
  - `quota` — квоты ускорителей.
- **Имя пользователя Kaggle** в репозиторий не пишется: инструмент берёт его из ответа API во время работы.
- **Ноутбуки создаются закрытыми.** Репозиторий открытый, поэтому всё, что идёт в git, проверяется на личные данные.

## Порядок для опыта
1. Код опыта и PREREG — коммит и пуш до прогона, как всегда; хеши сверяются.
2. `python3 tools/kaggle_run.py push experiments/<опыт>/run_kaggle.py --slug neu-<опыт> [--gpu]`.
3. `python3 tools/kaggle_run.py wait --slug neu-<опыт>`.
4. `python3 tools/kaggle_run.py output --slug neu-<опыт> --to experiments/<опыт>/run/` → коммит результатов и журнала.

Скрипт для Kaggle — один файл. Код опыта в него вкладывается целиком: Kaggle не видит репозиторий без интернета. В его начале — sha256 вложенных файлов, чтобы сверить с регистрацией.
