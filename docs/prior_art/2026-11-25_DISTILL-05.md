## 1. Вопрос

Семь малых моделей (≤ 2B) складывают «a+b=» с примерами. OLMo-2-1B режет числа на куски по три цифры слева направо; остальные шесть — по одной цифре. Гипотеза: у OLMo «прочие» ошибки — целые токены-соседи (кусок ± k), поэтому смещения ±10k при четырёх разрядах переходят в ±100k при пяти; у голов с цифрами по одной такого сдвига нет. Сравнение — с таблицей частот смещений того же размера.

## 2. Источники по пунктам

### (1) Связь нарезки токенизатором с видом ошибок

- **Singh, Strouse — «Tokenization counts: the impact of tokenization on arithmetic in frontier LLMs», arXiv 2402.14903.** Статус: **полный текст** (§2.2, §3.1–3.3, §4.1–4.4, §7, §8, приложения A, C). Модели GPT-3.5 и GPT-4 — не малые.
  - Сверено по тексту: L2R (три цифры на токен) даёт 75,6 % при 8 примерах, R2L (запятые) — 97,8 % (§3.1, рис. 4). Вывод сделан из выдачи, цифры по тексту сходятся.
  - §4.4: у L2R из 56 ошибок в «длина совпадает» 53 — смещение на ±1, у R2L из 25 — 24 таких. «Почти у всех» ошибка стоит **в последней цифре выходного токена**, то есть на границе куска. Это прямо близко к нашей гипотезе.
  - §4.3: при L2R и «длине не совпадает» модель всегда неверна в четвёртой цифре; величины ошибок «довольно равномерны, с небольшим перевесом ±1». Это ещё одна оговорка для нашей формы.
  - §4.1: L2R при ответе длиннее слагаемых даёт точность 8,25 %. Это механизм рассогласования нарезки, а не смещение на ±k.
  - Приложение C: частотный эффект слабый (L2R: 56 %, p = 0,005; R2L: 60 %, p = 0,115 при n = 25). Значит, частоту надо контролировать, но она не объясняет картину.
- **Bie и др. — «AI-rithmetic», arXiv 2602.10416.** Полный текст прочитан в DISTILL-03 (не перечитывался). Frontier-модели; смещение операнда (misalignment) и близкий перенос (close carry). По поиску — периодичность смещения по длине операнда, связанная с токенизацией. **Статус периодичности: сниппет**, в полном тексте не сверено; до PREREG сверить.
- **Levy, Geva — «Language Models Encode Numbers Using Digit Representations in Base 10», arXiv 2410.11781.** Статус: **частично** (введение, §2, §3.2–3.3). Llama 3 8B держит числа 0–999 одним токеном. Ошибки лежат ближе в «цифровом» пространстве строки, чем по значению (пример 833 → 633 / 823, а не 831 / 834). В таблице 1 (сравнение чисел, отличающихся одной цифрой) ошибки распределены по разрядам почти поровну.
- **Shintani — «Arithmetic OOD Failure Unfolds in Stages in Minimal GPTs», arXiv 2603.26828.** Полный текст в DISTILL-04. Минимальный GPT, OOD по длине; о нарезке токенов не сообщает.

### (2) Ошибка «соседним» числом-токеном

- **Singh, Strouse (2402.14903), §4.4 и приложение C** — **полный текст**. Тест строится ровно так: при ошибке на границе возможны три токена (верный, −1, +1). Среди соседей модель не выбирает более частый токен систематически: 7 из 24 (R2L) и 17 из 53 (L2R) случаев, по тексту приложения C; частотный эффект слабый. Сам выбор «верный или сосед» в этом тесте не анализировался. **Значит, сам факт «ошибка на ±1 токена» занят для GPT-3.5/4.** Для малых моделей и для связи с масштабом — не занят.
- **Levy, Geva (2410.11781)** — **частично**. Утверждение, что ошибки близки по цифровой строке, а не по значению, прямо конкурирует с гипотезой «близко по значению». У OLMo эти два прогноза расходятся только при займах (см. «Что стоит учесть»).
- **Zausinger и др. (2025), функция потерь с учётом близости чисел** — упомянуто в 2601.09706 (§2.2), **по пересказу, не открыто**; статус «сниппет».

### (3) Сдвиг масштаба ошибки с длиной числа

- **Не найдено.** Ни одна из работ не измеряет, как размер смещения растёт с числом разрядов для малых моделей. Singh, Strouse (§4.1, §4.3) сравнивают длины ответа и слагаемых, но не размер смещения по длине.
- **Bie и др. (2602.10416), периодичность по длине** — сниппет (см. выше).
- **Lee и др. (2023), «Teaching arithmetic to small transformers», arXiv 2307.03381** — по памяти: обратный порядок чисел упрощает алгоритм, нарезка не обсуждалась. Не проверено.

### (4) Модели ошибок по головам (не среднее) для малых моделей

- **Не найдено.** Все найденные работы агрегируют по модели или по задаче. Для малых моделей с разной нарезкой (сравнение семи голов) модели ошибок по головам не нашёл. Совпадает с выводом DISTILL-04 («Не найдено»).
- **NumeroLogic, Schwartz и др., arXiv 2404.00459.** Статус: **частично** (grep по тексту). Префикс с числом разрядов для малых трансформеров с символьной токенизацией. Анализа величины ошибок нет, это метод кодирования.
- **Value-Aware Numerical Representations, Dutulescu и др., arXiv 2601.09706.** Статус: **частично** (grep). GPT-2 с нуля, задачи NUPA; есть метрика «расстояние по длине», но нет анализа величины смещения. Оценка головы — точность.
- **Triadic Suffix Tokenization, Chetverina, arXiv 2604.11582 (v3).** Статус: **частично**. Предложение схемы, без опыта («Experimental validation» — в тексте, строка 421, теоретическое обоснование). Для малых моделей говорится, что N = 1 — гипотеза, не результат. Учитывать как «занято гипотезой, не опытом».

## 3. Что занято, что нет

| Пункт | Занято | Не занято |
|---|---|---|
| (1) нарезка → вид ошибок | Да, для GPT-3.5/4: L2R вызывает рассогласование (§4.1), ошибки на границе куска (§4.4) | Для малых моделей с нарезкой по три цифры (OLMo) — не проверено |
| (2) ошибка соседним токеном | Да, для GPT-3.5/4 (§4.4, приложение C). Строка-против-значения — Levy, Geva | Для малых моделей; совместный прогноз «±10k → ±100k» — нет |
| (3) сдвиг масштаба с длиной | Нет | Полностью свободно (сниппет Bie — периодичность, не масштаб) |
| (4) модели ошибок по головам | Нет (совпадает с DISTILL-04) | Полностью свободно |

**Что занято по существу:** сам эффект «L2R-нарезка → ошибки на границе куска, на ±1 токена» показан (Singh, Strouse). Что стоит учесть: в нашей гипотезе OLMo — не открытие, а проверка того же механизма на малых моделях и на длине, которую S&S не брали.

## 4. Что учесть в PREREG

1. **Заявлять новизну только для малых моделей и для сдвига масштаба.** Механизм «ошибка на ±1 токена на границе» — не новость; её описал Singh, Strouse (§4.4). Ссылаться, не выдавая за свой результат.
2. **Разделить «строка» и «значение».** Levy, Geva говорят, что ошибки близки по цифрам. Для OLMo при 4 разрядах оба прогноза дают ±10k. Различие видно на займах: при 5 разрядах смещение −100 от 12043 даёт 11943 (меняются две цифры), тогда как односимвольная правка цифры даёт другой набор величин. Предсказание: доля смещений с займом у OLMo выше, чем у головы с цифрами по одной. Это вывод по определению нарезки, **не проверено кодом**; до PREREG проверить на заглушке.
3. **Контроль частоты.** S&S показали слабый, но значимый частотный эффект (L2R: 56 %, p = 0,005). Вводить контроль по рангу слияния (merge rank), как у S&S (приложение C), и заранее указать разбивку по типам ошибок.
4. **Базы.** База «смещение на ±1 токен, равномерно» и база «смещение на ±k цифр, равномерно» — в PREREG как таблица частот того же размера, как в гипотезе.
5. **Величины, а не знаки.** S&S (§4.3) сообщают, что величины ошибок ближе к равномерным, чем к ±1. Порог «ошибки на ±1 токен» задать заранее и не подгонять по пилоту.
6. **Сверить Bie (периодичность по длине) по полному тексту** до регистрации: сейчас это сниппет.
7. **Не брать в основу TST (2604.11582) и NumeroLogic (2404.00459)** как результаты: оба без опыта над нарезкой-и-ошибками для малых голов.
8. **Числа из S&S** — 75,6 % и 97,8 % — сверены по тексту §3.1. Числа из поисковых выдач (например, «8,25 %», «53 из 56») — из текста §4.1 и §4.4 и сверены с ним; из других выдач не брать.
