## Находки

1. **LeapLabTHU/Absolute-Zero-Reasoner** (https://github.com/LeapLabTHU/Absolute-Zero-Reasoner): README прочитан (1,9k звёзд), открыты также `absolute_zero_reasoner/utils/code_utils/python_executor.py` и `data_construction/prompts.py`. Одна модель составляет задачи-программы и решает их, судья — исполнитель Python.
   - **Механизм, который можно взять:** (а) ворота годности задачи до игры: разбор AST, запрет перечисленных слов и модулей (`banned_keywords`), таймаут 10 с, двукратный прогон с совпадением статуса и вывода (проверка детерминизма), результат должен сериализоваться (`pickle.dumps`); в промпте запрещены случайность, дата и время, ввод-вывод и печать; (б) в промпт составителя кладутся прошлые задачи из буфера с требованием «the code needs to be sufficiently different from the provided reference snippets»; (в) в README упомянуты подключаемые награды «diversity and complexity rewards» (`azr.reward.generation_reward_config`).
   - **Куда у нас:** DUEL-01. Приём (б) можно ввести уже сейчас: показывать составителю его и чужие прошлые пары (семейство, параметры). Ворота (а) станут готовым шаблоном для судьи, если составителям разрешат писать собственные семейства задач кодом.
   - **Цена:** малая для (б), средняя для (а).
   - **Оговорка:** работа обучает веса через RL. Формула «обучаемости» (награда 0 при решаемости 0 % и 100 %) видна только в сниппете: страница проекта закрыта прокси. Близкий приём у Self-Challenging Agents (Zhou et al. 2025): задача годна, только если эталонное решение проходит проверяющую функцию, а заготовленные ошибочные не проходят (сниппет, кода не нашёл).

2. **Chengsong-Huang/R-Zero** (https://github.com/Chengsong-Huang/R-Zero): README прочитан (852 звезды), формулы из сниппета. **Gengsheng-Li/R-Diverse** (https://github.com/Gengsheng-Li/R-Diverse): README прочитан (8 звёзд). В R-Zero Challenger и Solver получаются из одной модели; R-Diverse исправляет в R-Zero «иллюзию разнообразия».
   - **Механизм:** в R-Zero составитель получает награду 1 − 2·|p̂ − ½|, где p̂ — доля из 10 ответов решателя, совпавших с ответом большинства. Повторы внутри пакета штрафуются так: задачи с 1 − BLEU < 0,5 объединяются в кластер, и штраф растёт с размером кластера. Решатель учится только на задачах, где с большинством совпали от 3 до 7 ответов из 10. В R-Diverse банк прошлых задач хранится через все итерации, а штраф считается как максимальное плюс среднее сходство с банком; без этого моды повторяются по кругу от итерации к итерации. Сходство меряется по каноническому решателю-программе, а не по тексту задачи («Skill-Aware Measurement»).
   - **Куда у нас:** DUEL-01. Наша задача уже канонична (семейство и параметры), поэтому «навыковое» сходство код считает бесплатно. Шаги: (1) хранить банк всех сыгранных пар (семейство, параметры) за все раунды; (2) штрафовать задачу из окрестности уже сыгранной или отказывать в ней; (3) выводить долю повторов по раундам как меру вырождения. Полоса «не слишком легко и не слишком трудно» пригодна как фильтр для контрольного набора.
   - **Цена:** малая.
   - **Оговорка:** p̂ по большинству нам не нужен, правду даёт судья. Штраф меняет правило очков, поэтому вводить его можно только в новой предрегистрации (DUEL-02), не задним числом.

3. **Разнородные решатели.** Статья «Beyond Uncertainty: Multi-Solver Disagreement Rewards for Self-Evolving Reasoning Curricula» (arXiv 2608.30035, август 2026): сниппет, кода не нашёл. Практический образец назначения моделей подагентам — **wshobson/agents** (https://github.com/wshobson/agents): README прочитан (40 000+ звёзд). Статья показывает, что награда составителя по неопределённости одного решателя падает до нуля, когда все ответы уверенного решателя совпадают.
   - **Механизм:** источником разногласия служат разные модели и режимы, а не копии. В статье награда — нормированная энтропия ответов разнородного ансамбля, где модели различаются мощностью и температурой. В wshobson/agents модель подагента задаётся во фронтматтере, ярусы по типу работы: Fable 5, Opus, inherit, Sonnet, Haiku.
   - **Куда у нас:** DUEL-01 и HIVE. По PRED-01 копии дают один ответ, поэтому у одинаковых копий очки составителя («средний балл соперников минус свой») вырождаются в шум. По справке workflow-authoring, `agent()` в Workflow принимает `opts.model` и `opts.effort`, так что разнородные головы получаются одним параметром.
   - **Цена:** малая по коду, но это новый фактор, и нужна новая предрегистрация.
   - **Оговорка:** очки начнут мерить разницу моделей, а не стратегий. Нужен план, который разделяет эти два эффекта, например одна и та же модель у пары «до» и «после» переписывания заметок. Результаты статьи известны только по сниппету.

4. **SakanaAI/drq**, Digital Red Queen (https://github.com/SakanaAI/drq): README прочитан (224 звезды). **spiral-rl/spiral** (https://github.com/spiral-rl/spiral): README прочитан (205 звёзд). В DRQ модель в каждом раунде пишет программу-воина для Core War, и эта программа должна победить всех прежних. В SPIRAL одна политика играет обе роли в играх с нулевой суммой.
   - **Механизм:** новичка оценивают против истории соперников («зал славы»). В DRQ это окно `last_k_opps` (20 в примерах) и порог приспособленности 0,8; по сниппету, исторические соперники гасят циклы. SPIRAL меряет долю побед против фиксированного соперника. Такой якорь нужен против эффекта Красной королевы: относительные очки могут расти, когда абсолютного прогресса нет.
   - **Куда у нас:** DUEL-01. Предлагаю перекрёстную матрицу поколений: заметки раунда r играют против замороженных заметок раундов 0…r−1 на свежих задачах, правду считает код. Матрица отличает прогресс составителей от циклов. Контрольный набор bench0/bench1 меряет только решение, а не составление.
   - **Цена:** средняя (нужны дополнительные вызовы).
   - **Оговорка:** SPIRAL обучает веса. У нас 4 игрока и мало раундов, поэтому мощность матрицы надо посчитать заранее. Близкая работа с популяцией — PopuLoRA (2026): пары учитель — ученик подбираются по TrueSkill к равным силам (сниппет). Официального кода не нашёл; lucidrains/populora — неофициальная переделка про эволюцию LoRA, не про подбор пар.

5. **conglu1997/ACD**, Automated Capability Discovery (https://github.com/conglu1997/ACD): README прочитан (68 звёзд), механизм по сниппету. Модель-«учёный» пишет кодом семейства задач (экземпляры, инструкции, оценка) для испытуемой модели. Архив задач растёт, а задачи, слишком близкие к уже известным, отбрасываются.
   - **Механизм:** архив и фильтр новизны до прогона; по README «Full logs and all discovered tasks … are saved in the `results` directory».
   - **Куда у нас:** DUEL-01, следующий шаг: составитель предлагает не параметры, а новое семейство, то есть код-генератор и код правды. Годность проверять воротами из п. 1, новизну — банком из п. 2.
   - **Цена:** большая.
   - **Оговорка:** по README судья по умолчанию — GPT-4o, то есть правда у них частично не от кода. Брать стоит только архив и фильтр новизны, не оценку. Что семейство оформлено как класс Python — по памяти.

6. **LeapLabTHU/ExpeL** (https://github.com/LeapLabTHU/ExpeL): README прочитан (244 звезды), операции с правилами по сниппету из текста статьи. Агент извлекает текстовые «инсайты» из удачных и неудачных попыток и держит их ограниченным списком (в README `max_num_rules=10`).
   - **Механизм:** свод не переписывается целиком: модель выбирает операции ADD, EDIT, UPVOTE, DOWNVOTE. Новое правило получает счётчик 2; UPVOTE и EDIT прибавляют 1, DOWNVOTE отнимает 1; при нуле правило удаляется.
   - **Куда у нас:** HIVE и DUEL-01. В HIVE-01 голосовать по операциям над пронумерованными законами, а не переписывать свод; это даёт встроенное забывание, а журнал операций становится готовой наблюдаемой: какие законы живут и какие умирают. То же пригодно для заметок в DUEL.
   - **Цена:** малая.
   - **Оговорка:** у ExpeL счётчик двигает сама модель, то есть он мерит «нравится модели», а не правду. У нас UPVOTE надо привязать к кодовой правде, например разрешать его, только если закон действовал в раунде с лучшим баллом.

7. **ace-agent/ace**, Agentic Context Engineering (https://github.com/ace-agent/ace): README прочитан (1,3k звёзд). Три роли — Generator, Reflector и Curator — ведут «плейбук» из пунктов.
   - **Механизм:** пункт выглядит как `[str-00001] helpful=5 harmful=0 :: текст`. Куратор вносит дельта-правки (добавить или обновить пункт) с детерминированным слиянием, удалением дублей и обрезкой. Цель — избежать «коллапса контекста», когда повторное переписывание стирает детали, и смещения к краткости. Метки не обязательны (`--no_ground_truth`).
   - **Куда у нас:** DUEL-01. Сейчас заметки после каждого раунда переписываются целиком, не больше 6 пунктов; ровно в таком режиме ACE наблюдает коллапс. (1) Пост-хок на уже собранных логах: длина заметок и число уникальных утверждений по раундам, доля пунктов, переживших переписывание. Вердикт это не меняет. (2) В следующей версии — пункты с id и счётчиками helpful/harmful, которые выставляет код по правде судьи.
   - **Цена:** малая.
   - **Оговорка:** у ACE счётчики выставляет Reflector, то есть модель; у нас это должен делать только код.

8. **giorgiopiatti/GovSim** (https://github.com/giorgiopiatti/GovSim): README прочитан (84 звезды). Агенты делят общий ресурс в трёх сценариях (рыбалка, пастбище, загрязнение); по README кооперация сложилась в 2 из 45 случаев, обвал — в 43 из 45 (15 моделей).
   - **Механизм:** готовые возмущения опыта: подсказка «universalization» («что будет, если так поступят все»), абляция без языка (агенты не общаются), «жадный новичок», которого вводят после того, как порядок сложился, и смешанные модели. Конфигурация через Hydra.
   - **Куда у нас:** HIVE. (а) Контроль «без обсуждения и голосования» меряет ценность законов. (б) «Новичок» — голова с чужим сводом входит в улей на раунде r; мера — устойчивость законов и балла.
   - **Цена:** малая или средняя.
   - **Оговорка:** их правда — динамика ресурса, а не точность ответов. «Жадный» участник не должен превращаться в намеренную порчу кода: наше правило такие постановки запрещает.

     - Agentrace — линтер готовых стенограмм `~/.claude/projects/<slug>/<session>.jsonl` с проверками error, gave_up, thin_prompt и другими; вывод в JSON.
     - AgentSociety выполняет запросы к JSONL-журналам через DuckDB.
   - **Куда у нас:** инфраструктура, беда из ERRORS № 31. В локальной папке этой сессии есть `subagents/workflows/wf_*/journal.jsonl` и `agent-*.jsonl`; я проверил только наличие файлов, чтение содержимого запретил классификатор разрешений. Предлагаю скрипт-аудитор по образцу Agentrace. Для каждой головы опыта он берёт первое сообщение из её стенограммы и ищет в нём последнее сообщение человека, фрагменты CLAUDE.md и пути к правде. Запросы — через DuckDB, результат — таблица в отчёт. Второй, независимый журнал дают хуки SubagentStart и PreToolUse.
   - **Цена:** малая.
   - **Оговорка:** не проверено, проходят ли вызовы `agent()` из Workflow через эти хуки. Важнее другое: по справке workflow-authoring, подагенты Workflow получают те же файлы CLAUDE.md, что и главный агент (кроме встроенных типов вроде Explore и Plan). Значит, головы опытов видят правила проекта, включая наши гипотезы, например об одинаковых головах. Это второй канал утечки контекста помимо ERRORS № 31, и аудитор должен искать оба.

15. **UKGovernmentBEIS/inspect_ai** (https://github.com/UKGovernmentBEIS/inspect_ai): README прочитан (2,9k звёзд), открыты `src/inspect_ai/model/_cache.py`, `_eval/evalset.py`, `agent/_filter.py`, `agent/_handoff.py`, `event/_model.py`; документация на inspect.aisi.org.uk закрыта прокси. В подкрепление — **stanfordnlp/dspy** (`docs/docs/learn/programming/language_models.md` на GitHub, прочитан). Inspect — каркас оценок LLM от UK AISI.
   - **Механизм:**
     - (а) **Ключ кэша.** В ключ входят конфигурация генерации, сообщения, base_url, инструменты, tool_choice, срок хранения и `scopes`; при `per_epoch=True` (так по умолчанию) — ещё и номер эпохи. Срок хранения по умолчанию «1W». В DSPy та же роль у `rollout_id` в ключе; при температуре 0 он бесполезен.
     - (б) **Журнал вызовов.** Каждый вызов модели записывается как ModelEvent с полями input, config, output, retries, error, `cache` («Was this a cache read or write»), `call` (сырой запрос к API) и working_time.
     - (в) **Повтор прогона.** `eval_set` при повторе берёт завершённые образцы из логов и заново запускает только упавшие. Повторных попыток по умолчанию 10, ожидание 30, 60, 120… с (до часа); задачу опознаёт хеш конфигурации.
     - (г) **Передача контекста подагенту.** У `handoff()` параметр `input_filter` по умолчанию None, то есть подагент получает всю историю. `output_filter` по умолчанию `content_only`: он убирает системные сообщения и рассуждения, а вызовы инструментов превращает в текст. Есть готовые фильтры `remove_tools` и `last_message` и лимиты на агента.
   - **Куда у нас:** инфраструктура.
     - Resume в Workflow отдаёт кэш по неизменному префиксу вызовов («same script + same args → 100% cache hit»). Поэтому в сырых записях нужны поле «живой / из кэша» и номер повтора внутри самого вызова, иначе «повторы» могут оказаться копиями.
     - Время вызова наши записи не содержат: по коду duel_step.js поле `t` всегда равно «не контролируется», потому что `new Date()` в сценариях запрещён. Стоит проверить, есть ли время в journal.jsonl.
     - Приём (г) — образец явного фильтра входа: для каждой головы записывать рядом с ответом, что именно ей передано.
   - **Цена:** малая для полей в записях. Переводить прогоны на сам inspect не советую.
   - **Оговорка:** inspect не умеет вызывать подагентов Claude Code, поэтому берём схему журналов и ключей кэша, а не каркас.

16. **ryoppippi/ccusage** (https://github.com/ryoppippi/ccusage): README прочитан (18,7k звёзд). Утилита считает расход токенов и деньги по локальным журналам Claude Code и других агентских CLI.
   - **Механизм:** отчёты по дням, неделям, месяцам и сессиям, а также по окнам оплаты Claude (blocks); вывод в JSON (`--json`), разбивка по моделям (`--breakdown`).
   - **Куда у нас:** инфраструктура. К бюджету вызовов добавить бюджет токенов: в каждом отчёте — расход на опыт с разбивкой по моделям. Это станет важно, если головы станут разнородными (п. 3).
   - **Цена:** малая, если доступен npm; иначе около 30 строк Python по полям usage в JSONL.
   - **Оговорка:** не проверено, учитывает ли утилита стенограммы подагентов в `subagents/`. По роли «инженер» в council.js сеть проекта открыта только для GitHub и PyPI, так что npm может быть закрыт.

17. **Предрегистрация кодом.** **polarizetech/adaptive-preregistration** (https://github.com/polarizetech/adaptive-preregistration): README прочитан (0 звёзд). **connorshibley/preregister** (https://github.com/connorshibley/preregister): README прочитан (0 звёзд). Оба инструмента защищают запись о предрегистрации от задним числом внесённых правок.
   - **Механизм:**
     - В adaptive-preregistration git-хук отказывает в коммите результатов до метки `-prereg` и в правке замороженного плана. Изменения идут в DEVIATIONS.md, где каждое датировано и помечено, был ли уже известен результат («can't turn a fail into a pass»).
     - В preregister lock-файл гарантирует, что в журнале «nothing above the last heading was ever edited». Реестр ведёт накопленное число проверок K, и каждая проверка значимости получает поправку Бонферрони на весь накопленный K. Журнал проверяется линтером: `python -m preregister.gatelog LOG.md --strict --lock LOG.lock.json`.
   - **Куда у нас:** инфраструктура (протокол). Pre-commit-хук с тремя правилами:
     1. нельзя коммитить `experiments/<ID>/run/*`, пока `PREREG-<ID>.md` не лежит в более раннем коммите;
     2. PREREG нельзя менять после первого коммита прогона — только DEVIATIONS.md с пометкой «результат известен: да/нет» (у HIVE-01 такой файл уже есть);
     3. `tools/ledger.py` считает накопленное K серии для общего ложного уровня.
   - **Цена:** малая.
   - **Оговорка:** у обоих проектов нет звёзд и проверки сообществом, поэтому брать идею, а не код. Пушить метки в нашей сессии нельзя (CLAUDE.md), поэтому проверять надо по коммитам, а не по меткам.

## Топ-5 взять в работу
Ранжировано по отношению пользы к цене.

1. **Аудитор входа голов (п. 14): цена малая.** Утечка последнего сообщения человека (ERRORS № 31) и, по справке workflow-authoring, инъекция CLAUDE.md в подагентов могут обесценить все опыты с головами. Аудитор нужен до следующей предрегистрации и сразу применим к уже сохранённым стенограммам.
2. **Pre-commit-хук предрегистрации и накопленное K (п. 17): цена малая.** Главный пункт протокола перестаёт держаться на дисциплине и становится механикой, а «общий ложный уровень серии» считается автоматически.
3. **Разнородные головы через `opts.model` и `opts.effort` (п. 3): цена малая.** Из всего найденного только это возвращает сигнал там, где копии дают один ответ: PRED-01 и очки составителя в DUEL. Нужна новая предрегистрация с планом, который отделяет «модель» от «стратегии».
4. **Заметки и законы как пронумерованные пункты со счётчиками, которые двигает код (пп. 6–7): цена малая.** Сначала бесплатный пост-хок «коллапса контекста» на логах DUEL-01 (вердикт не меняет), затем новая механика для DUEL-02 и HIVE.
5. **Парные ветки от снимка улья (п. 9): цена средняя.** Сейчас у нас нет способа проверить причину эффекта закона, а правило CLAUDE.md этого требует; ветки дают прямую проверку.

Следом по очереди: банк сыгранных задач со штрафом за повтор (п. 2), журнал продвижения в council.js (п. 13), поле «живой / из кэша» и номер повтора в сырых записях (п. 15), Парето-отбор для HIVE-02 (п. 10).
