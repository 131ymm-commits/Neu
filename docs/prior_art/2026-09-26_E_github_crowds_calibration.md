## Находки

### Разнообразие из одной модели

1. **CHATS-lab/verbalized-sampling** (https://github.com/CHATS-lab/verbalized-sampling) — README прочитан; 813 звёзд, Apache-2.0. Промпт против схлопывания мод: модель выдаёт k ответов с вероятностями, затем один выбирается случайно из этого распределения. README обещает рост разнообразия в 2–3 раза при том же качестве и прямо называет Claude среди совместимых моделей.
   **Механизм, который можно взять:** шаблон «Generate 5 responses … each within a separate `<response>` tag … `<text>` and a numeric `<probability>` … sample at random from the tails of the distribution, such that the probability of each response is less than 0.10»; API `verbalize(prompt, k=5, tau=0.10, temperature=0.9).sample(seed=42)`. Применений два: (а) копии получают разный `seed` выбора и перестают совпадать; (б) k значений с вероятностями — дискретное распределение головы, из которого 10-й и 90-й процентили дают интервал без прямого вопроса «дай 80 % интервал».
   **Куда у нас:** PRED, CALIB. **Цена:** малая (замена промпта). **Оговорка:** разнообразие ответов ещё не означает независимых ошибок. Замеров на числах с точной правдой в README нет. Хвостовой режим (τ < 0,10) нарочно выдаёт маловероятные значения, поэтому для оценок нужна выборка из всего распределения. Вербальные вероятности не откалиброваны.

2. **MraDonkey/DMAD** (https://github.com/MraDonkey/DMAD) — README прочитан; 26 звёзд, Apache-2.0; ICLR 2025. Дебат, в котором каждому агенту задан свой метод рассуждения: Chain-of-Thought, Step-Back, Input/Output prompting, Compositional CoT, Duty-Distinct CoT. Цель — сломать «фиксированную установку» одинаковых агентов. По выдаче DMAD за 2 раунда лучше MAD за 5 (Gemini; ScienceQA, MM-Vet) — сниппет. Базовая линия — **composable-models/llm_multiagent_debate** (Du et al.; README + код `gsm/gen_gsm.py`; 552 звезды): 3 агента × 2 раунда, реплика «These are the solutions to the problem from other agents: … Using the solutions from other agents as additional information…».
   **Механизм, который можно взять:** разнообразие через обязательный *разный метод решения*, а не через температуру или персону. Для счётных задач: перебор малых случаев с экстраполяцией; формула или рекуррентность; оценка порядка величины; нижняя и верхняя границы — у каждой головы свой метод.
   **Куда у нас:** PRED, совет, HIVE. **Цена:** малая. **Оговорка:** проверено на задачах с одним верным ответом, не на интервалах. У одной модели разные методы могут приводить к одинаковым ошибкам — мерить надо корреляцию ошибок, а не только точность.

3. **thunlp/ChatEval** (https://github.com/thunlp/ChatEval) — README прочитан; 343 звезды, Apache-2.0; ICLR 2024. Коллегия судей с разными ролями («Critic», «General Public» и т. п.) обсуждает ответы по очереди 2 раунда, потом ставит оценки; в промпте сказано, что порядок ответов не должен влиять на суждение. По сниппету статьи одинаковые роли ухудшают результат: 60,0 % с разными ролями против 53,8 % с одинаковыми (ChatGPT). Источник персон в масштабе — **tencent-ailab/persona-hub** (README прочитан; 1,7 тыс. звёзд; выложено 200 тыс. персон и 370 млн «elite personas»; данные CC BY-NC-SA 4.0, код MIT).
   **Механизм, который можно взять:** разные роли у судей и членов совета как дешёвый источник разнообразия; обсуждение по очереди.
   **Куда у нас:** судьи, совет, PRED. **Цена:** малая. **Оговорка:** по уже известной работе Zheng et al. 2024 персоны не повышают точность. ChatEval мерит согласие с людьми на открытых текстах, а не точность по кодовой правде. Роли могут менять стиль, не трогая ошибок.

### Агрегатор-синтезатор и взвешивание голосов

4. **togethercomputer/MoA** (https://github.com/togethercomputer/MoA) + **wenzhe-li/Self-MoA** (https://github.com/wenzhe-li/Self-MoA) — README прочитаны, + код `utils.py` MoA; 3,0 тыс. и 17 звёзд. MoA: слои моделей-«предлагающих» и агрегатор с системным промптом «You have been provided with a set of responses from various open-source models to the latest user query. Your task is to synthesize these responses into a single, high-quality response.»; ответы нумеруются и вставляются в системный промпт. AlpacaEval 2.0: 65,1 % против 57,5 % у GPT-4o (README). Self-MoA: N выборок из одной лучшей модели плюс агрегатор лучше смеси разных моделей: +6,6 на AlpacaEval 2.0 и в среднем +3,8 % на MMLU, CRUX, MATH (README). Цитата: «the MoA performance is rather sensitive to the quality, and mixing different LLMs often lowers the average quality». Есть последовательный вариант со скользящим окном.
   **Механизм, который можно взять:** «мозолистое тело» как синтезатор нумерованных ответов; Self-MoA — прямой аналог наших копий Claude.
   **Куда у нас:** HIVE. **Цена:** малая (у нас уже есть). **Оговорка:** выигрыш показан на открытых текстах с LLM-судьёй, не на числах с кодовой правдой. Self-MoA работает, только если выборки различаются, а PRED-01 показывает, что у нас они совпадают. На числовых прогнозах LLM-агрегатор не лучше медианы (п. 12, 13).

5. **dinobby/ReConcile** (https://github.com/dinobby/ReConcile) — README прочитан, + код `utils.py`; 207 звёзд, MIT. «Круглый стол» из разных LLM; итог — голосование, взвешенное перекалиброванной уверенностью.
   **Механизм, который можно взять (по коду):** `trans_confidence`: ≤ 0,6 → 0,1; (0,6; 0,8) → 0,3; [0,8; 0,9) → 0,5; [0,9; 1) → 0,8; 1 → 1. Вес ответа — сумма перекалиброванных уверенностей голосовавших за него (`certainty_vote[answer] += …`), побеждает максимум. Ступенька резко обесценивает «0,9» — ручная поправка на переуверенность. Альтернатива без самооценок — **Toloka/crowd-kit** (README прочитан; 254 звезды, Apache-2.0): Dawid–Skene, Wawa, GLAD, MACE оценивают надёжность голосующих по согласию на многих задачах.
   **Куда у нас:** совет (голоса 4 ролей), HIVE. **Цена:** малая. **Оговорка:** пороги авторы подобрали вручную. По сниппету «Consensus is Not Verification» (2026) самоотчётная уверенность LLM следует за ожидаемым согласием, а не за правильностью, поэтому у одинаковых голов вес по уверенности усилит общую ошибку. Отображение лучше подобрать изотонически по нашей кодовой правде.

6. **SALT-NLP/DyLAN** (https://github.com/SALT-NLP/DyLAN) — README прочитан, + код `code/MMLU/LLMLP.py`, `LLM_Neuron.py`, `llmlp_listwise_mmlu.py`; 215 звёзд, MIT; COLM 2024. Многораундовая сеть агентов, где команда отбирается по «важности агента» без разметки. По README: +13,0 % на MATH и +13,3 % на HumanEval к одиночному GPT-3.5-turbo; отбор команды — до +25,0 % на отдельных предметах MMLU.
   **Механизм, который можно взять (по коду):** агент следующего раунда ставит каждому предшественнику оценку 1–5 (разбор `[[…]]`), оценки нормируются в веса рёбер с суммой 1. Обратный проход: вес 1 делится поровну между агентами последнего раунда, чей ответ совпал с *итоговым ответом системы* (`llmlp.backward(res)`, не с правдой), и течёт назад: `importance += edge.weight * successor.importance`. Затем усреднение по вопросам даёт ранжирование ролей. Ранний останов — когда согласных больше ⌊2/3·n⌋.
   **Куда у нас:** совет, HIVE (отбор ролей). **Цена:** средняя (n² оценок за раунд). **Оговорка:** важность меряется относительно консенсуса, а не правды, и у одинаковых голов становится самоподтверждением. Раз у нас есть кодовая правда, честнее п. 10–11.

7. **karpathy/llm-council** (https://github.com/karpathy/llm-council) — README прочитан, + код `backend/council.py`; ≈ 25 тыс. звёзд. Автор называет проект «99% vibe coded» и поддерживать его не будет. Три стадии: независимые ответы → каждая модель ранжирует обезличенные ответы остальных → председатель синтезирует итог.
   **Механизм, который можно взять (по коду):** ответы помечаются «Response A/B/C…», соответствие метки и модели хранится отдельно. Ранжирование — в жёстком формате «FINAL RANKING: 1. Response C …» с разбором регуляркой; итог — средний ранг по рецензентам. Академический вариант — **machine-theory/lm-council** (README прочитан; 323 звезды; NAACL 2025): 20 моделей судят друг друга. По сниппету «разделимость» рейтинга у совета 90,5 %, у отдельного судьи в среднем 53,3 %.
   **Куда у нас:** совет, судьи. **Цена:** малая. **Оговорка:** обезличивание гасит предпочтение «своих» только между разными моделями; у копий Claude стиль один и узнавание неизбежно. Средний ранг не мерит правоту.

### Агрегация интервалов и веса по прошлой точности

8. **hubverse-org/hubEnsembles** (https://github.com/hubverse-org/hubEnsembles) — README прочитан, + код `R/simple_ensemble.R`, `R/linear_pool.R`; 8 звёзд, MIT; стандартные ансамбли эпидемиологических хабов прогнозов. `simple_ensemble` даёт взвешенное среднее или взвешенную медиану на каждом уровне квантиля (квантильное усреднение). `linear_pool` даёт смесь распределений: квантили каждой модели интерполируются и экстраполируются в функцию распределения (`distfromq::make_q_fn`), из каждой берётся выборка (по умолчанию 1e4), квантили считаются по объединённой выборке.
   **Механизм, который можно взять:** при равном бюджете сравнить агрегаторы 80 % интервалов трёх голов в лог-шкале: медиану нижних и верхних границ (наш текущий вариант), квантильное среднее и линейный пул. Линейный пул расширяет интервал, когда головы расходятся, квантильное среднее — нет (по памяти: Lichtendahl, Grushka-Cockayne, Winkler 2013 — квантильное среднее острее линейного пула). То же есть в **OakleyJ/SHELF** (README прочитан; 23 звезды, GPL): `fitdist` по квантилям, `linearPool` с весами.
   **Куда у нас:** HIVE, CALIB. **Цена:** малая (в Python — десятки строк). **Оговорка:** у одинаковых голов все агрегаторы совпадают. Для интерполяции нужны хотя бы 10-й, 50-й и 90-й процентили; хвосты за пределами интервала придётся задавать предположением.

9. **ryantibs/quantgen** (https://github.com/ryantibs/quantgen) — README прочитан; 16 звёзд. Квантильные ансамбли с весами, минимизирующими взвешенный интервальный балл (WIS) на прошлых данных; опция `tau_groups` даёт отдельные веса центру и хвостам; задача сводится к линейной программе (GLPK или Gurobi). По сниппету применялся в ансамбле COVID-19 Forecast Hub.
   **Механизм, который можно взять:** веса голов или вариантов промпта = argmin суммарного интервального балла на обучающих задачах с кодовой правдой (веса ≥ 0, сумма 1), отдельно для нижней и верхней границ.
   **Куда у нас:** HIVE, CALIB. **Цена:** малая (`scipy.optimize.linprog`). **Оговорка:** при 3 головах и десятках задач веса переобучатся — нужна проверка на отложенных задачах. У одинаковых голов веса не определены.

10. **grongen/anduryl** (https://github.com/grongen/anduryl) — README прочитан, + код `anduryl/core/experts.py`; 7 звёзд, GPL-3.0. Классическая модель Кука для экспертных оценок: эксперты дают квантили на контрольных вопросах с известным ответом, веса ставятся по калибровке и информативности.
    **Механизм, который можно взять (по коду):** калибровка = `1 − chi2cdf(2·N·MI·calpower, df = число корзин − 1)` (calpower — множитель «силы» калибровки), где MI — относительная энтропия долей попаданий правды в межквантильные корзины к ожидаемым долям (для 10/50/90 это 0,1/0,4/0,4/0,1). Информативность считается относительно фоновой меры на диапазоне. Вес = калибровка × информативность и обнуляется при калибровке < α. Переуверенная голова получает калибровку около нуля и выбывает — ровно та переуверенность, что в FermiEval. По сниппету веса по качеству лучше равных в 32 из 33 исследований (на обучающих данных).
    **Куда у нас:** CALIB, HIVE (отбор голов и промптов). **Цена:** малая (≈ 50 строк numpy; правда у нас есть). **Оговорка:** χ²-тесту нужны десятки контрольных задач на голову. Вес достаётся варианту промпта, а не «голове»; у одинаковых голов веса равны.

11. **mkim425/modelimportance** (https://github.com/mkim425/modelimportance) — README прочитан; 2 звезды, MIT; статья 2026 года — сниппет. Важность участника ансамбля = насколько ухудшается балл ансамбля без него. Два алгоритма: «leave-one-model-out» и «leave-all-subsets-out» (значение Шепли); формат прогнозов — квантили hubverse. По README пакет находит участников, слабых поодиночке, но полезных ансамблю.
    **Механизм, который можно взять:** вклад головы или роли = разность интервальных баллов ансамбля с ней и без неё; при 3–4 головах Шепли считается полным перебором подмножеств.
    **Куда у нас:** HIVE, совет, PRED. **Цена:** малая. **Оговорка:** пакет на R. У одинаковых голов вклад каждой ≈ 0 — это и есть численная мера PRED-01, её стоит считать.

12. **No-Stream/nostreambot-metaculus-bot** (https://github.com/No-Stream/nostreambot-metaculus-bot) — README прочитан; 7 звёзд. Бот Metaculus из нескольких LLM. Бинарные вопросы агрегируются медианой; в числовых перцентили каждой модели превращаются в полное распределение и берётся поточечная медиана функций распределения. Цитата: «A stacker, a model that rewrites the forecast when the three disagree, is in the code but off in production. In an 88-question test it scored no better than the median.» Ещё одна: «the worst misses come with all three models agreeing on a shared briefing». На 09.09.2026 — 15-е место из 277 (README). Каркас **Metaculus/forecasting-tools** (README прочитан; 83 звезды, MIT) агрегацию в README не описывает; по сниппету там медиана для бинарных вопросов, нормированная медиана для выбора из вариантов, смесь распределений для числовых.
    **Механизм, который можно взять:** поточечная медиана функций распределения как агрегатор интервалов; готовый отрицательный результат «LLM-стекер не лучше медианы»; наблюдение, что худшие промахи случаются при согласии всех на общих входных данных.
    **Куда у нас:** HIVE (мозолистое тело против медианы), PRED. **Цена:** малая. **Оговорка:** 88 вопросов без интервала эффекта; прогнозы событий, а не счётные величины.

13. **dannyallover/llm_forecasting** (https://github.com/dannyallover/llm_forecasting; Halawi et al. 2024) + **forecastingresearch/aggutils** (https://github.com/forecastingresearch/aggutils) — README прочитаны, + код `llm_forecasting/ensemble.py`, `R/agg.R`; 62 и 4 звезды. У Halawi базовые прогнозы дают разные модели (`gpt-4-1106-preview`, `claude-2.1`), у каждой свои шаблоны рассуждения, температура 1,0. Агрегаторы: среднее (по умолчанию), медиана, взвешенное среднее и «meta» (LLM синтезирует рассуждения). Функция «нормированного взвешенного усечённого среднего» вдвое уменьшает вес прогноза, дальше всех отстоящего от медианы; в файле она есть, но основной поток её не вызывает. В статье лучшим оказалось усечённое среднее (сниппет). aggutils (Forecasting Research Institute): `trim`; `hd_trim` — среднее внутри кратчайшего интервала, содержащего долю (1 − p) прогнозов; `soften_mean`; `geoMeanOfOddsCalc`; `neymanAggCalc` — среднее лог-шансов, умноженное на d = n(√(3n² − 3n + 1) − 2)/(n² − n − 1).
    **Механизм, который можно взять:** робастные агрегаторы точечной оценки в лог-шкале (`hd_trim`, половинный вес выброса); среднее лог-шансов с экстремизацией для вероятностей членов совета.
    **Куда у нас:** HIVE, совет, CALIB. **Цена:** малая. **Оговорка:** экстремизация предполагает, что у экспертов независимая информация. По формуле для n = 3 d ≈ 1,42 (мой расчёт), и у одинаковых голов это чистая ложная уверенность. Наши величины — числа, а не вероятности: для них лог-шкала, не шансы.

### Калибровка и мера неопределённости

14. **yromano/cqr** (https://github.com/yromano/cqr) — README прочитан; 316 звёзд, MIT; Romano, Patterson, Candès 2019. Конформализованная квантильная регрессия — обёртка над любым готовым предсказателем нижнего и верхнего квантиля.
    **Механизм, который можно взять:** на калибровочных задачах E_i = max(lo_i − y_i, y_i − hi_i) (у нас в логарифмах); Q — ⌈(n + 1)(1 − α)⌉-я порядковая статистика E; новый интервал [lo − Q, hi + Q], то есть обе границы домножаются и делятся на e^Q. Q может быть отрицательным — тогда интервал сужается. Покрытие гарантировано на конечной выборке, если задачи перестановочны. По сниппету FermiEval такая поправка вернула покрытие 99 % и снизила балл Винклера на 54 %. Несимметричный вариант с отдельными поправками границ — по памяти. Готовая реализация — MAPIE `ConformalizedQuantileRegressor(prefit=True)` (сниппет документации). Онлайн-вариант — адаптивный конформный вывод Gibbs & Candès, α_{t+1} = α_t + γ(α − промах_t) (по памяти).
    **Куда у нас:** CALIB, HIVE (после агрегации). **Цена:** малая (≈ 10 строк). **Оговорка:** гарантия действует только при перестановочности, поэтому калибровочные задачи должны быть из тех же семейств и размеров, что тестовые; одно Q на все семейства даст плохое условное покрытие. Поправка — надстройка кодом, а не свойство голов: вопрос «калибруются ли сами головы» мерить отдельно, до поправки.

15. **epiforecasts/scoringutils** (https://github.com/epiforecasts/scoringutils) + **uncertainty-toolbox/uncertainty-toolbox** + **EFS-OpenSource/calibration-framework** (netcal) — README прочитаны, + код `R/metrics-interval-range.R` scoringutils; 64 звезды, 2 тыс., 380. scoringutils: `interval_score` = (upper − lower) + 2/α·(lower − obs)·1(obs < lower) + 2/α·(obs − upper)·1(obs > upper); по умолчанию `weigh = TRUE` умножает балл на α/2 (для WIS); `separate_results` раскладывает балл на ширину, недопрогноз и перепрогноз; `transform_forecasts` переводит в лог-шкалу; есть покрытие интервалов. uncertainty-toolbox: калибровка (miscalibration area, adversarial group calibration), интервальный балл, изотоническая перекалибровка (Kuleshov et al.); прогноз предполагается гауссовым (среднее + σ). netcal для регрессии: variance scaling, isotonic, GP-Beta; метрики PICP, QCE, ENCE, UCE.
    **Механизм, который можно взять:** вторая независимая реализация нашей меры: с `weigh = FALSE` и α = 0,2 получается «ширина + 10 × промах». Разложение балла показывает, что перед нами — переуверенность или систематический сдвиг.
    **Куда у нас:** CALIB, HIVE. **Цена:** малая. **Оговорка:** scoringutils на R. Гауссово допущение toolbox не подходит к несимметричным интервалам без перевода в лог-шкалу.

16. **IINemo/lm-polygraph** (https://github.com/IINemo/lm-polygraph) — README прочитан; 509 звёзд, MIT. Библиотека оценок неопределённости LLM. Чёрный ящик (нужны только выборки ответов): NumSets (число семантических классов), EigV (сумма собственных значений лапласиана графа сходства), Deg, Ecc, LexSim, Kernel Language Entropy, вербальная уверенность 1S/2S. Работает с OpenAI-совместимыми API (`BlackboxModel.from_openai`).
    **Механизм, который можно взять:** неопределённость из разброса N ответов как сигнал «расширить интервал» или «позвать совет».
    **Куда у нас:** CALIB, PRED. **Цена:** средняя (нужна адаптация под числа и под Claude). **Оговорка:** чёрно-ящичным мерам нужен разброс выборок. При совпадении «цифра в цифру» (PRED-01) они покажут нулевую неопределённость даже на промахах. Методы по логитам субагентам Claude недоступны.

### Судьи без смещений

17. **lm-sys/FastChat**, модуль `fastchat/llm_judge` (https://github.com/lm-sys/FastChat) + **lmarena/arena-hard-auto** + **cambridgeltl/PairS** — у FastChat прочитан код `common.py` и `show_result.py`; у arena-hard-auto — README и `show_result.py` (1,1 тыс. звёзд, Apache-2.0); у PairS — README (49 звёзд, MIT). FastChat судит пару дважды, во второй раз с переставленными ответами (`play_a_match_pair`). В итоге: `if row["g1_winner"] == "tie" or row["g1_winner"] != row["g2_winner"]` → ничья, то есть победа засчитывается только при согласии обеих очерёдностей. В Arena-Hard на пару приходится два суждения, одно из них инвертируется (1 − s); шкала A>>B / A>B / A=B, сильное предпочтение весит 3. PairS при `calibrate: True` усредняет вероятности обеих перестановок A/B и сортирует слиянием по попарным сравнениям.
    **Механизм, который можно взять:** «обе очерёдности; расхождение = ничья» — стандарт для любого судьи Claude; доля расхождений сразу даёт меру позиционного смещения.
    **Куда у нас:** судьи, совет (при выборе между вариантами). **Цена:** малая (вызовов вдвое больше). **Оговорка:** от смещений по длине и в пользу «своего» не спасает. PairS нужны вероятности, а у субагентов есть только вербальные.

18. **tatsu-lab/alpaca_eval** (https://github.com/tatsu-lab/alpaca_eval), LC win rate, + контроль стиля в **lmarena/arena-hard-auto** — README alpaca_eval и код `show_result.py` arena-hard-auto прочитаны; 2,0 тыс. звёзд. LC: логистическая регрессия предпочтения судьи по трём признакам — инструкция, модель, разность длин; итог — контрфактическое предсказание при нулевой разности длин. Корреляция Спирмена с Chatbot Arena выросла с 0,93 до 0,98. Когда базовую модель просят писать подробнее, её обычный win rate растёт с 50 % до 64 %; LC-метрика эту уязвимость снижает (README). В Arena-Hard в регрессию Брэдли–Терри вместе с индикаторами моделей входят признаки стиля: разность длин (a − b)/(a + b) и разность плотности markdown-элементов, после стандартизации.
    **Механизм, который можно взять:** регрессией оценить знак и величину эффекта длины у наших судей (в HUMOR-01 они выбирали короткое) и выдать «рейтинг при равной длине».
    **Куда у нас:** судьи. **Цена:** малая. **Оговорка:** регрессия отделяет связь с длиной, но причины не доказывает: короткие шутки могли быть действительно лучше. Для причины нужен п. 19.

19. **Y0oMu/LLM-Judge-Bias-Dataset** (https://github.com/Y0oMu/LLM-Judge-Bias-Dataset; CALM, «Justice or Prejudice?», ICLR 2025) — README прочитан; 4 звезды. 12 смещений судьи: позиция, многословие, «своё», авторитет, стадность, CoT, отвлечение и другие. Для многословия поле `answer2_longer` — тот же ответ, раздутый избыточным текстом без изменения фактов. Смежное: **aangelopoulos/ppi_py** (README прочитан; 301 звезда, MIT) — prediction-powered inference, `ppi_mean_ci(Y, Yhat, Yhat_unlabeled, alpha)`: поправляет оценку по судье малой выборкой с правдой и даёт честный доверительный интервал.
    **Механизм, который можно взять:** пертурбационный тест — один и тот же ответ в двух длинах; доля сменившихся вердиктов даёт причинную меру смещения. PPI — когда правда есть только на части задач.
    **Куда у нас:** судьи. **Цена:** средняя (пары надо строить). **Оговорка:** в юморе раздувание меняет и качество, ведь краткость — часть шутки. Для чистого теста длины нужны содержательно пустые вставки или пары, которые люди признали равными.

## Топ-5 взять в работу

1. **Конформное расширение интервалов в лог-шкале (п. 14) и вторая реализация меры (п. 15) → CALIB, HIVE.** Штраф 10× за промах делает переуверенность главным источником потерь, и в FermiEval (сниппет) конформная поправка вернула номинальное покрытие. Цена — ≈ 10 строк плюс разбиение задач по семействам; scoringutils с `weigh = FALSE` проверяет наш балл вторым способом. Отчитываться «до» и «после» поправки отдельно.
2. **Веса голов и промптов по классической модели Кука (п. 10) и по минимуму WIS (п. 9) → CALIB, HIVE.** Правда у нас есть кодом — ровно те «контрольные вопросы», под которые модель Кука придумана. Переуверенные варианты отсекаются формальным тестом, а не на глаз. Цена малая; обязательна проверка на отложенных задачах.
3. **Турнир агрегаторов при равном бюджете (п. 8, 12, 4, 13) → HIVE.** Медиана границ, квантильное среднее, линейный пул, поточечная медиана функций распределения, hd-усечённое среднее, мозолистое тело. Внешние данные предсказывают, что LLM-агрегатор не лучше медианы (nostreambot, 88 вопросов; у Halawi лучшим было усечённое среднее), а линейный пул выигрывает, когда головы расходятся. Если ответы голов сохранены, сравнение можно пересчитать без новых вызовов — но как пост-хок, который вердиктов не меняет; для вывода нужна новая предрегистрация.
4. **Разнообразие без смены модели (п. 1–3; асимметрия входов — сниппет, см. ниже) → PRED.** Verbalized Sampling с выборкой из всего распределения; разный обязательный метод решения у каждой головы (DMAD); разные входные данные у разных голов. Успех мерить не разбросом ответов, а корреляцией *ошибок* по кодовой правде и вкладом по Шепли (п. 11). Цена малая, а ответ на этот вопрос — условие пользы всех остальных пунктов.
5. **Судья без смещений (п. 17–19) → судьи, совет.** Обе очерёдности с ничьей при расхождении, регрессия на длину, пертурбационный тест. Цена — ×2 вызовов и десятки строк. Это нужно каждой будущей постановке с судьёй-Claude и покажет, было ли «предпочтение краткости» в HUMOR-01 причинным.

**Главная оговорка.** Почти все механизмы рассчитаны на голов с частично независимыми ошибками. Для копий Claude на одном промпте (PRED-01) взвешивание, пулы, Шепли и экстремизация ничего не добавляют, а экстремизация вредна. Сначала нужно получить и *доказать* декорреляцию ошибок, и только потом агрегировать.

## Чего не нашёл

- **Кода у свежих работ 2026 года** — везде только сниппет, но выводы стоит учесть:
  - InfoDelphi, «Diverse Evidence, Better Forecasts» (arXiv 2607.01661): при одинаковых данных делиберация вырождается в стадность; разделение данных на общие и частные подмножества снижает корреляцию ошибок; Брайер лучше на 12–18 %; без асимметрии выигрыш почти исчезает.
  - «Diversity is the Strength of the AI Crowd» (2606.29661): фронтирные LLM дают сильно коррелированные прогнозы; лучшие ансамбли — точные, но разнородные.
  - «Diverse by Reasoning» (2608.24001): модели кластеризуются по следам рассуждений на тренировочных задачах; три медоида лучше голосования всех 25 моделей при −88 % вызовов.
  - «Consensus is Not Verification» (2603.06612): опросные стратегии «мудрости толпы» не дают устойчивого прироста правдивости даже при 25-кратной цене; самоотчётная уверенность следует за ожидаемым согласием.
  - «Are Diversity Metrics Measuring Diversity?» (2607.20768): голосование трёх моделей лучше лучшей из них лишь в 9,98 % подмножеств.
  - Douven, «Wisdom of LLM Crowds» (2607.18269): обученный логистический агрегатор лучше классических; загрязнение данных до даты отсечки искажает сравнения.
  - Consilience (2608.20564): конформная калибровка управления дискуссией агентов со скрытыми данными.
- **Официального кода String Seed of Thought** (Misaki, Akiba; arXiv 2510.21150, ICLR 2026): сначала сгенерировать случайную строку, потом детерминированно вывести из неё ответ. Метод — сниппет; есть лишь сторонний прототип с 0 звёзд (nshkrdotcom/anti_agents, README прочитан).
