## Находки

1. **google-deepmind/funsearch** (https://github.com/google-deepmind/funsearch). Статус: README прочитан, + код `implementation/programs_database.py` и `config.py`; 1,1 тыс. звёзд. Эволюционная часть FunSearch. По README, в репозитории нет LLM, песочницы и распределённой инфраструктуры.
   - **Механизм, который можно взять.**
     - Острова периодически сбрасываются: код сбрасывает «слабую половину» островов по лучшему баллу (ничьи разбиваются шумом 1e-6). Каждый сброшенный остров получает основателя — лучшую программу случайного выжившего острова. По умолчанию 10 островов, сброс раз в 4 ч.
     - Внутри острова программы собираются в кластеры по «подписи» — вектору баллов по каждому тестовому входу. Кластер выбирается софтмаксом по баллу. Температура падает линейно от 0,1 до 0 и возвращается к началу каждые 30 000 программ. Внутри кластера чаще выбирается более короткая программа.
     - В промпт идут 2 прежние версии, упорядоченные по возрастанию балла (`_v0`, `_v1`).
   - **Куда у нас.** HIVE-02.
     - Это ближайший кодовый аналог нашего падения.
     - «Подпись» улья — вектор баллов по 4 семействам. Ульи с одинаковой подписью считать одним видом; при равных баллах предпочитать более короткий свод законов. Это дешёвое давление против разрастания законов (TextReg, отчёт A № 18).
     - Мутатору показывать 2 прежние версии законов по возрастанию балла.
   - **Цена.** Малая.
   - **Оговорка.** У них острова живут изолированно, а сброс идёт по таймеру, а не по ёмкости среды. При 3 вопросах на семейство подпись очень шумная, её надо огрублять, например до рангов.

2. **jennyzzt/dgm** (https://github.com/jennyzzt/dgm) — известен. Статус: README прочитан, + код `DGM_outer.py`; 2,4 тыс. звёзд. Код Darwin Gödel Machine.
   - **Механизм, который можно взять.**
     - Выбор родителя (`score_child_prop`, по умолчанию): p ∝ σ(10·(балл − 0,5)) · 1/(1 + число детей). Так чаще выбираются сильные агенты, у которых ещё мало потомков.
     - Ступенчатая проверка: сначала малый набор задач; если балл ≥ 0,4 — средний набор; полный набор — только если балл не ниже второго лучшего в архиве.
     - Режим архива `keep_better`: потомок входит в архив, если его балл ≥ балла *исходного* агента − 0,1 (`noise_leeway`). По умолчанию стоит `keep_all`: архив хранит всех.
     - Родословная хранится как `parent_commit` и список детей.
   - **Куда у нас.** Следующая версия HIVE-02, если делиться будут не все ульи, а выбранные. DUEL-01 — принятие новых заметок-стратегий.
     - Штраф за число детей не даёт одной линии захватить популяцию.
     - Ступенчатая проверка потомков: сначала 4 вопроса (по одному на семейство), потом полная партия.
     - Допуск на шум — относительно основателя.
   - **Цена.** Малая.
   - **Оговорка.** Наш балл — логарифмический интервальный, чем меньше, тем лучше. Сигмоиду надо ставить на ранги или на разность с эталонным ульем. В нынешнем HIVE-02 при изобилии живут все, и ступенчатая проверка этому замыслу противоречит.

3. **SakanaAI/ShinkaEvolve** (https://github.com/SakanaAI/ShinkaEvolve). Статус: README и `docs/configuration.md` прочитаны; формула выбора родителя — сниппет статьи; 1,4 тыс. звёзд. Открытый аналог AlphaEvolve.
   - **Механизм, который можно взять.**
     - (а) Родитель выбирается с вероятностью p ∝ s·h, где s = σ(λ·(F − медиана F)) и h = 1/(1 + N детей). По умолчанию λ = 10.
     - (б) Почти-копии отбраковываются. Если сходство потомка с кем-то на острове выше 0,99 (`code_embed_sim_threshold`, по эмбеддингам изменяемой части), LLM-судья решает, ново ли это. На поколение даётся до 3 попыток (`max_novelty_attempts`).
     - (в) LLM-мутатор выбирает бандит (`ucb`, `ucb1` или `thompson`) с поправкой на цену (`cost_aware_coef` 0,5).
     - (г) Каждые 10 поколений мета-LLM даёт до 5 рекомендаций по архиву.
     - (д) `max_api_costs` — потолок в долларах; после него новые задания не отправляются.
     - (е) Островов по умолчанию 2, миграция выключена (`migration_rate` 0,0). При застое в 100 поколений заводится новый остров. Родословная хранится в базе и видна в веб-интерфейсе.
   - **Куда у нас.**
     - HIVE-02: после мутации считать кодом сходство нового свода с родителем и с живыми ульями (difflib или Жаккар по словам). Если порог превышен — просить мутатора ещё раз, не больше 3 раз.
     - HIVE-02: бандитом выбирать оператор мутации (обычная мутация, DE из № 8, рефлексия из № 9). Награда — «потомок лучше родителя» минус цена вызовов.
     - Инфраструктура: жёсткий потолок вызовов в `run_queue.sh`. Похожая формула полезности с ценой есть у SICA (MaximeRobeyns/self_improving_coding_agent; README прочитан, 403 звезды; формула — сниппет): U = 0,5·балл + 0,25·(1 − min(1, цена/$10)) + 0,25·(1 − min(1, время/300 с)).
   - **Цена.** Малая.
   - **Оговорка.** У голов Claude Code нет эмбеддингов, остаётся только кодовая мера сходства текста. LLM-судья новизны — это Claude, судящий Claude (урок HUMOR-01). Что отбраковка сильно лучше её отсутствия, известно только из сниппета статьи.

4. **algorithmicsuperintelligence/openevolve** (https://github.com/algorithmicsuperintelligence/openevolve). Статус: README и `configs/default_config.yaml` прочитаны; 7,4 тыс. звёзд. Открытая реализация AlphaEvolve.
   - **Механизм, который можно взять.**
     - MAP-Elites: сетка по признакам (`feature_dimensions`: complexity, diversity; по 10 корзин), в каждой клетке хранится лучший.
     - 5 островов, миграция по кольцу раз в 50 поколений; мигрирует 10 % лучших.
     - Элитный архив на 100 программ; доли выбора: эксплуатация 0,7, разведка 0,2.
     - Каскадная проверка с порогами [0,5; 0,75; 0,9].
     - Ранняя остановка: `early_stopping_patience` (по умолчанию выключена), `convergence_threshold` 0,001.
     - В промпт идут 3 лучшие и 2 непохожие программы. Шаблон промпта случайно варьируется. Ошибки выполнения («артефакты») возвращаются в промпт.
     - Фильтр сходства 0,99; сид 42 для воспроизводимости.
     - Та же сетка есть в CarperAI/OpenELM (README прочитан, 747 звёзд): MAP-Elites, CVT-MAP-Elites, Deep Grid MAP-Elites и среда QDAIF, где признаки разнообразия оценивает LLM.
   - **Куда у нас.** HIVE-02.
     - Архив элиты по кодовым признакам свода законов (число законов × длина), чтобы при усечении до 3 не терять непохожие своды.
     - Мутатору давать 3 лучших и 2 непохожих свода как «вдохновение».
     - 2–3 острова ульев с кольцевой миграцией — отдельная рука против boom–bust.
   - **Цена.** Средняя.
   - **Оговорка.** При ≤ 12 ульях сетка почти пуста. Признаки должны быть только кодовыми: признаки QDAIF от LLM — снова Claude, судящий Claude.

5. **FoundationAgents/AFlow** (https://github.com/FoundationAgents/AFlow). Статус: README прочитан, + код `scripts/optimizer_utils/data_utils.py` и `convergence_utils.py`; 603 звезды. Поиск рабочих процессов методом MCTS по коду.
   - **Механизм, который можно взять.**
     - Раунд для расширения выбирается с вероятностью P = λ·(равномерная) + (1 − λ)·софтмакс(α·(s − s_max)) среди лучших. Исходный вариант всегда входит в кандидаты. В коде α = 0,2, λ = 0,3.
     - Каждый процесс проверяется 5 раз (`validation_rounds`).
     - Остановка (`check_convergence`): среднее трёх лучших меняется не больше чем на z·σ пять раундов подряд. σ берётся из разброса повторных проверок, по умолчанию z = 0. Предел — 20 раундов.
   - **Куда у нас.**
     - HIVE-02: при выборе родителей подмешивать 30 % равномерного выбора, чтобы сохранять слабые линии.
     - Будущие опыты без заранее заданного числа поколений: правило остановки по стандартной ошибке.
   - **Цена.** Малая.
   - **Оговорка.** По сниппету «The Illusion of Multi-Agent Advantage» (arXiv 2606.13003), 7 из 14 итоговых процессов AFlow выродились в «один промпт трижды + агрегация», то есть по сути в CoT-SC.

6. **gepa-ai/gepa** (https://github.com/gepa-ai/gepa) и `dspy.GEPA` — известен. Статус: README прочитан, + код `src/gepa/proposer/merge.py`, `src/gepa/gepa_utils.py`, `dspy/teleprompt/gepa/gepa.py`; 6,7 тыс. звёзд.
   - **Механизм, который можно взять.**
     - (а) Парето по примерам. Для каждого проверочного примера берётся множество лучших кандидатов, доминируемые удаляются. Родитель выбирается с вероятностью, пропорциональной числу примеров, где он среди лучших.
     - (б) Слияние (`use_merge`, до 5 раз). Берутся два кандидата с общим предком, который не лучше каждого из них. Каждый модуль берётся у того потомка, который его изменил относительно предка; если изменили оба — у лучшего. Опробованные тройки (i, j, предок) запоминаются и не повторяются. Слитый кандидат принимается, если на подвыборке он не хуже лучшего из родителей.
     - (в) Рефлексия идёт на мини-партиях по 3 примера (`reflection_minibatch_size`) из trainset, а Парето считается по valset. Документация предупреждает: если оба дела делать на одном наборе, промпт переобучится.
   - **Куда у нас.** HIVE-02.
     - При падении брать не «3 лучших по среднему», а Парето по 4 семействам: улей выживает, если он лучший хотя бы в одном семействе. Остаток мест добирать по среднему.
     - Скрещивание делать кодом, без вызова LLM. Законы, которые изменил каждый из двух потомков одного предка, переносятся в свод предка; при конфликте берётся вариант лучшего потомка.
     - Родословная для этого уже есть: поле `parents` в `state.json`.
   - **Цена.** Малая.
   - **Оговорка.** При 3 вопросах на семейство Парето шумный; баллы линии надо копить за несколько поколений.

7. **ShengranHu/ADAS** (https://github.com/ShengranHu/ADAS). Статус: README прочитан, + код `_mmlu/search.py` и `_mmlu/utils.py`; 1,6 тыс. звёзд. Meta Agent Search.
   - **Механизм, который можно взять.**
     - Мета-агент получает архив всех найденных агентов целиком: код, мысль, поколение, пригодность.
     - Пригодность передаётся строкой «95% Bootstrap Confidence Interval: (…%, …%), Median: …%» (100 000 бутстреп-выборок).
     - После предложения идут 2 раунда саморефлексии; ошибки чинятся за `debug_max` попыток.
     - Агенты с точностью < 1 % в архив не попадают.
   - **Куда у нас.** HIVE-01 и мутатор HIVE-02.
     - В обратной связи давать не точечный балл, а бутстреп-интервал разности с эталонным ульем по вопросам поколения.
     - Мутатору давать архив всех испробованных сводов, включая `graveyard`, с их интервалами.
   - **Цена.** Малая.
   - **Оговорка.** По сниппету той же статьи 2026 года, ADAS входит в число систем, которые проигрывают CoT-SC при равном бюджете. Поможет ли головам интервал — не проверено.

8. **beeevita/EvoPrompt** (https://github.com/beeevita/EvoPrompt) — известен. Статус: README прочитан, + `data/template_de.py`; 253 звезды. Генетический алгоритм (GA) и дифференциальная эволюция (DE) над промптами.
   - **Механизм, который можно взять.**
     - DE-оператор умещается в один промпт: «1) найди различающиеся части промптов 1 и 2; 2) случайно мутируй их; 3) выборочно вставь их в промпт 3 (лучший); 4) скрести результат с базовым».
     - GA: скрестить два промпта, затем мутировать.
     - Отбор (`sel_mode`): рулетка, турнир или случайный.
     - В DE потомок заменяет родителя, только если он лучше.
   - **Куда у нас.** HIVE-02: второй оператор мутатора. DE — это разность сводов двух ульев, применённая к лучшему своду; рядом с нынешними «одной-двумя мутациями».
   - **Цена.** Малая.
   - **Оговорка.** На тексте DE часто даёт простую перефразировку, поэтому его стоит сочетать с отбраковкой почти-копий (№ 3). Результат обязан проходить кодовый фильтр.

9. **ai4co/reevo** (https://github.com/ai4co/reevo). Статус: README прочитан, + код `reevo.py`; 302 звезды. Рефлексивная эволюция эвристик (NeurIPS 2024).
   - **Механизм, который можно взять.**
     - Краткосрочная рефлексия идёт на парах с разным баллом; пары с равным баллом пропускаются. LLM видит лучшее и худшее решение и пишет, чем хуже худшее. Эту рефлексию получает скрещивание.
     - Долгосрочная рефлексия переписывается каждое поколение: прежняя сливается с новыми краткосрочными.
     - Мутирует только элита, по долгосрочной рефлексии. Элита сохраняется всегда.
   - **Куда у нас.**
     - HIVE-01: поправки строить из пар «лучшая и худшая голова на одном вопросе». Свод законов переписывать как долгосрочную рефлексию, с явным шагом слияния.
     - HIVE-02: мутатору давать общую долгосрочную рефлексию по всем ульям.
   - **Цена.** Малая.
   - **Оговорка.** У них правильность проверяется запуском кода. Если переписывать свод целиком, он может дрейфовать, поэтому кодовый фильтр нужен на каждом шаге.

10. **stanfordnlp/dspy** (https://github.com/stanfordnlp/dspy). Статус: код SIMBA (`dspy/teleprompt/simba.py`, `simba_utils.py`) и `docs/docs/learn/programming/language_models.md` прочитаны на GitHub; сайт dspy.ai закрыт прокси; 38,3 тыс. звёзд.
    - **Механизм, который можно взять.**
      - SIMBA работает мини-партиями по 32 примера; на каждом примере запускаются несколько кандидатов. Примеры сортируются по разбросу результатов: max − min, затем max, затем max − среднее.
      - На самых спорных примерах SIMBA либо добавляет удачный пример, либо пишет правило из сравнения лучшей и худшей траектории («если модуль получает …, то он должен …»). За шаг — 6 кандидатов, всего 8 шагов.
      - Кэш: вызов кэшируется по хешу входа и `rollout_id`. При temperature > 0 другой `rollout_id` даёт новый ответ, тот же — ответ из кэша.
      - `lm.history` хранит usage и cost каждого вызова.
    - **Куда у нас.**
      - HIVE-01: для критики брать вопросы с наибольшим разбросом интервальных баллов голов.
      - Инфраструктура: кэш ответов голов по хешу «полный промпт + номер выборки», чтобы продолжать прогон без повторных вызовов, и журнал цены каждого вызова.
    - **Цена.** Малая.
    - **Оговорка.** Правило SIMBA вида «если вход такой — делай так» по сути предметное, и наш фильтр такие запрещает.

11. **zou-group/textgrad** (https://github.com/zou-group/textgrad). Статус: README прочитан, + код `textgrad/optimizer/optimizer.py`; 3,7 тыс. звёзд.
    - **Механизм, который можно взять.**

      - `gradient_memory` — последние N критик.

    - **Цена.** Малая.
    - **Оговорка.** Ограничения в промпте мягкие; жёсткий барьер — только кодовый фильтр.

12. **metauto-ai/HGM** (https://github.com/metauto-ai/HGM). Статус: README прочитан, + код `hgm.py`; 432 звезды. Huxley–Gödel Machine.
    - **Механизм, который можно взять.**
      - Ценность узла — успех всей клады: Beta(1 + успехи потомков, 1 + неудачи потомков). Узел выбирается сэмплированием Томпсона.
      - По мере расхода бюджета параметры умножаются на растущий множитель («охлаждение»), и эксплуатации становится больше.
      - Нового потомка создают, если (число проверок)^α ≥ числа узлов; иначе уже существующий узел проверяют на новой задаче.
    - **Куда у нас.** HIVE-02.
      - Какая линия получает больше потомков при изобилии, решать по успехам её потомков, а не по баллу самого улья. Успех = улей лучше эталона на вопросе.
      - Правило «создать потомка или перепроверить» делит бюджет между рождением и повторной оценкой.
    - **Цена.** Средняя.
    - **Оговорка.** Нужен бинарный исход; за 6 поколений клада получается мелкой.

## Топ-5 взять в работу
1. **Контроли равного бюджета** (№ 17 llm-eps и № 19 OCCAM со статьёй 2606.13003).
   - Что сделать: в HIVE-02 — улей-восходитель (1+1); в HIVE-01 — «одна голова × 3 выборки + медиана» и нокаут голов.
   - Польза: без этих контролей нельзя отделить эффект популяции и законов от простого восхождения и самосогласования. Две работы 2026 года (сниппеты: 2606.13003; 2609.04217 — см. «Чего не нашёл») говорят, что при равном бюджете структура из агентов не окупается.
   - Цена: одна-две руки, код ответа почти готов.
2. **GEPA** (№ 6).
   - Что сделать: при падении выбирать выживших по Парето по семействам; скрещивать законы кодом через общего предка.
   - Польза: при усечении 12 → 3 отбор по среднему убивает специалистов по семействам. Скрещивание без вызова LLM учитывает родословную.
   - Цена: десятки строк в `hive2_run.py`.
3. **FAPO** (№ 14).
   - Что сделать: голова-рецензент поправок без доступа к правде, память отвергнутого, неизменяемые версии законов.
   - Польза: закрывает щель между регулярным фильтром и пересказом предметного правила — главный путь гудхарта в HIVE-01. FAPO устроен так же, как мы: на подагентах Claude Code.
   - Цена: +1 вызов на поколение.
4. **ShinkaEvolve** (№ 3).
   - Что сделать: отбраковывать почти-копии законов кодовой мерой сходства (до 3 попыток); поставить жёсткий потолок вызовов в очереди.

   - Цена: бутстреп в коде обратной связи.
