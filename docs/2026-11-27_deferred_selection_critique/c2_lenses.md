## Линза 1. Утечка истины и предрешённость исхода

### 1.1. Знак P1 и P2 почти задан механикой ветви FIXED. Вероятность 0,65 отражает в основном риск ничьих, а не риск ошибки модели
- **Что найдено.** При постоянных тестах с элитизмом заявка C не убывает. Элита сменяется только при строгом росте C: `np.argmax` берёт первый максимум, а элита всегда стоит на индексе 0 (`evo01.py`:110, 113; `evo06.py`:80, 93). Значит, C и T меняются только в одних и тех же поколениях. Отсюда:
  - d ≠ 0, только если элита сменилась после 11-го поколения;
  - «поражение» (d < 0) возможно, только если при смене T выросла больше, чем C. Это почти исключительно событие «задача решена»: T и C прыгают к 1, а C до этого была ≥ T.
  - Поэтому знак d > 0 ожидается без всякой М3 — из одного проклятия победителя при сохранённой элите на фиксированной выборке. Проверка не отличает М3 от этой простейшей альтернативы.
- **Ещё одна проблема — определение d.** d > 0 засчитывает и случай, когда отрицательный разрыв просто приближается к нулю. В пилоте FIXED32 T4 s997 C − T идёт −0,033 → −0,027: это засчитано бы как «завышение растёт», хотя заявка там ниже правды.
- **Чем подтверждается.** Расчёт на пилоте EVO-06 функциями скрипта:
  - у всех шести прогонов FIXED32 `min(diff(C)) = 0.0`;
  - поколения смены C совпадают с поколениями смены T: T1 s997 — 3, 12, 18; T4 s997 — 2, 3, 58 и т. д.;
  - `sign_test` пилота: wins 3, losses 0, ties 3;
  - блоки C − T у FIXED32 T4 отрицательны в обоих сидах (вывод `defer01.py pilot`).
- **Уверенность:** 0,85.
- **Что изменить.**
  - Записать эту механику в PREREG §6–7.
  - Разложить вероятность на два множителя: P(n ≥ 10) и P(«подтверждено» | n ≥ 10).
  - «Завышение растёт» определить как рост при W > 0, либо отчитывать отдельно прогоны с W ≤ 0.
  - В §7 записать, что P1 и P2 не отличают М3 от проклятия победителя при сохранённой элите.

## Линза 2. Код `defer01.py`

### 2.1. Самопроверка не ловит ни сдвиг окна, ни перепутанную пару P4, ни потерю ничьих
- **Что найдено.** Я сделал пять копий скрипта с внесённой ошибкой. Все пять проходят `selftest` «10 из 10»:
  1. окна сдвинуты на одно поколение: `(10,39),(120,149)`;
  2. позднее окно выходит за конец: `(122,151)` — срез молча берёт 29 значений;
  3. в P4 переставлены `MIRROR_50` и `MIRROR_100`, знак перевёрнут;
  4. окно без правой границы: `v[lo:hi]`;
  5. счёт ничьих обнулён.
- **Почему так.** Синтетика непрерывная: в ней нет ни ничьих, ни ступеней, как у FIXED. Для P4 синтетика симметрична (разрывы 0,1 и 0,1), поэтому смена знака не меняет «не решено». Допуск медианы 0,01 в пять раз больше эффекта сдвига окна на одно поколение (0,002). P6 и P7 не проверяются вовсе.
- **Чем подтверждается.** Вывод `python3 -I m1.py selftest` … `m5.py`: «самопроверка: 10 из 10 пройдено» у всех пяти.
- **Уверенность:** 0,95.
- **Что изменить.** Добавить синтетику с точным ответом:
  - ступенчатая C − T с известными средними окон и сравнение с допуском 1e-9 — ловит сдвиг на одно поколение;
  - асимметричная доза для P4 (W50 > W100) — ловит знак;
  - заданное число точных ничьих — ловит их счёт;
  - `assert len(hist) == 151`;
  - проверки P6 и P7.

### 2.2. Обещанное в PREREG и посчитанное кодом не совпадает: P7 не считается, у P5 нет правила исхода, P6 судится не по своему правилу

### 2.3. Целостность данных не проверяется; NaN выпадает молча; разности порядка 1e-17 считаются победами и поражениями

- **Что изменить.**

## Линза 3. Проверяемость предсказаний

### 3.1. P1 и P2 не следуют из М3: сама модель говорит, что роста во времени в ней нет
- **Что найдено.**
  - В `deferred_selection_models.md`, строка 71: М3 «описывает установившийся уровень, а не рост разрыва во времени»; строка 165 — то же.
  - Предсказание 2 («копится там, где показатель можно выучить») в форме уровня — FIXED завышает больше, чем SAME — уже известно: C-005, C-024 (85/106).
  - Ставка «d > 0 со временем» приписана модели, а не выведена из неё.
- **Уверенность:** 0,8.
- **Что изменить.** Либо добавить в М3 динамику (например, φ(x_t) с x_t, растущим по силе отбора) и вывести знак и форму d, либо пометить P1 и P2 как «не из М3» и не начислять М3 вес опоры по ним.

### 3.2. Интервалы P7 противоречат формуле модели; отображение q = f/2 не проверено
- **Противоречие с формулой.** По модели D(q)/D(0) = 1 − q·(1 + G)/G ≤ 1 − q при любом G > 0 (строка 93). При q = f/2 верхние границы — 0,875, 0,75 и 0,5.
  - Интервалы P7 — [0,75; 1,0], [0,6; 0,9], [0,3; 0,65]. Их верхние части (0,875–1,0; 0,75–0,9; 0,5–0,65) модель запрещает.
  - Значения ниже интервалов модель разрешает при умеренном G (при G = 1: 0,75, 0,5 и 0).
  - Итог: исход P7 «в интервале» может противоречить модели, а «вне интервала» может с ней согласовываться.
- **Отображение q = f/2.**
  - В MIRROR_0 новые входы всё равно приходят каждое поколение: мутанты `keep ± 5` (`evo03.py`:26).
  - 8 оставляемых тестов отбираются по спорности p(1 − p), а не случайно.
  - Поэтому MIRROR_0 — не «q = 0», а свежие тесты — не «экзамен по правде» М3.
- **Уверенность:** 0,8.
- **Что изменить.**
  - Вывести интервалы из формулы: [1 − q·(1 + G)/G при G из записанного до прогона диапазона; 1 − q] плюс шум, оценённый пилотом.
  - Записать допущение о мутантах как непроверенное.
  - Задать исход при W(MIRROR_0) ≤ 0.

### 3.3. Разные задачи слиты в один тест, и разбивка заранее не задана
- **Что найдено.** Правило CLAUDE.md: «Разные задачи в один тест не сливать. Разбивку по типам задач задавать заранее». Сейчас:
  - P1 сливает T1–T3;
  - P2 сливает T1–T6;
  - P3 и P4 сливают T1–T3.
- **Почему это важно.** Механизм различается по задачам. На T1 и T6 элита часто доходит до T = C = 1, и это даёт ничьи либо «поражения» при решении после 11-го поколения: в PREREG-EVO-06 §3 |C − T| = 0 у 13/20 T1 и 18/20 T6. На T3 элита застревает: в пилоте T3 C−T стоит с 5-го поколения.
- **Уверенность:** 0,85.
- **Что изменить.** Заранее записать разбивку по задачам (хотя бы описательно, с победами/n и медианой по каждой) и правило, что делать, если знаки по задачам расходятся. Как вариант — гладкие (T1, T6) против кусочных (T2–T5), как в EVO-06 §7.3.

### 3.4. Зависимость пар одного сида не учтена ни в тесте, ни в бутстрепе
- **Что найдено.**
  - Постоянные тесты (`default_rng(2·10⁶+seed)`) и скрытая правда (`10⁶+seed`) сидированы без номера задачи (`evo01.py`:79, 81; `evo03.py`:20; `evo06.py`:52, 57). У одного сида T1–T3 (или T1–T6) получают одни и те же 16 (32) входов. В P1 60 прогонов — это 20 независимых наборов постоянных тестов.
  - §8 это упоминает, но знаковая проверка и `boot_ci` (строки 52–55) считают прогоны независимыми. Ложный уровень и ИД занижены.
- **Уверенность:** 0,75.
- **Что изменить.** Первичным сделать тест на уровне сида (по сиду — знак средней по задачам, n = 20) или перестановку и бутстреп кластерами по сиду. Текущий тест оставить вторичным.

### 3.5. «Ложный уровень серии ≤ 0,033» неверен
- **Что найдено.**
  - Порог задан как P ≤ 0,01 при фактическом n. Ложный уровень на тест доходит до 0,0099–0,0100 (n = 54, 82, 107, 116 — расчёт `threshold`/`binom_tail` по n = 10…120). Для четырёх «подтверждено» граница Бонферрони — 0,04, а 0,033 верно только при n ≈ 40.
  - «Обратный эффект» — тоже вердикт с весом. Значит, тест двусторонний, и ложный уровень любого вердикта по серии — до 0,08.
- **Уверенность:** 0,9.
- **Что изменить.** Записать «≤ 0,04 для подтверждений, ≤ 0,08 для любого направленного вердикта» или сузить α на тест до 0,005 с каждой стороны.

### 3.6. Правило веса опоры расходится с правилом проекта и даёт почти нулевой вес обратному эффекту при малом n
- **Что найдено.**
  - В `tools/support_bits.py`:10 log₂((1 − мощность)/(1 − ложный уровень)) — вес «опровержения», то есть неподтверждения порогового теста. В PREREG §4 эта формула отдана «обратному эффекту», а «не решено» получает 0 бит.
  - При n = 10 мощность при доле 0,7 равна 0,028, и вес «обратного эффекта» ≈ −0,04 бита. Явный обратный эффект почти ничего бы не стоил.
- **Уверенность:** 0,65.
- **Что изменить.** «Не решено» → log₂((1 − мощность)/(1 − ложный уровень)) по правилу проекта. «Обратный эффект» → отдельное отношение правдоподобий P(обратный | H1)/P(обратный | H0) или фиксированный отрицательный вес, записанный заранее.

### 3.7. Мощность при ожидаемых ничьих не посчитана; чтение «не решено» в §7 приписывает непроверенную причину
- **Что найдено.**
  - Пилот: 3 ничьи из 6. При n = 30 мощность при доле 0,7 — 0,43, при n = 20 — 0,24, при n = 10 — 0,03 (порог 10 из 10). В §4 даны 0,76 и 0,98 — для n без ничьих.
