## 1. Решение

**Задача и шкала сложности**
- Задача — произведение M = 10·N матриц 2×2 по модулю p ≈ 10⁹. Правду вычисляет только код.
- Дерево вложенное. N = 20 собирается из двух деревьев N = 10, каждое N = 10 — из двух деревьев N = 5. На одно зерно приходится 20 листьев, 19 сборок, всего 39 узлов.
- Рядом с каждой ячейкой публикуется трудность M·ε.
- Точка N исключается из уровня, если одиночка с одним вызовом проходит на ней больше 0,1.

**Гигиена**
- Инструменты головам запрещены. Все вызовы пишутся в журнал JSONL с хешем запроса.
- Ответ — строгий JSON. Если он не разбирается, это провал: парсер ответ не исправляет.
- Зёрна для оценки лежат вне рабочего каталога. Хеши списков зёрен записываются в PREREG до калибровки.
- Зёрна калибровки, выбора M и оценки не пересекаются.

**Первичный генотип (фиксируется в PREREG)**
- Дерево, r = 2. Копии не видят друг друга, код сравнивает их по точному равенству. При расхождении ставится третий вызов, решает большинство 2 из 3.
- Ячейка «без защиты» — копия A из того же пула.
- Проверка соседом v (полная или по det) входит в основные ячейки только при двух условиях: d ≥ 0,9 на естественных ошибках листа и ложные тревоги ≤ 0,1. Даже тогда — только в режиме «проверяющий не видит ответ».

**Калибровка до PREREG, ≈ 130 вызовов (п), на отдельных зёрнах**
- ε листа и ε сборки.
- d на естественных ошибках и на подложенных ошибках четырёх типов: элемент, порядок, транспонирование, весь продукт.
- ρ — доля совпадающих неверных ответов у копий.
- det-проверка: доля пойманных ошибок и ложные тревоги.
- Якорь: проверяющий видит или не видит ответ проверяемого.
- Одиночка на M = 50/100/200 — для выбора M.

**Макромодель**
- P_орг = Π по узлам [1 − ε_узла·(1−d)^v·q_r], где q_r включает ρ.
- Параметры берутся только из калибровки. Формула и её интервал замораживаются до прогона.
- Критерий: наблюдение попадает в 90 % интервал предсказания для каждого N.

**Пул**
- 10 свежих зёрен по ≈ 90 вызовов (п).
- Единица анализа — зерно. Анализ парный, бутстреп по зёрнам.

**Контроли**
- Одиночка с одним вызовом на всей задаче: каждое N на каждом зерне.
  - Промпт обязывает довести счёт до конца. Долю отказов публикуем отдельно.
  - Если отказов больше 0,3, условие «одиночка ≤ 0,1» не засчитывается.
- Одиночка с равным бюджетом: одна беседа, контекст растёт.
  - Разрешены самоперепроверка, другой порядок умножения и голосование с собой. Запрещены инструменты и новые контексты.
  - Ставится при N = 10, 8 зёрен, K ≈ 42 вызова (п).
  - В каждом ответе головы промежуточные произведения в JSON. По ним код считает наклон ε по позиции в контексте, без новых вызовов.
- Цепочка из свежих голов: 3 зерна, только разведка.

**Сертификат уровня — должны выполняться все условия**
- Нижняя граница 95 % ДИ парной разности «организация − одиночка с одним вызовом» > 0,3 при N = 20.
- Нижняя граница разности «организация − одна беседа с равным бюджетом» > 0 при N = 10.
- Вето: если одна беседа с равным бюджетом даёт ≥ 0,8, уровня нет.
- Одиночка с одним вызовом ≤ 0,1 при доле отказов ≤ 0,3.
- Макромодель попадает в интервалы.
- Против равного бюджета N = 20 не сертифицируется, в тексте это пишется прямо.
- Если любой порог нарушен, уровень не присуждается, и это публикуется.

**Отбор**
- Разведка всех генотипов на пуле или калибровочных зёрнах, с поправкой Холма.
- В PREREG называются первичный и один запасной генотип.
- Подтверждается ровно один заранее названный генотип, вживую, на отложенных зёрнах с хешем в PREREG.
- Эволюция по Правому идёт отдельной фазой после сертификата (правило автора: ставятся все предложения).

## 3. Оставшиеся несогласия

1. **Порог против равного бюджета.** Скептик требует нижнюю границу > 0,2 и абсолютное условие «организация ≥ 0,8». Левое, Правое и Инженер ставят > 0: по их оценке (п) порог 0,2 недостижим по мощности. По правилу автора позиция Скептика входит как отдельно публикуемый строгий критерий.
2. **Число зёрен пула.** Инженер — 10, Левое — 11, Скептик — 12. Расчёты границ расходятся. Для 12 зёрен при 10/12 против 0/12 Левое по Танго получает 0,39, Инженер по Ньюкомбу — 0,46.
3. **Зёрна для равного бюджета.** Левое, Скептик и Инженер — 8 зёрен (≈ 336–360 вызовов). Правое — 6 зёрен (≈ 240).
4. **Подтверждение отбора.** Правое и Скептик — вживую на отложенных зёрнах; у Правого это зёрна 4–6 внутри бюджета. Левое и Инженер — вне бюджета.
5. **Формула q_r.** Правое: q_r = ρ + (1−ρ)·ε. Левое: q_r = ρ как условная вероятность совпадения неверного ответа.
6. **Контроль якоря.** Инженер и Скептик — 20 × 2 ≈ 40 вызовов в калибровке. Правое — 30 × 2 ≈ 60. Левое — 2 зерна при N = 5, дубль видит ответ, ≈ 60.
7. **Цепочка.** Скептик готов её снять при нехватке бюджета. Остальные оставляют 3 зерна разведки.

## Голоса

- **Правое (интуит): за.** В решение вошло главное из моих предложений. Рядом с каждой ячейкой публикуется M·ε. Проверка по det стала кандидатом в генотипы с жёсткими порогами. Измеряются ρ и полиморфизм дубля. Гипотеза компартментализации проверяется бесплатно, по наклону ε вдоль контекста из промежуточных JSON. Сертификат требует выполнить оба условия, эволюция вынесена в отдельную фазу. Вложенное дерево 5→10→20 с общими зёрнами работает как сравнительный метод: одна «линия» прослеживается на трёх масштабах, и это сильнее трёх независимых выборок.

Два своих несогласия снимаю.
1. Формула q_r. Прав Левый: q_r = ρ как условная вероятность совпадения неверных ответов. Код сравнивает копии по точному равенству по модулю около 10⁹, поэтому независимые ошибки почти никогда не совпадают. Моё слагаемое (1−ρ)·ε завышало бы риск.
2. Равный бюджет. Принимаю 8 зёрен ради мощности.

Строгий порог Скептика «> 0,2» правильно публиковать отдельным критерием. Отказ сертифицировать N = 20 против равного бюджета — честная формулировка, её поддерживаю.
