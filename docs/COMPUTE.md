## 1. Colab: новое в 2026 году
Google выпустил официальную консольную программу Colab (июнь 2026, `github.com/googlecolab/google-colab-cli`, лицензия Apache 2.0; README прочитан нами).
- `colab run --gpu T4 script.py` выделяет машину, запускает скрипт, забирает файлы и освобождает машину. Программа сделана и для агентов в терминале.
- Вход — аккаунтом Google: ссылка, затем одноразовый код, который вставляют в программу. Токен хранится в системном хранилище ключей. В облачной сессии такого хранилища нет, а контейнер временный, поэтому код пришлось бы вводить каждый новый сеанс. Значит, здесь Colab остаётся «в один клик».
- Если автор будет вести Neu через Claude Code на своём компьютере, Colab там может запускаться сам.

## 2. Почему не всё сразу

- Modal и аренда — когда Kaggle и Colab станет мало.

## 3. GitHub Actions — подключено (слово автора 14.11.2026: «да, GitHub Action»)
- **Что даёт.** Для открытых репозиториев стандартные раннеры GitHub бесплатны и без ограничения минут (документация GitHub, по выдаче). Задание — до 6 ч, машина `ubuntu-latest` — 4 ядра и 16 ГБ (по выдаче). Можно запускать несколько заданий параллельно.
- **Как устроено.** Я пушу файл задания, GitHub прогоняет его и коммитит результаты в ту же ветку.
- **Сначала не было подключено.** Это файл `.github/workflows/neu-run.yml` с правом записи в репозиторий. Система разрешений сессии не дала добавить его без явного согласия автора; после слова автора файл добавлен.
- **Как запускать.**
  1. Кладу или меняю `gha_jobs/<имя>.sh` и пушу.
  2. GitHub выполняет задание. Первым аргументом оно получает папку `gha_out/<имя>/` и пишет туда результаты.
  3. Workflow коммитит результаты обратно в ту же ветку от имени Claude, а я подтягиваю их через `git pull`.
- **Проверка, 14.11.2026.** Задание `gha_jobs/probe.sh` выполнено, результат — `gha_out/probe/probe.json`.

## Дополнение 15.11.2026 (по OCSHIFT-01; проверено нами)
- **Квота Kaggle считается по времени сессии, а не по числу видеокарт.** Пилот на двух T4 шёл 595 с и занял 605 с квоты; тест — 3580 с.
- **Две T4 в одном прогоне:** два процесса через fork, по карте на процесс; число карт берётся через `nvidia-smi` до обращения к CUDA. Ответы и logp совпали с выводом одной карты точно (блок сверки с OCREP-01).
- **Скорость анализа на GitHub Actions** (4 ядра, вложенный бутстреп с переподгонкой восьми оценщиков): 22000 задач × 10000 повторов — 5891 с. По прогонам на 1000–2000 повторов я ждал вдвое меньше; прогноз времени брать с прогона того же размера.
- **Задание, результаты которого входят в хеши регистрации,** запускать копией зарегистрированного шаблона, которая кладётся одним коммитом с сырым выводом: пуш запускает задание один раз, а сверка хешей проверяет и копию.
- **Запуск по расписанию в сессию, ограниченную доверенными устройствами, не проходит** (отказ в доступе). Такое ограничение ставится необратимо, когда автор разрешает сессии писать в его другие сессии. События PR по подписке приходят.

### API Anthropic (*полный текст*: platform.claude.com, цены — в долларах)
| Модель | вход / выход за 1 млн токенов | пакетный API (−50 %) |
|---|---|---|
| Claude Haiku 5.5 (подсказка до 100 000 токенов) | $0,10 / $0,50 | $0,05 / $0,25 |
| Claude Sonnet 5.5 | $2 / $10 | $1 / $5 |
| Claude Opus 5.5 | $4 / $20 | $2 / $10 |
- Это не процессор и не видеокарта. Это головы Claude и контейнер для кода.
- Главная польза для Neu — опыты на головах Claude (цель программы: «система взаимодействия предобученных голов Клауда»): правда от кода, разные модели как разные головы, пакетный API.
- **Ключ в этой облачной сессии не сохранять.** Базовый адрес самой сессии — `https://api.anthropic.com`: сетевой секрет для этого адреса прокси подставляет во все запросы к нему из среды, и неизвестно, не попадут ли туда запросы самой сессии. Путь — секрет репозитория GitHub `ANTHROPIC_API_KEY` (кладёт автор в настройках репозитория), запуск — с GitHub Actions; для этого нужна строка в `neu-run.yml`, только по слову автора. В консоли Anthropic автору лучше поставить предел трат на рабочее пространство ключа.
