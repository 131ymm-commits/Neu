# Протокол: исследование вместе с ИИ в одном репозитории

Общий алгоритм для любого исследования, которое человек ведёт вместе с ИИ. Он вырос из живого опыта программы Neu (сентябрь 2026). Тогда работа была разбросана по 42 репозиториям, архивам и чатам. Часть результатов была удалена, часть чисел в итоговом документе была вписана по памяти, а сами разговоры, в которых принимались решения, не сохранились нигде. Протокол нужен, чтобы этого не повторилось.

Главный принцип: **репозиторий — это память исследования, и разговор человека с ИИ — её часть.** Результат без разговора, в котором его придумали, проверили и поправили, теряет половину смысла.

## 1. Старт: один дом для всего

1. **Один репозиторий на программу.** Не новый репозиторий на каждую версию, идею или сессию. Версии — это коммиты и теги (`v1.0`), ветки — это альтернативные гипотезы.
2. **Каркас сразу:**
   ```
   README.md        — что это, карта папок, карта старых источников, чего не хватает
   CLAUDE.md        — правила для ИИ в этом репозитории (читаются в начале каждой сессии)
   PROTOCOL.md      — этот алгоритм
   docs/            — тексты, теория, итоговые документы
   experiments/     — <дата>_<ID>/ : PREREG, код, результаты, REPORT
   archive/         — импортированные старые материалы, без правок
   recovered/       — найденное в истории git, удалённое или потерянное
   audit/           — проверки утверждений против файлов
   journal/         — чаты, ошибки ИИ, решения, предположения
   ```
3. **Правила для ИИ — в CLAUDE.md**, чтобы каждая новая сессия начинала с них, а не с нуля.

## 2. Сбор: всё, что уже есть

1. **Инвентаризация источников.** Все репозитории аккаунта, все их ветки и **вся история git**, включая удалённые файлы; архивы; облачные диски; проекты и чаты в других интерфейсах ИИ. Смотреть только последнюю версию основной ветки недостаточно: в Neu удалённые эксперименты Q46–Q48 нашлись только в истории.
2. **Импорт с провенансом.** Для каждой импортированной вещи записать, откуда она, дату и хеш коммита источника. Импортированное лежит в `archive/` и не правится.
3. **Восстановление.** Удалённое из истории git — в `recovered/` с указанием коммита, где файл был удалён.
4. **Список «чего нет».** В README: что упоминается в текстах, но не найдено ни в одном источнике. Это такая же важная часть инвентаризации, как найденное.

## 3. Цикл эксперимента

1. **Гипотеза до поиска.** Сформулировать одной фразой, письменно.
2. **Занятость.** Проверить, кто это уже делал; записать.
3. **Предрегистрация до кода.** `PREREG-<ID>.md`: вопрос, постановка, предсказания с порогами, критерий провала, третий исход «разницы нет», ложный уровень (посчитанный, а не предположенный), ресурсы. **Коммит и push до первой строки кода.** Хеш этого коммита — доказательство.
4. **Код и прогон.** Код в той же папке. Результаты — json и логи, числа из них, а не из памяти.
5. **Отчёт.** `REPORT-<ID>.md` со ссылкой на хеш предрегистрации. Вердикты строго по букве предрегистрации. Отрицательный результат хранится так же, как положительный.
6. **Пост-хок — отдельно.** Всё, что найдено после факта, записывается с пометкой «пост-хок» и вердикт не меняет. Оно порождает следующую предрегистрацию.
7. **Ошибки ИИ в прогнозе** (не тот механизм, неверная оценка разброса) — в `journal/ERRORS.md`.

## 4. Разговор как данные

1. **Каждая сессия выгружается в `journal/CHAT_<даты>.md`**: реплики человека дословно, ответы ИИ полностью, действия ИИ одной строкой. События среды помечаются как «не человек».
2. **`journal/ERRORS.md`** — всё, в чём ИИ ошибся или что предположил без проверки. Записи не удаляются, исправление дописывается к записи.
3. **Решения** — кто решил, что и почему. Особенно решения человека против совета ИИ и наоборот.
4. **Числа «по памяти» помечаются.** Утверждение без пути к файлу и строки — это предположение, а не результат.

## 5. Проверка

1. **Любое число — с путём и строкой** в файле результатов.
2. **Периодический аудит** итоговых документов против файлов: что подтверждено, что расходится, что непроверяемо.
3. **Независимая перепроверка** важных выводов: другой агент, другая линза, или человек.

## 6. Git-гигиена

1. Коммиты ИИ помечены (Co-Authored-By, отдельный автор).
2. **Запушенную историю не переписывать**: хеши предрегистраций — доказательства.
3. Большие файлы (чекпойнты, сырые траектории) — вне git; в репозитории — логи, json и указание, где лежит сырьё.
4. Push после каждого законченного шага, а не в конце дня.

## 7. Роли

- **Человек** задаёт вопросы, решает, подписывает, отвечает. Он может не уметь пользоваться git — это задача ИИ.
- **ИИ** ведёт репозиторий, пишет предрегистрации, код и отчёты, проверяет, записывает свои ошибки и прямо говорит, чего не может сделать и почему.
- Решения, меняющие опубликованное (удаление, перезапись истории, публикация наружу), — только с явного согласия человека.

## 8. Конец сессии: чек-лист

- [ ] всё закоммичено и запушено;
- [ ] чат выгружен в `journal/`;
- [ ] новые ошибки и предположения — в `ERRORS.md`;
- [ ] README обновлён: новые папки, что появилось, чего по-прежнему нет;
- [ ] следующий шаг записан (возврат из последнего отчёта).
